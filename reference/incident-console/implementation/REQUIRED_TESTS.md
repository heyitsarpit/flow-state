# Required tests

Status: pre-coding audit companion; each row must acquire one owning phase and one executable proof-case ID before implementation

Every test below is deliberately one physical line in the form `condition -> required behavior -> anti-drift oracle`; tests must use public declarations, public observations, independent counters, Effect TestClock, hostile controlled boundaries, packed consumers, artifacts, or process I/O rather than source-text matching or private state mutation.

## Phase 0 — proof and cutover controls

- RT-0001 | Given every public package route -> inventory every runtime value and exported type with keep/change/delete disposition -> compare source entry points and freshly packed declarations so stale `dist` cannot satisfy the check.
- RT-0002 | Given every normative local and central proof ID -> assign every atomic proof case to exactly one closure phase -> validate the generated index rejects missing, duplicate-owner, and unknown IDs.
- RT-0003 | Given every issue row, including dotted I5 and I10 sub-IDs, plus every CUT removal -> map it to a contract, proof case, phase, live owner, and deletion owner -> fail Phase 0 when any row is unowned or multiply owned.
- RT-0004 | Given an architecture test that reads filenames or source tokens -> classify it as migration evidence rather than behavioral proof -> require a named replacement test before its owning phase can close.
- RT-0005 | Given the dirty starting worktree -> preserve every pre-existing path and record overlap in the receipt -> compare before/after name-status so unrelated user changes cannot be absorbed into a phase.
- RT-0006 | Given a focused green subset and a failing or skipped required broad case -> keep the phase pending -> make receipt validation require exact exits, test counts, skip counts, deletions, and remaining IDs.
- RT-0007 | Given a broad PROOF row with several implementation seams -> split it into stable atomic subcase IDs with exactly one closing phase while later dependency reruns cannot claim closure again -> validate the proof index as structured data rather than receipt prose.
- RT-0008 | Given I5, I10, and I16 -> assign canonical-ref validation to Phase 1 and split resource-versus-React and runtime-versus-model concerns into separate issue IDs -> reject any issue row whose named implementation owner cannot perform its required change.
