# Collections

A trait placed with `.each` gives one copy per entry of a host memory list, and each copy runs its own state, timers and operations.

## Example: autosave for each open document

Each open document gets its own `Autosave` copy, keyed by `docId`, so saves for different documents never share state.

```ts
// workspace.definition.ts
import { definition, Flow } from "flow-state"
import { Schema } from "effect"
import { Autosave } from "./autosave.trait"

const OpenDoc = Schema.Struct({ docId: Schema.String, title: Schema.String, body: Schema.String, etag: Schema.String }) // user-defined: what GET /docs/:id returned

export const Workspace = definition({
  id: "Docs/Workspace",
  states: ["READY"],
  events: {
    Open: { docId: Schema.String, title: Schema.String, body: Schema.String, etag: Schema.String },
    Close: { docId: Schema.String },
    KeepMine: { docId: Schema.String },
  },
  memory: { open: Flow.initial(Schema.Array(OpenDoc), []) },   // the host's list: membership is host data
  traits: { docs: Autosave.each({ of: "open", by: "docId", max: 20 }) },   // one copy per open document
})
```

```ts
// workspace.machine.ts
import { deny, machine } from "flow-state"
import { Autosave } from "./autosave.trait"
import { Workspace } from "./workspace.definition"

type Memory = typeof Workspace.Memory.Type
const copy = (m: Memory, docId: string) => m.docs.find((d) => d.key === docId) // a copy's public memory: key, item, ...

export const WorkspaceMachine = machine(Workspace, ({ S, E }) => ({
  default: S.READY,
  // one filling for every copy; it receives the entry as item
  traits: { docs: { input: ({ item }) => ({ docId: item.docId, body: item.body, etag: item.etag }) } },
  on: {
    Open: {
      target: "self",
      guard: ({ memory, event }) => !memory.open.some((d) => d.docId === event.docId) || deny("AlreadyOpen"),
      updateMemory: ({ memory, event }) => ({ open: [...memory.open, event] }), // adding a copy
    },
    Close: {
      target: "self",
      guard: ({ memory, event }) => copy(memory, event.docId)?.status !== "dirty" || deny("Unsaved"),
      updateMemory: ({ memory, event }) => ({ open: memory.open.filter((d) => d.docId !== event.docId) }), // removing a copy
    },
    KeepMine: {
      target: "self",
      guard: ({ memory, event }) => copy(memory, event.docId)?.status === "conflict" || deny("NoConflict"),
      raise: [E.docs.Overwrite.from(({ event }) => ({ key: event.docId }))], // a raise into one copy
    },
  },
  states: { READY: {} },
}))
```

## Example: a list of form fields

Each row is a `Field` copy keyed by its own entry in `inviteIds`. The host adds and removes entries in its own transitions.

```ts
// signup.definition.ts
import { definition, deny, Flow } from "flow-state"
import { Schema } from "effect"
import { Field } from "./fragments"                  // user-defined trait (machine-design 3.1)

const optionalEmail = (v: string) => v === "" || v.includes("@") || deny("NotAnEmail") // user-defined

export const Invites = definition({
  id: "Signup/Invites",
  states: ["INVITE"],
  events: { AddInvite: {}, RemoveInvite: { key: Schema.String } },
  memory: {
    inviteIds: Flow.initial(Schema.Array(Schema.String), ["invite-1"]), // membership is host data
    nextInvite: Flow.private(Flow.initial(Schema.Int, 2)),              // deterministic keys
  },
  traits: {
    invites: Field(Schema.String, { validate: optionalEmail }).each({ of: "inviteIds", max: 5 }),
  },
})
```

```ts
// signup.machine.ts
import { deny, machine } from "flow-state"
import { Invites } from "./signup.definition"

export const InvitesMachine = machine(Invites, ({ S }) => ({
  default: S.INVITE,
  traits: { invites: { input: () => ({ value: "" }) } },
  on: {
    AddInvite: {
      target: "self",
      guard: ({ memory }) => memory.inviteIds.length < 5 || deny("FiveAtMost"),
      updateMemory: ({ memory }) => ({
        inviteIds: [...memory.inviteIds, `invite-${memory.nextInvite}`],
        nextInvite: memory.nextInvite + 1,
      }),
    },
    RemoveInvite: {
      target: "self",
      // a key gone from the list ends its copy
      updateMemory: ({ memory, event }) => ({ inviteIds: memory.inviteIds.filter((k) => k !== event.key) }),
    },
  },
  states: { INVITE: {} },
}))
```

## Example: one live quote per symbol

Each symbol on the watchlist gets one live subscription, placed and released as the key enters and leaves the list.

```ts
// watch.definition.ts
import { definition, Flow } from "flow-state"
import { Schema } from "effect"
import { Market } from "./market.contracts" // user-defined: a stream contract whose key is ["symbol"]

export const Watch = definition({
  id: "Market/Watch",
  states: ["WATCHING"],
  events: { QuoteLost: { symbol: Schema.String } },
  memory: { watchlist: Flow.initial(Schema.Array(Schema.String), ["ACME"]) },
  operations: ({ E }) => ({
    quotes: Market.quote.outcomes({
      failure: E.QuoteLost.from((_e, { key }) => ({ symbol: key.symbol })),
    }),
  }),
})
```

```ts
// watch.machine.ts
import { machine } from "flow-state"
import { Watch } from "./watch.definition"

export const WatchMachine = machine(Watch, ({ S, O }) => ({
  default: S.WATCHING,
  // one session per symbol in the after list
  activities: [O.quotes.subscribe.each(({ memory }) => memory.watchlist.map((symbol) => ({ symbol })))],
  states: { WATCHING: {} },
}))

// view: undefined for a symbol that is not placed
// useView(watch, (s) => List.O.quotes.get(s, { symbol })?.data)
```

## Keywords

### `.each({ of, max, by? })`

**What:** Places one copy of a trait for each entry of the memory field `of` names, in that field's order.

**Why it exists:** Each entry gets its own state, timers and operations, while the host's list stays the only source of membership.

- `max` is required. A duplicate key keeps its first entry, and keys past `max` are dropped, each repair recorded as evidence.
- A copy for a removed key ends with its `whenAbandoned` fused into that turn. A new key is seeded from the memory after the turn.

<small>Source: machine-design rule 9; 2.9.6; 3.3</small>

### `by`

**What:** Names the key field when the entries of `of` are records; `by: "docId"` keys each copy by `docId`.

**Why it exists:** A list of records needs one field that identifies each entry, so copies survive reordering.

- Without `by`, the entries are bare strings and are their own keys.

<small>Source: machine-design rule 9</small>

### `input`

**What:** The filling of a trait placed with `.each` is one function for all copies; it receives the copy's `item` and returns that copy's inputs.

**Why it exists:** A copy starts from the host's entry, and the filling is written once rather than per copy.

```ts
traits: { docs: { input: ({ item }) => ({ docId: item.docId, body: item.body, etag: item.etag }) } },
```

<small>Source: machine-design rule 9; 2.9.6</small>

### `item`

**What:** The entry of the list that a copy was placed for, available to the filling and to the copy's public memory.

**Why it exists:** A copy needs the data of its own entry without reading the whole list again.

- `key` and `item` are reserved memory names in a trait placed with `.each`.

<small>Source: machine-design rule 9</small>

### `key`

**What:** The key of a copy: the entry's value, or its `by` field when `by` names one. It appears on each copy in `s.memory.<name>`.

**Why it exists:** Every copy must be addressable by one stable value, so events and raises can reach it.

- Whether `key` is exposed on a copy's memory depends on the field's `Flow.private` setting; see machine-design rule 9. Views and host raises address the copy through `key` either way.

<small>Source: machine-design rule 9</small>

### `E.<name>.key(k)`

**What:** Addresses one copy of a trait placed with `.each`, used by a view to send an event to that copy and by a machine to raise into it.

**Why it exists:** Events must reach the right copy by its key, not by its position in the list.

```ts
// view: send an event to one copy
send(Workspace.E.docs.key(docId).Edited({ body }))

// machine: a raise into one copy
raise: [E.docs.Overwrite.from(({ event }) => ({ key: event.docId }))],
```

- A raise into an absent key is dropped with evidence in a turn started by a delivery; otherwise it refuses.

<small>Source: machine-design rule 9; 2.9.6</small>

### `Field`

**What:** A trait that holds one form field's value and validation result; placed with `.each`, it gives one row per entry.

**Why it exists:** A form with a variable number of rows needs one state per row without a separate definition.

- The validator returns `true` or `deny(code)`, and the field stores the denial or `null` as its error.

<small>Source: machine-design 3.3</small>

### `updateMemory`

**What:** The transition's memory patch; here it adds or removes entries of the list field, which is how a copy is added or removed.

**Why it exists:** Membership is host memory changed by the host's own transitions, so a copy is added or removed behind the host's guards.

- There are no `Add` or `Remove` events for copies. A removed key ends its copy, and a key added and removed in one patch changes nothing.

<small>Source: machine-design rule 9; 3.3</small>

### `subscribe.each(select)`

**What:** An operation placed with `subscribe.each` opens one live session per distinct key of the inputs that `select` returns.

**Why it exists:** A list of live reads, such as a quote per symbol, should start and stop one stream per key with no hand-written bookkeeping.

- A key's subscription starts when the key first appears in the after list and is released when it leaves. Two placements of one key are `DuplicateSession`.
- A view reads one session with `O.x.get(s, key)`, which is `undefined` while the key is not placed.

<small>Source: machine-design rule 41; 2.7.10</small>
