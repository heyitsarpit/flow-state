## Example: chat messages (facts, with catch-up)

A chat room's messages: a fact stream that resumes from the machine's cursor and repairs gaps from history.

```ts
// chat.contracts.ts
import { Feed, stream } from "@flow-state/core"                    // NEW: Feed (module); existing: stream
import { Effect, Option, Schedule, Schema, Stream } from "effect"  // Effect: the library's functions

export const Chat = {
  messages: stream({                                               // existing: stream
    id: "Chat.messages",                                           // existing: id
    input: { roomId: Schema.String, after: Schema.optional(Cursor) },   // existing: input; user-defined: Cursor; after is the resume position, outside key (K2)
    output: Message,                                               // existing: output (was result, OD12); user-defined: Message
    key: ["roomId"],                                               // existing: key: one session per room
    delivers: "facts",                                             // accepted: delivers (M6-D4)
    subscribe: ({ roomId, after }) =>                              // existing: subscribe
      Stream.unwrap(Effect.map(ChatSocket, (chat) =>               // user-defined: ChatSocket (the adapter, example 2)
        Feed.reconnect((from) => chat.room(roomId, from), {        // NEW: Feed.reconnect; user-defined: chat.room
          from: after,                                             // NEW: from
          position: (m) => m.cursor,                               // NEW: position
          while: (e) => e._tag === "ChatDropped",                  // Effect: while (which errors are transient)
          schedule: Schedule.exponential("500 millis").pipe(Schedule.jittered, Schedule.upTo({ times: 8 })),   // Effect: schedule
          catchUp: (cursor) => fetchPage(roomId, cursor).pipe(     // NEW: catchUp; user-defined: fetchPage
            Effect.flatMap((p) => p.truncated                      // the server's word: its history no longer reaches the cursor
              ? Effect.fail(new Feed.CannotRepair({ reason: "history starts later", continueAt: p.beforeOldest }))   // NEW: Feed.CannotRepair (decided S7)
              : Effect.succeed([p.messages, p.complete ? Option.none() : Option.some(p.next)] as const))),   // the server's own completeness field ends paging
        }))),
  }),
}

// chat.definition.ts
operations: ({ E }) => ({
  messages: Chat.messages.outcomes({
    value: E.Message.from((message) => ({ message })),             // existing: value (outcome)
    missed: E.MayHaveMissed.from((m) => ({ why: m.why, restartAt: m.restartAt })),   // NEW: missed; user-defined: MayHaveMissed
    failure: {                                                     // existing: failure
      SignedOut: E.SignedOut,                                      // user-defined: terminal error from the adapter
      ChatDropped: E.FeedEnded, Closed: E.FeedEnded,               // user-defined: transient error, once the budget is gone; NEW: Closed (decided S5)
      Overflow: E.FeedEnded, Defect: E.FeedEnded, Interrupted: E.FeedEnded,   // NEW: Overflow; existing: Flow reasons Defect, Interrupted
    },
  }),
}),

// chat.machine.ts
LIVE: {
  activities: [O.messages.subscribe(({ memory }) => ({ roomId: memory.roomId, after: memory.cursor }))],   // existing: activities, subscribe; read once at start
  on: {
    Message: { target: "self", updateMemory: ({ memory, event }) => ({ messages: upsert(memory.messages, event.message), cursor: event.message.cursor }) },   // user-defined: upsert; cursor is the resume position (decided S4)
    MayHaveMissed: { target: "self", updateMemory: ({ memory, event }) => ({ notice: "Some messages could not be recovered.", cursor: event.restartAt ?? memory.cursor }) },   // user-defined: MayHaveMissed, notice; explicit acceptance
    FeedEnded: { target: S.RETRY_WAIT },                           // user-defined: RETRY_WAIT (machine-level re-open)
  },
},
```

## Example: the chat socket adapter (where the signals come from)

The adapter turns socket frames into values and signals; the machine never sees a frame.

```ts
// chat.socket.ts (simplified: the registration deadline and error mapping are in streams proposal-v2 4.1)
const room = (roomId: string, from: Cursor | undefined) =>         // user-defined: ChatSocket.room
  Stream.unwrap(Effect.gen(function* () {
    const socket = yield* Socket.makeWebSocket(roomUrl(roomId, from))   // Effect: effect/socket; user-defined: roomUrl
    const pull = yield* Socket.readerString(socket)                // Effect: one pull per batch of frames
    return Stream.fromEffectRepeat(pull).pipe(
      Stream.flatMap((frames) => Stream.fromIterable(frames)),
      Stream.mapEffect(decodeFrame),                               // user-defined: pure decoding, not shown
      Stream.flatMap((f) => Stream.fromIterable<Message | Feed.Signal<never, Cursor>>(   // Feed.Signal<D, P>: drop reason and position types
        f.t === "hello"
          ? [f.replayedFrom && same(f.replayedFrom, from)          // user-defined: same (Cursor equality)
              ? Feed.live({ proof: "server replayed from our cursor" })   // NEW: Feed.live({ proof }): the server's echo of this from
              : Feed.live()]                                       // NEW: Feed.live(): registered, nothing proven
          : f.t === "reset"
          ? [Feed.live({ lost: "server log reset", restartAt: { epoch: f.epoch, seq: 0 } })]   // NEW: lost, restartAt
          : f.t === "msg" ? [f.message] : [])))                    // pings decode to nothing
  }))
```

## Example: a watchlist of quotes (state, one session per key)

The newest price wins, and only a price the current connection confirmed is current.

```ts
// market.contracts.ts
export const Market = {
  quote: stream({
    id: "Market.quote",                                            // existing: id
    input: { symbol: Schema.String },                              // existing: input
    output: Quote,                                                 // existing: output; user-defined: Quote
    key: ["symbol"],                                               // existing: key
    delivers: "state",                                             // accepted: delivers (M6-D4)
    subscribe: ({ symbol }) => Stream.unwrap(Effect.map(MarketFeed, (mf) =>   // existing: subscribe; user-defined: MarketFeed
      Feed.reconnect(() => mf.quotes(symbol), {                    // NEW: Feed.reconnect; user-defined: mf.quotes
        while: (e) => e._tag === "MarketDropped",                  // Effect: while
        schedule: Schedule.exponential("500 millis").pipe(Schedule.jittered, Schedule.upTo({ times: 12 })),   // Effect: schedule
      }))),
  }),
}

// watch.definition.ts
operations: ({ E }) => ({
  quotes: Market.quote.outcomes({
    value: E.Quoted.from((q, { key }) => ({ symbol: key.symbol, price: q.price })),   // existing: value; user-defined: Quoted
    failure: {                                                     // existing: failure; every tag is mapped (exhaustive)
      MarketDropped: ended, Closed: ended, Overflow: ended,        // user-defined: MarketDropped, ended (= E.QuoteEnded.from((_e, { key }) => key)); NEW: Closed, Overflow
      Defect: ended, Interrupted: ended,
    },
  }),
}),

// watch.machine.ts
WATCHING: {
  activities: [O.quotes.subscribe.each(({ memory }) => memory.watchlist.map((symbol) => ({ symbol })))],   // existing: subscribe.each; user-defined: watchlist
  on: {
    Quoted: { target: "self", updateMemory: ({ memory, event }) => ({ prices: { ...memory.prices, [event.symbol]: event.price } }) },   // user-defined: prices
  },
},

// Quote.tsx
const row = useView(watch, (s) => Watch.O.quotes.get(s, { symbol }))   // existing: get; undefined if not placed
const now = useNow("1 second")                                     // existing: useNow
const reconnecting = row?.connection === "Connecting" && row.drop !== undefined   // accepted: connection; NEW: drop
const price = row?.value                                           // state: confirmed by the current connection
return price ? <Price value={price.price} />                       // user-defined: Price
  : row?.last ? <Price value={row.last.value.price} dim age={now - row.last.at} />   // NEW: last { value, at }
  : <Price pending />
```

## Keywords

### `stream({ id, input, output, key, delivers, subscribe })`

**What:** Declares a streaming operation's contract: its id, input fields, output Schema, key, delivery kind and a `subscribe` that returns a Stream.

**Why it exists:** A stream's meaning is a property of its data, so `delivers` sits on the contract next to `output`, not on each consumer.

- `input` holds the key fields and, outside `key`, any resume position. A session reads `input` once at start, so a non-key change does not restart it; put a field in `key` to restart on it.
- Plans disagree: OPS O1, O4 and O6 still write `result` and `persist: false`. Streams proposal-v2 2.1 renames `result` to `output` (OD12) and drops `persist` on streams, so this page follows the proposal.

<small>Source: streams proposal-v2 2.1, 2.2 · decided S5 (Q10)</small>

### `delivers: "facts" | "state"`

**What:** Says whether each value is a fact (every one is delivered, in order) or state (the newest value wins and is current only while connected).

**Why it exists:** Whether a value may be skipped is a property of the data, so the contract declares it and the machine and view are checked against it.

<small>Source: streams proposal-v2 1 (R-Kind), 2.2 · M6-D4 (accepted)</small>

### `Feed.reconnect(connect, options)`

**What:** Wraps one connection, `connect(from)`, and reconnects it after a transient failure, reporting each drop and each new connection to Flow.

**Why it exists:** Backoff, budget reset, resume-from-last and catch-up ordering are the same in every app of a kind, so they are written once.

- It announces every connection, emits `Feed.down` on a transient failure, waits by `schedule` and connects again from its last position. `while` and `schedule` are Effect's existing words.
- A failure that `while` does not accept, or an exhausted `schedule`, fails the session with that error.

<small>Source: streams proposal-v2 2.3 · M6-D3 (extended), decided S5 (Q12)</small>

### `from`

**What:** The position the first connection resumes after, read from the stream's input (`after: memory.cursor` above).

**Why it exists:** Flow orders no positions, so the source's own resume point is named by the author.

- Required whenever `position` is given. A call without `from` gets an unproven first start on every session.
- With `from` declared and empty, the very first registration for a memory is `fresh`: nothing was owed.

<small>Source: streams proposal-v2 2.1, 2.3 · decided S4, S8, S10</small>

### `position`

**What:** A function that names a value's place in the source's order, such as `(m) => m.cursor`.

**Why it exists:** Positions let a repair and the live socket meet at their first common value, and Flow compares them with `Equal.equals`.

<small>Source: streams proposal-v2 2.3 · R-Position in 1 (decided S4)</small>

### `catchUp`

**What:** An optional page reader that repairs the gap between the last value and the live socket before any newer value reaches Flow.

**Why it exists:** Repair belongs with the adapter that knows the history, so `missed` arrives only for what nothing could repair.

- It is `Stream.paginate`'s step: the first call receives the position, later calls the page token. Only the server's own completeness field ends it, never a short page.
- Pages return values oldest first, starting after the cursor. The socket's values are buffered, at most `bufferSize`, until a page meets them.

<small>Source: streams proposal-v2 2.3 · decided S3, S6 (Q15, Q18)</small>

### `Feed.CannotRepair({ reason, continueAt? })`

**What:** A `catchUp` step fails with it to say the history no longer reaches back to the cursor.

**Why it exists:** A repair that cannot reach back must say so, rather than become an outage or a silent "complete".

- The start settles lost: `missed Lost` reaches the machine before the next value. No drop happens and no retry budget is spent.
- `continueAt` is the cursor the next page starts after, and paging resumes from it before the buffer follows.

<small>Source: streams proposal-v2 2.3, 1 (R-Repair) · decided S7</small>

### `value` (outcome)

**What:** The outcome key that handles each fact, once and in order; on a state feed, a reconciled value that differs from the last one heard.

**Why it exists:** Facts are never skipped and state is coalesced, so the same key carries a different guarantee for each kind.

<small>Source: streams proposal-v2 2.7 · R-Kind in 1</small>

### `missed`

**What:** The outcome key for a gap, receiving `Feed.Missed { why, restartAt?, initial }`, where `why` is `"Unproven"`, `"Lost"` or `"Reset"`.

**Why it exists:** Some gaps cannot be repaired, and the machine must accept or handle them before any later fact.

- `initial` is true when this memory and key were not registered before. A handler may ignore a `missed` only when `why` is `"Unproven"`, `initial` is true and its memory holds nothing; a `Lost` or `Reset` is never ignored.
- Required on a fact feed; a state feed has no `missed` (a type error).

<small>Source: streams proposal-v2 2.7, 2.3 · decided S9, S10</small>

### `failure`

**What:** The outcome key for a session that ended: the adapter's error tags, plus Flow's reasons `Closed`, `Overflow`, `Defect` and `Interrupted`.

**Why it exists:** An ended stream always has a reason, and the machine maps every one.

- `Closed` is a connection that completed (`Feed.Closed`); `Overflow` is a `Feed.callback` past its bound. Both are retryable: `Feed.reconnect` retries them.
- On a fact feed it is exhaustive, a type error otherwise. On a state feed it is required once anything is mapped.

<small>Source: streams proposal-v2 2.7, 2.3 · decided S5 (Q7, Q12)</small>

### `activities: [O.x.subscribe(select)]`

**What:** The machine's entry that places the stream's session while a state is active; `select` computes its input from memory.

**Why it exists:** The machine says when interest exists, and the session's input is read at start.

<small>Source: streams proposal-v2 2.1, 2.5 (lifecycle, R-Owner)</small>

### `Feed.live()`

**What:** Registers the connection: the server is listening now, and nothing is proven about the past.

**Why it exists:** Registration and continuity are separate facts, so a row can read Live while a gap is still unanswered.

<small>Source: streams proposal-v2 2.3, 1 (R-Live, R-Answer) · decided S2</small>

### `Feed.live({ proof })`

**What:** Registers the connection and proves that nothing was missed since the last value this session delivered, with `proof` as the recorded basis.

**Why it exists:** Continuity is claimed only with a written reason, which Inspection, Stories and `flow explain` can show.

- `proof` is a required string, such as `"server replayed from 8:41"`. It covers the span since the last delivered value, and every later value in source order until the connection ends.

<small>Source: streams proposal-v2 2.3 · decided S5</small>

### `Feed.live({ lost, restartAt })`

**What:** Registers the connection and says something was missed; `restartAt` moves the position into a new space when the server reset its log.

**Why it exists:** A server that resets its log has told Flow that the old positions no longer apply.

- Rare. `Feed.reconnect` resumes in the new space at once, and the handler stores `restartAt` for the next session. Old `{ epoch: 8, seq: 1 }` and new `{ epoch: 9, seq: 1 }` are both kept.

<small>Source: streams proposal-v2 2.3, 2.7 · SR11</small>

### `Feed.down(reason)`

**What:** Reports that the connection dropped, with a reason the author types.

**Why it exists:** The row must say "Reconnecting" and why, without the machine taking a transition.

- `Feed.reconnect` emits it for you on a transient failure. A drop changes the row, never the machine: a two-second drop is a `Feed.down` and a `Feed.live`, and Flow never re-opens a session.

<small>Source: streams proposal-v2 2.3, 2.4 · SR13, SR15</small>

### `subscribe.each`

**What:** The state operation form that gives one session per distinct key in a list held in memory.

**Why it exists:** A watchlist or a set of rooms is many keyed streams, without writing one session per item.

<small>Source: streams proposal-v2 2.5 (multiplicity), 4.3 · K4</small>

### `connection`

**What:** The row's registration state, `"Connecting"`, `"Live"` or `"Ended"`, present on every phase.

**Why it exists:** A view asks one question, whether the server is listening now, and `row?.connection === "Live"` type-checks even when the row is undefined.

<small>Source: streams proposal-v2 2.6 · accepted M6-D4; SR22</small>

### `drop`

**What:** The reason of the latest `Feed.down`, present while `"Connecting"` and `undefined` otherwise.

**Why it exists:** It tells "Connecting…" from "Reconnecting: offline" in the view.

<small>Source: streams proposal-v2 2.6</small>

### `value` (row)

**What:** On a state row, the value the current connection confirmed, or `undefined`. A fact row has no `value` field at all.

**Why it exists:** Only a confirmed value is current, so a view can show it without checking freshness itself.

- A value after `Feed.down` with no new live updates `last` only: dimmed, aged and never a machine event.

<small>Source: streams proposal-v2 2.6, 2.3 · decided S6 (Q17)</small>

### `last`

**What:** `{ value, at }`, the last value Flow knew, where `at` is the epoch-millisecond moment it was last known to be current.

**Why it exists:** A dimmed price needs an age, and the age must not depend on the server's clock.

- `at` is the arrival while live and the drop moment once the connection leaves `"Live"`. Across a reload or SSR Flow transfers the age and rebases it on the receiving clock.

<small>Source: streams proposal-v2 2.6 · decided S5 (Q6)</small>

### `resetAfter`

**What:** `resetAfter` is how long a connection must stay registered before `Feed.reconnect` restores its `schedule` to the first step; the default is `"1 minute"`.

**Why it exists:** A server that accepts and drops at once must not reset the backoff on every cycle.

<small>Source: streams proposal-v2 2.3 · decided S5 (Q12)</small>

### `Feed.callback(register, { bufferSize? })`

**What:** Bridges a callback SDK or raw browser API into a stream. `register(emit)` is a scoped Effect, and `emit` passes values or signals.

**Why it exists:** Callback APIs are common, and the bound and back-pressure are the same for each of them.

- `bufferSize` defaults to 1,024. Past it the stream fails with `Feed.Overflow`, which `Feed.reconnect` retries. Signals never count against the bound.
- `emit` returns a `Promise<void>` that resolves when the queue has room; `emit.fail(error)` and `emit.end()` finish the stream after what is queued.

```ts
Feed.callback((emit) => Effect.acquireRelease(                  // NEW: Feed.callback; Effect: acquireRelease
  Effect.sync(() => sdk.subscribe(symbol, (q) => emit(q))),    // user-defined: sdk.subscribe; emit(valueOrSignal)
  (off) => Effect.sync(off)),                                  // the finalizer runs at release, awaited
{ bufferSize: 1024 })                                          // default 1,024
```

<small>Source: streams proposal-v2 2.3 · decided S5 (Q13), S7 (Q20)</small>
