# Experimental Alpha Status

Flow State `0.1.0-alpha.0` is an installable prerelease for evaluation, not a
stable compatibility promise. Adopt it only when its Effect beta dependency and
narrow workflow model fit your application.

## Supported package contract

| Surface       | Alpha position                                                                                                        |
| ------------- | --------------------------------------------------------------------------------------------------------------------- |
| Runtime       | One caller-owned scoped runtime for resources, actors, transactions, streams, timers, children, tests, and inspection |
| Entrypoints   | `flow-state`, `flow-state/react`, `flow-state/testing`, `flow-state/server`, and `flow-state/inspect`                 |
| Module format | ESM on Node 22.18 or newer                                                                                            |
| Effect peer   | Exactly the declared Effect 4 beta version                                                                            |
| React peer    | Optional; React 18 and React 19 are covered when `flow-state/react` is imported                                       |
| CLI           | Installed `flow-state` bin with `behavior`, `story`, and `trace` command families                                     |
| Server        | Request-scoped boot payloads, resource hydration, actor restore, and isolation                                        |

The five recipe applications prove focused features. Incident Console proves the
combined client/server path over real HTTP and SSE, including optimistic 409
reconciliation, reconnect/replay, child workflows, teardown, and API restart.

## Public Surface Boundaries

The public contract is the five package entrypoints above and the installed CLI
families `behavior`, `story`, and `trace`. Local CLI proof surfaces are real, but
repository helpers under `packages/flow-state/scripts/**` and the maintained
recipe matrix in `examples/FEATURE_COVERAGE.md` remain repository-owned evidence,
not additional package APIs.

## Known alpha limits

- The machine model supports flat transitions, guards, updates, bounded `always`
  microsteps, state-owned resources, transactions, streams, one-shot timers, and
  children. Parallel states, history states, root `onDone`, raised events, and a
  complete hierarchical statechart model are outside the alpha.
- Resource cache capacity and eviction policy, richer TTL policy, generalized
  offline persistence, and router-aware loading are outside the alpha.
- Stream pressure is bounded for the proved queue/coalesce policies, but this is
  not a general durable event log or transport abstraction.
- Server support covers request-scoped prefetch, boot payloads, hydration, and
  restore. Generic React Server Component runtime ownership and a framework
  adapter layer are outside the alpha.
- Testing exposes ready-work flush, bounded settle, TestClock, fixtures,
  scenarios, receipts, issues, and pending work. It cannot make arbitrary
  external Promise or network work virtual.
- The CLI produces local behavior, story, graph, and trace evidence. It is not a
  hosted console or visual editor.
- App composition performs dependency and cycle validation plus duplicate
  module ids and duplicate resource ids across modules; not every cross-module
  descriptor collision is checked.
- The library does not provide a router, forms, authentication, component-local
  state, offline support for Incident Console, or adapters beyond React.

## Comparison boundary

TanStack Query has a broader dedicated server-state ecosystem, and XState has a
broader statechart model and tooling ecosystem. Flow State trades that breadth
for one Effect-typed runtime whose resource, workflow, test, and inspection owners
share scoped lifecycle and exact Effect requirements. Choose it for that unified
ownership model, not for API compatibility with either project.

For the executable path, start with [Getting Started](/getting-started). For the
real network boundary, run [Incident Console](/examples#incident-console).
