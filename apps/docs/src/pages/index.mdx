# Flow State

<div className="fs-lede">
  One scoped owner for the parts of an application that usually live in four libraries: cached
  resources, optimistic transactions, workflows, and the tests that prove them.
</div>

<div className="fs-abstract">
  Flow State is an experimental Effect-native runtime for teams building mid-to-large applications
  with cached resources, optimistic transactions, workflows, streams, deterministic tests, and
  inspection under one scoped owner. It is an opinionated alternative to assembling TanStack Query
  and XState for the same application boundary. It is not a drop-in replacement and does not claim
  feature parity with either library.
</div>

## A write, drawn as a machine

Every server write is a `flow.transaction`. It previews optimistically, then settles into a typed
outcome. The same shape that runs in the app is what the tests step through and the inspector draws.

## The alpha surface

| Need                    | Flow State owner                                                               |
| ----------------------- | ------------------------------------------------------------------------------ |
| Canonical shared data   | `flow.resource`, keyed refs, freshness, and invalidation                       |
| Server writes           | `flow.transaction` with optimistic preview, rollback, and typed outcomes       |
| Workflows               | `flow.machine`, state-owned resources, streams, timers, and children           |
| Reusable UI projections | `flow.view`                                                                    |
| React                   | Caller-owned `FlowProvider` plus `useActor`, `useResource`, and `useView`      |
| Deterministic proof     | `test(...)`, `test.app(...)`, virtual time, receipts, issues, and pending work |
| Inspection              | Behavior contracts, stories, graphs, traces, and the package CLI               |

The package exports `flow-state`, `flow-state/react`, `flow-state/testing`,
`flow-state/server`, and `flow-state/inspect`.

## What it looks like

A resource owns canonical server data; I/O stays behind an Effect service.

```ts
import { Effect } from "effect";
import * as flow from "flow-state";

const postsResource = flow.resource({
  id: "posts.list",
  key: () => flow.createKey("posts", "list"),
  lookup: () => Effect.flatMap(PostsService, (service) => service.list),
  freshness: { staleAfter: "30 seconds", onInvalidate: "active" },
});
```
