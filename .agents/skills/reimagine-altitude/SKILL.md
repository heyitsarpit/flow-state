# Reimagine Altitude

Use this skill to compare other ways of achieving the outcome behind a requested deliverable. A
deliverable serves a purpose for someone; sometimes a different deliverable would serve it better.
This skill steps back to the purpose and looks for those alternatives, without changing the goal on
the user's behalf.

## Steps

1. **Find the purpose.** Identify the requested deliverable, who will use it, and what it should let
   them do. Separate the user's stated priorities from your assumptions about what they value. Note
   whether the requested form itself is required (a dashboard because the contract says so) or only
   the first approach proposed; ask when that is unclear.

2. **Question the approach, while keeping the constraints.** Keep every binding constraint. Ask
   whether the current approach is really necessary for that purpose, or just the first one that
   came to mind.

3. **Propose up to three distinct approaches,** including the original when it is still viable. For
   each, give its benefits, its costs, the access it would need (data, systems, people, or budget),
   and how you would check that it achieved the purpose.

## What to return

The alternatives and a recommendation judged against the user's own stated criteria; if they have
stated none, propose criteria and label them provisional. Return unresolved value choices to the
user as questions. Do not change the goal or start building.
