# Incorrect assumptions in the v3 tests

Commit 3836abc4. Chrome 146.0.7680.76, `--headless=new`, throttling on, over `conformance/bench/cdp.ts`, throwaway profiles. No `review*.md` or `RESULTS.md` was read, so some of this may already be known.

Verdict: the fake is good on request outcomes and write-ahead, and wrong about what a page's life is. Its central claim, "a process is a generation; when it dies, nothing from it reaches the next one" (`fake-world.ts:2-3`), is false in real Chrome. An ordinary same-origin navigation leaves the old page alive in bfcache, holding the Web Lock, so the next page in the same tab boots as a "second tab". No test in the suite can see this. Next most serious: a fake server more forgiving than Stripe's documented behaviour, a `freeze` that only stops timers, and durability evidence from kills, which cannot test durability.

Marks: [ran] measured here, single run unless a count is given. [read] code or spec read. [reasoning] neither. "Memory" means a citation I did not re-fetch.

## Checked and true

- The next generation gets the lock after a reload (8 of 8) and after `Page.crash` (8 of 8). A frozen owner keeps it, and a second tab is refused: true, though no test has this state. [ran]
- The first send is synchronous: `runForkWith` calls `fiber.evaluate` at once. [read]
- All 8 `@ts-expect-error` lines in `typed/type-tests.ts` fail for the reason each comment gives (`tsc` with the comments stripped). [ran]
- A store shuffled on read is false, since `getAllKeys` returned `["a","m","z"]`, but it is only stricter, so it is harmless. [ran]
- Timers past 2^31 - 1 are refused (`round8.scenario.ts:696`). The fact itself is from memory. [read]
- `performance.now` has a 0.1 ms step. `workClock` differs, and it doesn't matter. [ran]

## Inconclusive

- Quota: my probe with a 200 KB override let 5 MB of `"x"` through. Compression or how Chrome checks quota may explain it, so it doesn't refute `run7 --only quota`. The hypothesis stays open: failure depends on batch size, so "everything dirty goes as one batch" (`edge.ts:87`) can let one large record stop a small ticket, where `plainFails` counts batches and `storage: refuse` is unconditional. [reasoning]
