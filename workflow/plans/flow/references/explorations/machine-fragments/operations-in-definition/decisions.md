# Operations in definition: owner decisions

Decisions the owner confirmed while reviewing the direction of revision 3 ([proposal.md](proposal.md),
[reviews/review-3.md](reviews/review-3.md)). The proposal itself is not revised yet; the next revision applies these.

## Decided

| # | Decision | Date |
| --- | --- | --- |
| OD1 | The retry budget guard takes a named option, following Effect's `Effect.retry({ times })`: `O.pay.retryable({ times: 3 })`, or `O.post.retryable(selectKey, { times: 3 })` for a keyed lane. `times` counts re-sends after the first send, which is what `retryCount` counts. Replaces revision 3's `retryable(n, k?)`. | 2026-10-30 |
| OD2 | Machine verbs are the contract's own function names, not new words: `O.pay.commit(select)` for a write, `O.read.lookup(select)` for a one-off read, `O.feed.subscribe(select)` in `activities` for a live resource or a stream. Different names signal different intent. Revision 3's `start` and `params` are dropped. These are `Operations.plan` O2's existing words (`lookup`, `subscribe`, `refetch`); O6's `descriptor.get(snapshot, params)` is the prior art for `get`. Which verb is used decides one-off or live, not which outcome key is mapped. | 2026-10-30 |
| OD2a | A live resource and a stream both use `subscribe`, as `Operations.plan` O2 already has it. `watch` for resources was considered and rejected: the act (hold it while the state is active) is the same; the kind differences (gaps, recovery by `refetch` vs automatic reconnect, row shape) are already checked by the declaration's outcome keys, the members and the row types. | 2026-10-30 |
| OD4 | Review 3's K3: a contract's `key` is a list of top-level input fields, `key: ["docId", "field"]` (composite keys list every field), like `primaryKey`. Its Schema is the input's pick of those fields. A domain write defaults to the entity's primary key, checked at the operation. Members and `get` accept any value that carries the key's fields (`O.post.get(s, msg)`). Inside an ending's handler, `retry`, `retryable` and `cancel` with no key address that ending's Attempt. Derived or nested keys need the input reshaped. | 2026-10-30 |
| OD5 | Review 3's K1, the owner's recommendation (prior art: RxJS `concatMap` over `switchMap` for writes, TanStack mutation `scope`, Replicache/Firestore ordered write queues, Stripe idempotent retry until known): only a never-sent start is replaceable. A sent Attempt's ending is always delivered. A retained unknown holds its lane: under `latest` the waiting start stays waiting, under `reject` a start ends `Rejected`, until `retry` resolves it or `cancel` releases it. The addressable Attempt is the oldest unresolved sent one. Under `cancel` concurrency, an Attempt interrupted by a newer start is evidence only. The write row gains `uncertain` (merge 4's word), true while the lane holds an unknown. Version preconditions (`If-Match`) remain a contract-level option on top, not a replacement. | 2026-10-30 |
| OD6 | Review 4's K4: the hold stays the default (no quiet release, no automatic retry). `flow check` reports `UnresolvedHold` when a path can leave a write's unknown neither retried nor cancelled, read from the machine's tokens. The write row gains `waiting` (a commit queued behind a held unknown). | 2026-10-30 |
| OD7 | Review 4's K5: `cancel` acts on the same one Attempt as `retry`, the oldest unresolved sent one; after it is released, the waiting commit is sent. `cancel` never silently drops a waiting commit. | 2026-10-30 |
| OD8 | Review 4's K6: a key-less member on an unkeyed operation always names its one lane. On a keyed operation it is allowed only in a handler of an event that this operation alone maps, and names that ending's Attempt; anywhere else it is `KeyRequired`. | 2026-10-30 |
| OD9 | Section 11 round 1, all option A: Q2 (write lanes per operation and key, created by work), Q4 (one write operation per write contract, a `SharedContract` error otherwise), Q6 (a one-off read delivers only its latest lookup), Q7 (a bare write's results are evidence only), Q21 (a one-off read's row is OPS O6's resource lane), Q22 (`O.x.subscribe.each(select)`), Q23 (`VerbMismatch`, and `cancel` on a one-off read; amends OPS O7), Q26 (one-off read lanes are not persisted). | 2026-10-30 |
| OD10 | Review 5: the next revision states the write lane as an explicit state machine (states `Idle`, `InFlight`, `Held`, each with an optional waiting commit; a table of every member and ending against every state; `pending`, `uncertain`, `waiting` defined as functions of the state; `UnresolvedHold` as a check over that graph), and applies review 5's rule cuts. | 2026-10-30 |
| OD11 | Contracts keep their function inline (`commit`, `lookup`, `subscribe`), calling user services whose Layer is the swap point. Contracts as pure data implemented by a Layer per contract (the RPC exploration's design C, `contract.toLayer`) is rejected. | 2026-10-30 |
| OD12 | Every contract kind (transaction, resource, stream) has exactly two schemas, flat at the contract's top level: one for what goes in and one for what comes out. No nesting under the function, and no third `params` schema. `key` names fields of the in-schema; a stream's resume position is an ordinary in-field outside the key; errors stay `Schema.TaggedError` classes typed through the function's Effect. Names: `input` and `output` on every kind (`result` renamed to `output`; mapper context `{ params }` becomes `{ input }`). | 2026-10-30 |
| OD13 | Effect RPC: the core contract stays `input`/`output` plus its function, with no Rpc inside (Rpc is `@stability unstable` in 4.0.5 and adds wire machinery Flow does not need). An opt-in `resource.fromRpc` / `transaction.fromRpc` adapter, taking an existing `Rpc` for its schemas and mapping a client error to `unknown`, comes later when a real app needs it. | 2026-10-30 |
| OD14 | `input` and `output` accept either a fields record (`{ q: Schema.String }`, wrapped as `Schema.Struct`) or a full Schema (for unions and classes), as `Rpc.make`'s `payload` does. | 2026-10-30 |
| OD15 | `key` is required on resources and transactions; there is no default. One lane or one cache entry is written `key: []`. This replaces the "default to every input field" proposal and revision 5's domain-write primary-key default (a domain write states its key too). Streams: not yet decided. | 2026-10-30 |
| OD16 | Review 6's K13–K16 are applied as definitions: the table's cells apply in step 5 in action order; `keys` and published rows read the after lanes; `UnresolvedHold` sees commits already waiting; one name per distinct thing; the amendment list to MD and merge 4 is completed. Then one more review. | 2026-10-30 |
| OD17 | Section 11 rounds 4 and 5, all option A: Q12 (persist write lanes by contract id and key), Q13 (`restartOn` per key on keyed schedules, `armOn` banned there), Q14 (`DuplicatePlacement` unless state tokens make placements exclusive), Q15 (names `outcomes`, `get`, `O`), Q16 (mappings only on the definition, for now), Q17 (cache verbs `invalidate`, `clear`, `setData` on the contract, in actions), Q18 (`*.contracts.ts`), Q19 (operations in fragments deferred to their own exploration). | 2026-10-30 |
| OD18 | Q37 (2): a transaction's `progress` keeps its own schema, the one named exception to OD12's two schemas (it is the commit's side channel, not in or out). | 2026-10-30 |
| OD19 | Behaviour, delegated by the owner to the main session ("whatever is still open in terms of behavior"); API and public-syntax changes stay with the owner. Taken: Q28 A (the table's cells as recommended), Q31 A (two tabs: a stated limit), Q32 A (rebase across the lane's own writes; its owner may move to merge 4's record queue per review 7's K20), Q35 A (per-item stops use a keyed design; on `serialize`, key-less members only in the head's own ending handler), Q9 A, Q10 A, Q20 A. Review 7's H1: write lanes are owned by the Runtime, not the actor (TanStack Query's `MutationCache` model): disposing an actor never drops or cancels its sent, held or queued writes; a later actor of the same definition rebinds them by (contract id, key). Left to the owner as API questions: Q29, Q33, Q34, Q36, Q37 (1), Q38. | 2026-10-30 |
| OD20 | Behaviour, delegated (as OD19), from review 8 and the lane model (lane-model/RESULTS.md): a lane's identity is (Runtime O3 actor identity, contract id, key), so a new actor adopts only its own identity's lanes; lanes are Runtime records, captured and acknowledged per lane; `UnresolvedHold` counts an unhandled arrival as keeping the hold; the storage acknowledgement is per Attempt; a held unknown is delivered exactly once on rebind or restore, as `unknown { Restored }`; a storage-refused re-send re-delivers the mapped `unknown` with reason `StorageRefused`; under `latest` a commit replacing a never-sent head becomes the head; Runtime disposal starts no new invocations and ends queued commits `NotSent { Disposed }`; lanes are never hydrated from the server; a released Attempt landing late stays a stated limit, remedied by version preconditions. | 2026-10-30 |
| OD21 | Behaviour, delegated (as OD19), from review 9 and the lane model's G1–G6. K25: an ending (including `NotSent { Disposed }`) for a persisted identity with no live actor is saved as a pending mapped outcome of that identity's record (Persistence O2/O4) and delivered when the record is restored; it is evidence only when no record survives. K26: MD rule 14 is amended so an adopted lane's endings and `unknown { Restored }` are current, delivered from the active leaf (a restored record resumes in its saved leaf); `UnresolvedHold`'s arrivals are every leaf a new incarnation can be in; S7c becomes "handle at the root". | 2026-10-30 |
| OD22 | Behaviour, delegated (as OD19), from review 10. Parked endings are stored raw on the lane record and mapped at delivery, so a release cannot lose them (review 10 M3). | 2026-10-30 |
