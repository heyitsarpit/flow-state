# Review: T16's production walking skeleton (`5206dd7d..18187020`) and T7's rows round 2

Verdict: **T16 meets its acceptance for the Pay path but is not ready to ship.** The adapter does no runtime
work. The core is pure, synchronous and deterministic. All 13 production mutants are real faults and are caught. But
four paths that users reach are wrong and no case exercises them:

- the public `Runtime.dispose()` skips the disposal protocol;
- `ready()` runs more than once, acquires services before it reads storage, and does not gate early calls;
- an input that cannot encode is sent with no durable record;
- `latest`, `serialize` and `cancel` contracts compile and silently behave as `reject`.

The suite passes because it drives disposal, uses and boot through `src/host/testing.ts`, not through the public
routes. T7's rows round 2 is sound in what it asserts. Three rows count as checked while their oracles judge only
part of them (I23 fully, and I2, I14, I17, I18 and I24 on one expectation each).

Method: an archive of `18187020` with `node_modules` symlinked. I re-ran `suite --runtime production`: 61/111 pass,
every failure is a fixture production cannot boot yet, and all 61 `pay`-fixture cases pass. I re-ran
`falsify --runtime production` (13/13 caught, control green). I ran six probe mutants of my own (results under M6).
Four Haiku sidecars ran read-only; their log is at the end. Paths are under `packages/flow-state-v3/` unless they
start with `workflow/`. Specs are cited at `18187020`.

**The T7 range was mislabelled.** `52deba77..189b571c` holds T8 commits only (`44ea855a`, `5b2b23c0`, `189b571c`).
T7's rows round 2 is `6240740c..27753f93` (`6240740c`, `1ba1bdb8`, `c4980d35`, `c1a813ad`, `0fb1ab24`, `3e4d155a`,
`6a0ac5a5`, `27753f93`). I reviewed both. `5b2b23c0` is covered under T7-L1.

## Findings, ranked

### H1. The public `Runtime.dispose()` never enters disposal

`src/host/runtime.ts:246-254` calls `driver.stop()`, which only clears host timers (`src/host/driver.ts:181-184`), and
then closes the services scope. It never sends `Input.DisposeRuntime`. So admission stays open, the 5 s bound never
arms, nothing is parked, never-sent commits get no `NotSent { Disposed }`, and nothing waits for the last write. Only
the seam sends the input (`src/host/testing.ts:28`), and the adapter uses the seam
(`conformance/adapters/production.ts:313`).
That is why the DISP cases pass while the shipped route does none of it.

- Rules: Actors R22 ("closes admission first"), R23 (waits for the final write), I35, I38.
- Fix: `dispose()` sends `DisposeRuntime` and completes once disposal ends. Then the adapter calls the public
  `dispose`, so the cases judge the shipped route.

### H2. Boot breaks Actors R2 to R4 and I3, I4

All four points are in `src/host/runtime.ts:199-223` unless another file is named.

- **No once-guard.** Each `ready()` builds a new scope and Layer and sends another `Boot`. The second boot replaces
  `records`, `lanes` and `parked` wholesale (`src/core/incarnations.ts:307-317`), dropping lanes created since the
  first. Rules: I3 ("the bootstrap runs at most once"), R2 (callers share one Exit), I2 (each service acquired once).
- **Services before storage.** The Layer is built (`:201-210`) before `store.load()` (`:212-220`). Rule: I4.
- **Early calls are not gated.** `ensureActor` (`:227-229`) starts a fresh actor before boot and saves it
  (`src/core/incarnations.ts:191`, `:164`). An early `send` to an actor with no incarnation is dropped with no reason
  (`src/core/step.ts:79-86`). Rule: R4 (reject with `RuntimeNotReady`; a send to a persisted actor queues until boot).
- **Not covered.** Actors Q2 already says no prototype case covers this. The suite boots once, through the adapter
  (`production.ts:290`).

### H3. An input that cannot encode is sent without a durable record

`commit` checks only that the key encodes (`src/core/lanes.ts:96-101`). Persisting the lane then calls `encodeLane`,
which returns none when the input fails to encode (`src/core/record.ts:129-143`). `laneWrite` turns that none into a
removal (`src/core/persist.ts:76-83`). The ticket still arms. When storage acknowledges the removal, the head is
invoked. The write goes on the wire with no lane record, so a reload forgets it.

- Rules: WriteLanes R12 ("a commit whose input or key cannot encode declines NotSent { Unencodable }"), I18.
- The same silent drop hits actor records: `actorWrite` writes nothing when the memory cannot encode
  (`src/core/persist.ts:64-73`). Rule: Actors I12.

### H4. Public features compile and are then ignored

These are a walking skeleton's gaps, which T16 may have. But the public types accept them and the runtime ignores
them without an error. Those combinations are wrong answers, not missing features.

- **Concurrency.** `Concurrency` is `"reject" | "latest" | "serialize" | "cancel"` (`src/core/compiled.ts:163`).
  `src/machine.ts:198` copies the value, and nothing reads it. `commit` (`src/core/lanes.ts:87-143`) always rejects.
  STATUS lists "reject is the only concurrency" as open, not as a refusal. Rules: WriteLanes R6, R7.
- **Computed entry schedules at a fresh start.** `start` keeps only `Fixed` delays (`src/core/incarnations.ts:137-142`).
  So a computed schedule on the initial state never arms, while one on a transition does
  (`src/core/turn.ts:230-262`). Rule: Turn R14 ("a schedule without armOn starts on entry"). This is a bug in a built
  feature, not a gap.
- **Mapper context.** Mappers receive `{}` (`src/machine.ts:170`), which breaks WriteLanes R4.
- Fix: until each of these is built, compilation refuses it with `UnbuiltInProduction`, as the adapter already does
  for part sends.

### M1. Restore wakes identities it must leave as records

- **Undecodable records are overwritten.** Boot calls `ensure(actor, none, false)` for every identity with a parked
  ending (`src/core/incarnations.ts:340-344`). With no record, `!existing` starts a fresh actor from `initialMemory`
  and saves it (`:191`, `:126`, `:164`). A record that failed to decode is dropped silently
  (`src/core/record.ts:181-188`), so that identity gets invented state written over its stored record. Rule:
  Restore I1 ("an Owed identity whose record is quarantined ... has no live incarnation").
- **Held heads are restored live, against the user's ruling.** Each Held head's `unknown Restored` is parked at boot,
  so its identity is live at ready (`:319-338`). The user ruled on 2026-11-11 (`5aa3b95a`) that Restore R1 stands and
  DISP-05 changes. T16's code and STATUS ("Open: Restore R1") predate that ruling, so the change is now owed.

### M2. Kept endings are invisible to `idle`, `retry` and `cancel`

`commit` treats a kept ending as blocking (`src/core/lanes.ts:106`), but `viewOf` returns `Idle` whenever no lane is
found (`:390-402`). A kept ending lives only in `world.parked`, so `idle(k)` passes on a key that `commit` will
reject. Snapshots omit kept rows (`src/host/runtime.ts:134-145`).

- Rules: WriteLanes R6 ("a kept ending ... is a value on its lane"), I13 ("holds no kept ending").
- Probe `kept-ignored`: deleting the kept check at `lanes.ts:106` survives the whole suite on production. No case or
  oracle protects it.

### M3. Lane addressing breaks R9, I14 and R14

- **A key-less member takes the ending's own lane.** `laneFor` (`src/core/lanes.ts:145-157`) never checks that this
  lane belongs to the member's operation. So a key-less `B.cancel` inside A's ending acts on A's lane. Elsewhere, a
  key-less member on a keyed operation is a silent no-op, not `KeyRequired`. Rules: WriteLanes R9, I14.
- **Cancel does not wait for an acknowledgement in progress.** Cancel during `Acknowledging` ends `NotSent
  { Cancelled }` at once (`lanes.ts:224`). Rule: WriteLanes R14 ("cancel waits for storage").

### M4. Snapshots are live world data, not frozen

`snapshotOf` returns the world's own memory object (`src/host/runtime.ts:148-158`), and nothing in `src/` freezes
anything (no `freeze` in `src/`). A caller that mutates a snapshot mutates the core's state and the record it
persists next. Rules: Turn R24 ("deeply frozen plain data"), I29. The publication oracle judges identity only, so it
cannot see this.

### M5. The StillUnknown failure is lost, and the adapter hides it

- **The runtime drops it.** The runtime rewrites the ending to `unknown StillUnknown` and drops the definite failure
  (`src/core/lanes.ts:363-366`). Rule: WriteLanes R2 ("StillUnknown { failure }").
- **The adapter reports none.** It hardcodes `failure: Option.none()` (`conformance/adapters/production.ts:152`).
  `failureKept` passes on none (`conformance/write-lanes/ending-channels.ts:163-171`), so on production that clause is
  vacuous. The prototype adapter does the same, so the gap predates T16.
- **`entity` should refuse, not answer none.** `entity` returns none (`production.ts:336`). It should throw
  `UnbuiltInProduction`, as `send` does for parts (`:300-301`). LANE-16 is its only reader, and it cannot boot today.
- **Latent fabrication.** `part: []` and `definition: e.actor.machine` (`:125-126`) are correct only for a machine
  with no child parts.

### M6. The production mutants are sound but thin

- **All 13 are sound.** Each applies once, breaks a real behaviour, and is caught by an oracle or a case for the
  stated reason (re-run). Twelve break the runtime, which shows the adapter is not doing that work for it. One breaks
  the adapter.
- **Seven core modules have no mutant:** `persist.ts`, `record.ts`, `tx.ts`, `rows.ts`, `evidence.ts`, `world.ts` and
  `input.ts`. The production falsify passes without a count check or the coverage gate
  (`conformance/runner/main.ts:308`; the prototype path has both, `:435-437`). A dropped mutant would shrink the
  denominator unnoticed. The run notes "no production mutant yet for: graph-names late-results".
- **My six probes** (`suite --runtime production`, compared with the baseline's failures):

  | Probe             | Edit                                | Result                                                       |
  | ----------------- | ----------------------------------- | ------------------------------------------------------------ |
  | `wa-skip`         | flushLanes skips capture            | caught by case expectations only (PAY-01, PAY-05, DLV-01/02) |
  | `no-actor-save`   | `saveActor` writes nothing          | caught (DISP-01..05, PAY-05, PAY-09)                         |
  | `boot-unapplied`  | restored heads not `mayHaveApplied` | caught (PAY-16, I25/I3)                                      |
  | `no-stillunknown` | StillUnknown rewrite removed        | caught (PAY-05, PAY-16)                                      |
  | `kept-ignored`    | commit ignores a kept ending        | **survives** (M2)                                            |
  | `mint-random`     | ids not deterministic               | caught by the replay (Turn I17)                              |

- Recommended: register `wa-skip`, `no-actor-save` and `kept-ignored` (with a case) as production mutants, and give
  the production run the count and coverage checks.

### M7. The test seam is unexported but reachable from every Runtime

`testing.ts` is imported only by the adapter and is not in `src/index.ts`. But every public `Runtime` carries
`[Symbol.for("flow-state/runtime-internal")]` (`src/host/runtime.ts:79`, `:100`). Anyone can reach it, and through it
`driver.input` (fake `Settled`, `Stored`, `Fired`, `Forget`) and the whole world. The seam's doc names a route,
`flow-state/internal/testing` (`testing.ts:18`), that does not exist, and the package has no `exports` map.

- Fix: use a module-private `Symbol()` or a `WeakMap` from Runtime to internals, shared by `inspect.ts` and
  `testing.ts`.

### M8. Implicit state machines and stored derived facts in the core's data

Both are AGENTS rules for the core.

- **Implicit state machines:**
  - an Ending's life is three booleans: `current`, `redelivered`, `parked` (`src/core/world.ts:110-112`). They are
    switched by hand at `src/core/serve.ts:94-95`, `:162`, `:271` and `src/core/incarnations.ts:86-93`;
  - `Head.sent` sits beside `phase` (`world.ts:72`). It splits `Ready` into a first send and an owed re-send, and
    it decides capture or acknowledge (`lanes.ts:26`, `:326`, `:338`);
  - `Parked.kept` (`world.ts:198`) and `OnWire.cancelled` (`world.ts:54`) are flags of the same kind.
- **Stored derived facts:**
  - `World.tickets` (`world.ts:213`) duplicates the `Silent` timers that already hold the ticket;
  - the lane record's `inFlight` (`src/core/record.ts:141`) is derived from `phase` and never read back;
  - `Lane.id` is rebuilt by hand at `record.ts:239`.

### M9. Serving order and bounds

`drain` stops at a silent 10 000 items (`src/core/serve.ts:279-285`). Leftover mail stays queued until some unrelated
input arrives. Follow-ups go to the tail of one global FIFO (`src/core/tx.ts:150-152`), with no 64-per-event bound and
no `InvalidTurn`. Rule: Actors R13 ("Follow-ups run first, up to 64 per admitted event").

### L1. A `false` guard becomes a decline with no code

`verdict === true ? OPEN : Option.some(verdict.code)` (`src/core/turn.ts:176`) turns `false`, or any other
non-Denial, into a decline with code `undefined`. Rule: Turn R12 ("any other invalid return is a guard defect").
Only untyped code can reach it.

### L2. Pay's guarded stays match the real Pay, except in UNSURE

The decision holds for PAYING. The stand-in keeps the real guard, so `states.PAYING.on.Confirmed[1]` and `[2]` sit
where they do in the real Pay (`workflow/plans/flow/references/checkout/features/Pay/pay.machine.ts:256-275`).

The shared `challenge` stand-in (`conformance/machines/pay.ts:205-210`) differs from the real Pay in UNSURE:

- In `UNSURE.on.IntentRead[1]`, it drops the real guard's `memory.clientSecret !== null` and the real action
  `O.pay.cancel(intent)` (real Pay `:400-412`). A `requires_action` read with no client secret therefore selects
  `[1]` here and `[2]` in the real Pay, and the Held pay lane stays Held.
- In PAYING, it writes a notice where the real Pay stores `clientSecret`.

No case reaches `requires_action`, so nothing judges these stand-ins. The fix is to copy the real guard and the
cancel into the UNSURE stand-in.

### T7-M2. `ending-channels` lets through every `unknown Cancelled`

`if (ended.channel === "unknown" && ended.reason === "Cancelled") return [];`
(`conformance/write-lanes/ending-channels.ts:184`) passes any answered send that ended Cancelled. It does not check
for a cancel, release or interrupt in the Case's history, which R14 requires. `3e4d155a` describes the exemption as
"an interrupted send's", but the code does not check that. No mutant exercises the line. It is also why only LANE-13's
own expectation sees the key-less cancel hitting the wrong lane (STATUS.md:448-451).

### T7-M3. Five rows are cleared on one expectation each

The coverage gate counts an Invariant as checked when one case cites it and one mutant expects it
(`laneKeysCovered`, `conformance/write-lanes/lane-keys.scenarios.ts:119-125`). That cleared these rows:

- **I14:** only the in-handler key-less cancel is tested. `KeyRequired` elsewhere is not.
- **I18:** the decline is tested. R12's mapper value is not.
- **I17:** the decline at release 2 is tested, nothing else.
- **I2:** the Refused path is tested. The unknown path is not.
- **I24:** the edit and the answer both use "Kept" (`lane-keys.scenarios.ts:109-112`), so the check cannot tell
  "confirm with the answer's value" from "keep the predicted value".

STATUS.md:434 also still lists I2, I17, I19, I23 and I24 as T7's, which disagrees with the rows. Recommended: give
each its rest as a remainder row, or make LANE-16's answer differ from its edit.

### T7-L1. `5b2b23c0` widened the Spec before D4's proof

## Answers to the brief

- **Adapter runtime work:** none. Twelve runtime mutants are caught through it. Its two fabrications are M5's.
- **Core rules:** pure, synchronous and deterministic. There is no Effect runtime, clock, randomness or host API in
  the core. Work is returned as data, and the only throw is the definition-time `FlowError`. Breaches: M8 and L3.
- **Specs or a copy of round-14:** the code follows the Specs' Pay subset in its own shape, not round-14's. Where it
  departs, it is narrower than both the Spec and round-14 (H2, M2, M3, M9) or follows a case the user has since ruled
  against (M1).
- **Mutants:** sound, but they miss persistence and records (M6).
- **Test seam:** not a public route by import, but reachable by a global symbol (M7).
- **Pay's guarded stays:** right in PAYING, but wrong in UNSURE (L2).
- **T7 round 2:** sound, but over-credited (T7-M1 to T7-M3).
