## Blocking

### K1. B2 is not built: `Finished` and `Incarnated` still steer expect from reports

`dsl/compare.ts:315` applies a reported `Finished` as `ActorMove.Finished`, which sets the record to `grace`
(`dsl/lifecycle-fold.ts:41`). The next `Ensured` then adopts (`dsl/expect.ts:113-126`), and `incarnate` owes each
Held head's restore (`dsl/lifecycle.ts:519-531`). A runtime that never ends an actor owes no restores; one that
reports a false end creates them. `Incarnated` (`dsl/compare.ts:304-314`) is gated on a suite fact but never owed,
so omitting it skips the `Opens` lives. Both are unchanged from 74911f8d. The accepted design (section 2, decision 3)
owes the end from held uses, lane state and `Advanced` past the 100 ms grace (Actors R8, I10, I37). The lead's
comments say "Step 3 done" and never mention it.

**Fix:** build section 2's two actor rows in `dsl/expect.ts`; compare matches `Finished` and `Incarnated` to them.

### K2. The anchor is an expect module, but its calls are built from report fields

`turn/selection.ts:366-374` feeds the reported `Minted` (actor, key), `Sent`, `Ended` (channel, reason) and
`Unparked` into `turn/anchor.ts` (`minted` :180, `ended` :246-262, `current` :208). `routeOf` (:158) reads those
calls to pick `current`, `late` or `either` (Turn R20), and `pendingOf` reads them for Turn R21. Omitting `Minted`
gives `either`, the weakest route; a reported `unknown { Restored }` in an attaching step makes a call current.
`dsl/boundary.test.ts` passes because the report arrives through function arguments, not imports, so the T40 check
certifies a module whose state is report-driven.

**Fix:** derive the calls from expect's own lane items (an owed mint's owner is the predicted turn's leaf and entry;
an ending's channel from expect's ending item), and pass the anchor only the index compare matched.

### K3. A turn's header, event and keys still fall back to the report

- `turn/selection.ts:157` and `turn/judge.ts:105-109`: `from` is the report's whenever the anchor has no leaf: after
  a kill with lost turns, for a `Fresh` actor, for `Unanchored`, and for an undeclared machine. `wrongFrom` checks only
  when anchored. Design section 3 allows "any leaf those turns reached"; the code admits any leaf at all.
- `turn/selection.ts:163`: `event: turn.event`. `admitted` (:79-86) accepts any driven credit, so the report picks
  which driven event ran, and `chosenRow` (`dsl/lifecycle-owed.ts:148-151`) picks the owed row from it.
- `turn/selection.ts:167`: `keys: { ...reportedKeys(turn), ...keysFor(...) }`. Where a fixture folds no key, or the
  fields are unknown, the report's key chooses the lane the commit is owed on.
- Nothing owes a turn from `Drove` (design section 2, "turn: event"): a driven credit that no `Turn`, `Unhandled` or
  `Denied` consumes is dropped without a refusal (`turn/selection.ts:249`, and no end-of-step check).

The lead logged the lost-kill case as carried; the other cases are not listed. `dsl/lifecycle-owed.ts:180-182` says
"no report is read here (Conformance R20)", and the `Predicted` doc cites a `limits.ts` row; no `conformance/limits.ts`
exists at this revision (only the prototype's budget file).

**Fix:** a lost leaf becomes the allowed set the unsaved turns reached; a `Fresh` actor's leaf is the fixture's
initial state; the event comes from the credit order; every remaining fallback becomes a real limits row the liar
gate counts; an unconsumed driven credit at the step's end is refused (Turn R2).

### K4. NO_POLICY declines are still report-only

`dsl/lifecycle-lanes.ts:341-351` accepts any `Unencodable`, `NoPersistence`, `OldVersion` or `ModuleDisabled`
decline. A runtime can turn any owed commit into one and owe nothing. Design section 4 made these facts
(`Reloaded.release`, the `encodable` label, the boot's persistence choice) with "no limits rows"; `Reloaded` is still
`{}` (`dsl/facts.ts`). Not built and not logged.
