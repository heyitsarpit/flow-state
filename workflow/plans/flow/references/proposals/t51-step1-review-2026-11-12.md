## Findings, most severe first

1. **Q3 is a harness bug, not a production requirement.** `code:packages/flow-state-v3/conformance/dsl/case.ts#reload`
   records `Fact.Ensured` (line 343) before it asks `removed(actor)` (line 345). `removed` takes the actor's last
   Disposed, Forgot or Ensured fact, which is now that Ensured, so it is always false. The driver therefore always
   calls `ensureExisting`, even for a forgotten actor. The Port says `ensureExisting` never creates
   (`conformance/port.ts:375`). The comment on `removed` (case.ts:412) and Actors R21 ("the next ensure starts
   fresh") both call for a creating `ensure`. The model is right: it saw an Ensured, so it owes a fresh incarnation
   (Actors R9, I14). Production is right not to create one on `ensureExisting`. The fix is to read `removed` before
   `record`. That file is outside T51's May change, so the orchestrator owns it. Every case that forgets or disposes
   an actor and later re-attaches it has gone through this dead branch. Proposed: drop Q3 from T51 or make it
   conditional. Re-run GEN-pay-seeded-281 on production after the driver fix, and add a production requirement only
   if it is still red.

2. **Missing: the bound path of `dispose()` (Q2b).** The Q2 case only answers inside the bound. A rework whose
   `dispose()` waits on a `Deferred` with no bound passes Q2, yet it hangs a real dispose whose call never answers.
   Actors R22 says that past 5 s an Attempt on the wire ends unknown { Disposed } and its late result is ignored.
   Add a case: the call never answers, then `advance(5000)`, then `dispose()` exits, and the evidence is the
   unknown Disposed ending followed by RuntimeDisposed.

3. **Weak Q2 check** (`src/host/lanes.test.ts:198-221`). It never asserts that `dispose()` is still pending before
   "ding", and `Parked` carries no channel (`src/core/evidence.ts:96`). A rework that parks the on-wire Attempt as
   soon as dispose starts and returns at once passes, which breaks R22's "a call settling within 5 s is parked".
   Fix: run it with `runFork` and assert the fiber has not exited before the answer. Then boot again and assert
   that the next incarnation hears `success`.

4. **Weak Q1 check** (`src/host/lanes.test.ts:177-195`). It reads endings only. A rework that re-sends after the
   disposal started (R22: "nothing new is invoked") passes, as long as the re-send never answers. Add
   `second.bell.waiting.size === 0` and no `Sent` for the Attempt on the second boot.

5. **Missing: key-less members on an unkeyed operation (Q11).** See ruling 4.

6. **Weak Q5 check** (`noEndingFlags`, `src/host/lanes.test.ts:228-231`). It bans four key names, so renaming one
   (`sent` to `wasSent`), nesting it, or widening the type to an index signature passes. It also leaves out
   `Parked.kept` (`src/core/world.ts:230`). The model makes Kept a Phase, while the composition paragraph keeps it
   in the parked map. Fix: assert the exact key sets of `Head`, `Phase`'s cases, `Ending` and `Parked`, with a
   two-way `Equal` type, so that any rename or added flag fails. Keep `mayHaveApplied`, which WriteLanes R5 puts on
   the Attempt.

7. **Missing: totality, Q5's open cells, and the derived fields.** Nothing checks the "one total function, no `if`
   chain" part of acceptance 1. Neither Q5's two open cells (Kept with a cancel commit; a kept unknown on a Held
   head) nor the dropped `tickets` (world.ts:245), `Lane.id`, `key` and `keyText` (world.ts:117-121) have a
   check. Proposed: make the table a mapped type over Phase × Cue, so a missing cell fails to compile. Add a type
   assertion that those two cells have type `Impossible`, and fold `Lane` and `World` into the exact-shape check
   from finding 6.

8. **Q6 covers less than acceptance 2** (`vite.config.ts:55-60`, 310, 314-317). The approach names "Sent, Minted
   and endings", but the lint bans only `Minted`, `Sent` and `Lane`. The endings a cell decides (Rejected,
   Overloaded, Cancelled, Disposed, which reach `Ended` and `Parked`) are not covered. The rule can also be dodged:
   an alias (`import { Evidence as E }`) or a bare `{ _tag: … }` literal passes. The exemption also covers all of
   `src/core/cells.ts`, which is where the lane will live, so the rule only proves the reports sit in that file.
   Proposed: list the ending kinds `evidenceOf` owns and add them, or log why they stay written. Narrow the
   exemption to `evidenceOf` itself, or check the property by behaviour.

9. **Q9 regex misses forms that exist today** (`tools/flow-state-lint/index.ts:7`): "the Restore Spec's R5"
   (`src/core/record.ts:148`), bare Task ids such as "owed by T19" (`src/host/browser.ts:16`), and "(T18)" in a
   string at `src/machine.ts:286`. It also misses the letters D, G, H, M and P, and ids split across `//` lines.
   Widen it to an optional "Spec's" and bare `T\d+`, and say whether strings count.

10. **Q7 is minor.** `lookupTakesInputOnly` checks the internal `Call` arity. If the `Read` variant is renamed it
    passes vacuously, because `never extends …` is true. Reads I21 allows a ctx without an Attempt. The public
    `lookup` already takes only its input (`src/contract.ts:152`). Better: assert that the Read context type has
    no `attempt`, `id` or `key` key, and add `[LookupArguments] extends [never] ? false : …`.

## Rulings

- **Item 3, GEN-pay-seeded-281:** the model is right and so is production; the case driver is wrong (finding 1).
  The rules: Actors R21 says the next ensure after a forget starts fresh, Actors R9 and I14 say a fresh ensure
  owes a new incarnation, and the Port says `ensureExisting` never creates.
- **Item 4, retry:** this is a production bug, and it needs a T51 requirement (Q11). WriteLanes R9: "On an unkeyed
  operation a key-less member names its one lane." `laneFor` (`src/core/lanes.ts:147-159`) resolves a key-less
  member only through the ending's own Attempt. So outside a handler, `retry` gives NothingToResend (lanes.ts:175),
  `cancel` does nothing (lanes.ts:267), and `idle` and `retryable` see Idle (lanes.ts:399). An `idle` guard that
  passes while the lane is InFlight is a correctness bug, not only a report. The rework rewrites `laneFor` anyway
  once lane ids are derived. Check: in `lanes.test.ts`, an external event retries the Held unkeyed lane, and the
  bell sees a second ring with the same id. `KeyRequired` for keyed operations is not built anywhere in `src/`.
  Proposed for revisit.md unless a fixture has a keyed operation.
- **Item 5, mutant re-pointing:** a re-pointed mutant counts as the same mistake only if all five hold:
  1. Its edit changes the single decision its `says` names (one cell or one derivation in the reworked code),
     and nothing else.
  2. It applies, compiles and runs. It is not killed by a type error or a crash.
  3. On its unchanged `cases`, it is killed by the oracle in `expects`, and by no other oracle first.
  4. Its first divergent fact from the clean run (step, fact kind and Attempt) matches the original mutant's at
     909f4bee. Record both traces in the T51 comment.
  5. If the rework makes the mistake impossible to write (for example `prod.kept-redelivered`, once the
     `redelivered` flag becomes a tries tag), the edit goes to the equivalent tag transition. If no single edit
     expresses it, the mutant is retired with a logged reason, not forced onto a different mistake. A retired
     report-only mutant is what acceptance 2's "fall" asks for.
