plan React
title   React ownership, attachment and passive views
status  proposed
goal
    Give React components stable actor handles and exact, tear-free selected values from the
    production Runtime. Render computes a pure first snapshot; commit attaches the same handle.
    React neither builds a second execution engine nor starts actor work during render.

    This Plan owns FlowProvider, the hooks, attachment, grace disposal, view eligibility and
    render errors. ServerRendering owns Hydrate and its ancestor-only server view; Runtime owns
    actor admission, context and disposal. This restates FlowState O7, D38, D40 and D51 and carries
    FlowState Q1 as an open question. references/ledger/React.md records archived dispositions.
outcomes
    O1  Provider and Runtime ownership
        flow-state/react exposes FlowProvider over exactly one existing Runtime:
        <FlowProvider runtime={runtime}>{children}</FlowProvider>. It is the sole application
        Runtime context wrapper. Construct the browser Runtime outside FlowProvider and outside
        component render, except for a stable host wrapper's lazy useState initializer, as in
        @plan.ServerRendering.O7. construct() remains inert. FlowProvider never constructs a
        Runtime, builds services, reads storage or acquires Runtime disposal authority.

        FlowProvider renders children before ready() completes. Its effect observes the cached
        runtime.ready(); concurrent observers join the same bootstrap. It never suspends or
        replaces children with a readiness fallback. Before readiness, ensuring hooks expose pure
        pre-attach handles (@O2); their effects wait for readiness before admission. Hydrate can
        therefore supply its server view during the first render (@plan.ServerRendering.O4).
        An unmounted observer stops waiting without cancelling the Runtime's shared bootstrap.
        A readiness failure is rethrown as FlowError on the next render (@O5).

        Provider props contain no App, services, factory, storage, codec, boot payload, restore
        callback, actor id or startup policy. Persistence is configured on RuntimeSetup before
        React (@plan.Persistence.O1). Hydration payloads enter through Hydrate, never Provider
        props or a mutable Runtime hydrate method.

        Hooks resolve only against the nearest FlowProvider. Explicit nested unrelated Runtimes
        never merge actor lookup, canonical data, persistence, subscriptions or ownership. A
        handle from another Runtime cannot be read through useView under this Provider: reject
        with a provenance FlowError before subscribing. A principal switch constructs a new
        Runtime under a keyed Provider and the host disposes the old Runtime; changing a key
        alone does not dispose a Runtime. Requests and Stories own separate scoped production
        Runtimes (@plan.Runtime.O7, @plan.Testing.O7, @plan.ServerRendering.O1).

        All actors and store entries in one Runtime publish into one versioned store. Every
        useView call in one render reads one version, including reads across actors. During SSR
        and hydration it reads one immutable ancestor-boundary view instead (@O2).
        Reference: references/dispatch-desk/app/view.tsx and app/host.ts.
    O2  Hooks and the first render
        useActor(machine, options?) owns one fresh opaque local actor per component incarnation,
        including machines without input. Options require exact input when declared; there is no
        stable actor id. Wiring comes from the app default. Imperative runtime.createActor is
        the immediately admitted host path (@plan.Runtime.O3), not a React render operation.

        useActorByRef(ref, options) is the ensure form. Any options object, including {} for an
        input-free machine, selects ensure; it passes exact input when declared. Without options,
        useActorByRef(ref) is lookup only and returns Actor | null. A missing or disposed actor
        returns null; a foreign, forged, opaque-local or machine-mismatched ref rejects with a
        provenance FlowError. A null ref returns null and starts nothing. An ensure with a
        non-null ref always returns a handle, never Actor | null. Neither lookup nor ensure calls
        ensureActor or adopts a lazy entry during render. Lookup does not subscribe or count as
        a use; a later parent render may resolve a newly admitted actor.

        During ordinary client render, an existing actor supplies its committed snapshot. When
        no actor is attached, both ensure forms return a stable handle reading a pure pre-attach
        snapshot: default state path; memory from initial(input); passive context selected from
        available provider snapshots; lifecycle active; no issues; active resource lanes Pending
        with data undefined or the declared pure placeholder. Inactive lanes remain absent.
        pending reflects unsettled optimistic/predicted writes, not merely a pending lookup.
        No initializer result is discarded merely because commit attaches: fresh admission uses
        the prepared memory. A restored or already-existing shared actor wins over fresh input
        under @plan.Runtime.O3 and @plan.Persistence.O4.

        This computation creates no actor registration, context edge, Scope, subscription, work,
        storage write or evidence. It does not evaluate effectful adapters, start schedules,
        deliver outcomes or adopt lazy code. initial and placeholders are pure and may be
        evaluated for a render that React later discards; evaluation is not a machine turn.
        Provisional context is never persisted or emitted.

        In server rendering and the browser hydration render, hooks obey H1 of
        @plan.ServerRendering.O4: only component props and ancestor Hydrate payloads determine
        the snapshot, even if the live Runtime has a restored draft or a sibling payload.
        getServerSnapshot applies the selector to that immutable view. A ref absent from the
        ancestor chain gives null for lookup and the pure pre-attach value for ensure. A lazy
        ref carries its machine for this projection; it still causes no adoption.

        Handles, send functions and typed event constructors stay referentially stable across
        re-renders for the same identity. Re-created equivalent refs compare by machine and
        canonical id, not ref object identity, while conflicting persist/retain/context options
        reject under @plan.Runtime.O3. Changing the ref resolves the new identity. Local input
        is read once per component incarnation; a changed local machine or input emits a
        development diagnostic requiring a keyed remount. Later input for a shared identity does
        not reset it: first accepted input wins.
        Reference: references/dispatch-desk/features/Tickets/editor/useEditor.ts and
        features/Tickets/editor/TicketPanel.tsx.
    O3  Attach, detach, Strict Mode and grace
        A committed hook effect waits for ready(), then admits through the production Runtime:
        create for local actors, ensure for shared refs. Lazy adoption occurs at this admission
        boundary (@plan.LazyFeatures.O2). It attaches the same handle returned during render;
        no replacement Runtime or synthetic actor shell owns mutable truth. Before activation,
        recheck exact provider identities and revisions and install current context silently,
        without onContext, initial, input or finite-work replay. Admission failure reverses its
        partial registrations and edges; no partial actor escapes (@plan.Runtime.O3).

        The pre-attach handle buffers at most 64 sends in FIFO order. A 65th send throws
        FlowError(AdmissionOverloaded) before adding an event, mutating state or emitting
        evidence. Attach drains accepted commands exactly once, after baseline installation,
        through normal payload validation and mailbox admission (@plan.Runtime.O4). Repeated
        effect setup cannot replay the buffer. Closed or abandoned handles never buffer again:
        their later sends reject with a lifecycle FlowError. Discarded renders create no live
        ownership; their private buffers are discarded, not drained into another incarnation.

        Cleanup removes the mounted use. For local actors it schedules disposal after a private
        100-millisecond grace on the Runtime Clock; setup reattachment before the deadline cancels
        disposal and keeps the same actor and handle. This is deferred disposal, not suspension:
        the actor stays active through grace, schedules and activities continue normally, and
        there is no resume protocol or public prepared/suspended lifecycle. At expiry React calls
        runtime.disposeActor; cleanup joins its finalizers and preserves failures. Strict Mode's
        immediate cleanup/setup sequence neither duplicates work nor disposes the actor.

        A mounted ensuring shared hook counts as a use until cleanup. Shared actor retention
        follows its ref's retain on the Runtime Clock (@plan.Runtime.O3); React does not apply
        local grace as an independent shared-actor lifetime. Bound consumers also count as uses.
        Dropping a JavaScript handle alone disposes nothing. An explicit disposeActor affects all
        users: they see lifecycle disposed and later sends report SendTargetAbsent; a still-mounted
        ensuring hook re-ensures a new incarnation after disposal. Old outcomes, schedules and
        issues cannot reach it. A provider with live consumers cannot be disposed.

        An effect detached while waiting for ready never admits later on behalf of that detached
        component. If a local actor's disposal has begun, reattachment waits for cleanup and then
        admits a fresh incarnation; failed cleanup quarantines the identity and surfaces @O5.
        Activity hiding that exceeds local grace loses the local actor; reveal creates a fresh
        one. Exact hidden-state continuity beyond grace is not promised (@Q1).
        Reference: none yet (stage S10 adds it); references/dispatch-desk/app/view.tsx demonstrates
        closing a shared editor panel and letting its ref retain apply.
    O4  Eligibility in views
        useView(actor, select) is the sole reactive read hook. It accepts an exact actor handle,
        not a Machine, ref or registered view id. It preserves the selector's exact return type
        without adding null or undefined. Lookup users must branch on Actor | null before using
        it. No comparator argument, useShallow, useResource, per-actor context or view-model prop
        surface is added.

        The selector receives plain frozen snapshot data: state, memory, context, issues,
        lifecycle and activities. Public snapshots expose no revision, timers, raw Cause,
        receipts or child projections (was FlowState D38). Disposed snapshots retain the last
        committed state, memory and context with lifecycle disposed. Inspection owns revisions
        and schedule evidence (@plan.Inspection.O1).

        Reads are pure functions of the snapshot: S.X.is, S.X.child, check(s, event),
        descriptor.get(s, keyInput) and Entity.get(s, key, shape). check returns Allowed, Denied
        with every reason, or Unhandled (@plan.Machines.O4); it never dispatches. State tokens
        narrow snapshot types. Views derive button eligibility and denial text from check,
        rather than reproducing guards or reading transaction execution state.

        Activity lanes belong to the actor's own subscription and follow @plan.Operations.O6:
        resource tags Pending, Ready, Refreshing, Failure, Defect, Interrupted; stream tags
        Running, Complete, Failure, Defect, Interrupted. All lanes carry data (undefined when
        absent) and pending for unsettled optimistic/predicted writes; domain lanes carry stale;
        paged data holds loaded pages in order and hasMore. placeholder receives previous and
        input and returns data or undefined; it does not change confirmed data. Transactions
        have no view reader: outcomes become events and the machine owns the UI workflow.

        Track each descriptor and canonical key read during an evaluation; replace the dependency
        set after conditional reads change. Matching store publications rerun the selector even
        when the actor snapshot did not change. Reads of several actors and entries never mix
        publication versions. Changing selector identity does not resubscribe to the actor.
        Compare selected values with Equal.equals (was FlowState D40), including Data values
        returned by check; there is no fieldwise Object.is or custom comparator alternative.
        Lanes keep their identity when their observable data has not changed.

        Selectors acquire no ownership, start no work, subscribe to no operation and mutate
        nothing. A passive descriptor.get never fetches, invalidates or extends cache lifetime.
        No refresh, commit, write, clear, disposal or bound can capability is attached to a view.
        Reference: references/dispatch-desk/features/Tickets/editor/TicketPanel.tsx and
        features/Tickets/queue/QueueList.tsx.
    O5  Errors in views
        Memoise a selector exception by its exact actor/store cut. Reading the same cut rethrows
        that exception to the nearest React error boundary without reevaluation; retry only on a
        later matching publication, not an unrelated update or an unchanged-cut render loop.
        A defect encountered while validating initial attachment or hydration aborts that
        admission and rolls back its partial actor. A defect in an already-attached view does
        not undo committed Runtime truth or fail sibling selectors.

        Layer acquisition/readiness, admission, lazy adoption, invalid provenance and cleanup
        failures retain their FlowError classification and cause (@plan.Diagnostics.O1). Effects
        report their failure for rethrow on the next render; they never render a failed feature
        as an empty successful actor. Adoption is retried by a later attach after boundary reset,
        not by calling load during render (@plan.LazyFeatures.O2).

        Resource Failure/Defect/Interrupted lanes and machine-owned typed errors are ordinary
        view data. They do not automatically throw to a React boundary. Unknown commits remain
        explicit machine workflow, with an actionable reconciliation event (@plan.Operations.O3).
        React provides no custom error-boundary API and no Suspense integration.
        Reference: references/dispatch-desk/features/Tickets/editor/TicketPanel.tsx.
decisions
    D1  Ensure always returns a handle; lookup is nullable
        Owner decision 29 settles the former first-render gap. It rejects lazy-features.md Q1's
        nullable ensure proposal. A pure snapshot provides the first render without registration.
    D2  Snapshot shape remains data
        Was FlowState D38: lifecycle stays public; revisions and timers belong in inspection.
        Activity lanes replace O readers (FlowState D39); Operations owns their exact fields.
    D3  One read hook uses Equal.equals
        Was FlowState D40. Selected values are exact and passive; useShallow and Object.is-based
        comparator rules from archived ReactAndHosts O3 are superseded.
    D4  Options distinguish ensure from lookup
        Was FlowState D51: {} ensures an input-free ref; omitting options only looks up.
    D5  Render before readiness is required for hydration
        Adopted server-rendering.md section 3 and owner decisions 30 and 33 supersede the inventory
        suggestion to gate children or require ready() before hydrateRoot. FlowProvider renders
        immediately; effects wait for shared readiness; getServerSnapshot obeys H1.
    D6  Grace replaces suspension
        FlowState D16 remains binding. The proposed private grace is 100 milliseconds on the
        Runtime Clock, testable without wall-clock sleeps. There is no public grace option or
        local retain option in version 1; the Activity continuity question remains @Q1.
constraints
    C1  One production owner
        React attaches and reads; Runtime owns canonical truth, readiness and cleanup. Local
        component lifetime authorizes local disposal only through the Runtime. Server capture and
        Hydrate are @plan.ServerRendering.O1 and @plan.ServerRendering.O4, not alternate engines.
    C2  No compatibility surface returns
        No public prepared or suspended lifecycle, mutable hydration, public writer,
        FlowPersistenceError wrapper, old O readers, bound can or runPromiseExit is restored.
        Durable context remains provider-derived and restored silently (@plan.Persistence.O4).
verification
    V1  Provider, types and isolation
        Compile allowed Provider props and reject App/services/storage/payload/factory props;
        mount nested unrelated Runtimes and reject cross-Runtime handles. Prove children render
        before readiness, readiness failure reaches a boundary, and unmount interrupts only its
        waiter. Compile exact input, nullable lookup, non-null ensure and exact selected values.
        Packed React 18 and 19 consumers pass, including the use client route boundary. Planned.
    V2  Render and attachment accounting
        Count registrations, edges, Scopes, subscriptions, adapter calls, writes and evidence
        before render, after discarded/server renders and after commit: only commit adds live
        resources. Verify pure default and placeholder snapshots, current passive context, same
        handle/memory on fresh attach, changed provider before commit, keyed-remount diagnostic,
        changed-ref resolution and lookup never creating or adopting. Buffer 64 commands, reject
        the 65th without mutation, and drain once under repeated setup. Planned.
    V3  Lifecycle races
        On TestClock verify reattach before 100 ms cancels local disposal and expiry disposes;
        race Strict Mode, Activity hide/reveal, ready completion, explicit disposal, due schedules
        and in-flight work. No duplicate adapters, replay or late admission after unmount. Verify
        shared retain uses, provider-use protection, re-ensure incarnation fencing and quarantined
        cleanup failure. Finalizers and failures cannot be hidden by React cleanup. Planned.
    V4  Passive views
        Verify Equal.equals for primitives, records and Data verdicts; exact conditional descriptor
        key dependencies; entry-only publication reruns; selector identity changes do not
        resubscribe; several actor/store reads never tear. Same-cut selector failure evaluates
        once, later matching cut retries, siblings keep committed truth. Negative Machine/ref,
        comparator and mutation fixtures; no view starts a lookup. Planned.
    V5  SSR and browser integration
        Use the production renderToString/hydrateRoot round trip and generated boundary orders of
        @plan.ServerRendering.O4: identical first HTML, zero recoverable hydration errors, no
        double fetch, no initial/onContext/value-outcome replay. Include eager/lazy refs, nullable
        lookup, restored draft, failed admission rollback and concurrent request isolation.
        Dispatch Desk Next.js browser gates run Chromium, Gecko and WebKit; packed-consumer checks
        run at each stage. These are planned proofs, not current verification receipts.
questions
    Q1  Should local actors survive React Activity hiding beyond grace?
        Was FlowState Q1. Activity runs effect cleanup while hidden, so local actors currently
        expire after grace. Recommended for version 1: accept this behavior; add retain to
        useActor only when a concrete screen requires hidden-state continuity. Shared refs already
        provide explicit retain. The inventory's low-priority suggestion to add local retain is
        not an accepted API expansion.
