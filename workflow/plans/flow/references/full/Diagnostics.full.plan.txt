plan Diagnostics
title   Canonical failures, closed codes and safe remediation
status  proposed
goal
    Give every Flow boundary one FlowError carrier and one Diagnostic schema, with a closed,
    actionable vocabulary, complete Cause classification and safe rendering. Capability owners
    decide when a diagnostic occurs; this Plan owns its shape and codes. No runtime behavior or
    implementation proof is claimed. references/ledger/Diagnostics.md is provenance only.
outcomes
    O1  FlowError
        FlowError extends Error, has readonly _tag: "FlowError", code, diagnostics, optional
        cause and optional evidence. diagnostics is a non-empty readonly array of Diagnostic;
        code equals diagnostics[0].code. The first diagnostic is the primary boundary failure;
        secondary diagnostics preserve phase order and multiplicity. code is never inferred from
        message text. Construction returns values and throws FlowError for expected invalid
        authoring; no generic Error or archived feature error class substitutes for it.

        Diagnostic is a real Error, directly yieldable, with an executable Schema.TaggedError
        codec. Its required fields are classification (exactly Failure, Defect or Interruption),
        code (@O2), path (array of strings or finite numbers), details (record of strings, finite
        numbers, booleans or null), summary and help (strings). Non-finite numbers reject.
        Serialized diagnostics derive from this one codec; unknown codes, unknown closed reasons,
        wrong tags, missing fields and values outside those domains reject. No public projection
        aliases, second codec or second expected-error hierarchy are introduced.

        FlowError.cause is the complete in-process Effect Cause, when available, never a lossy
        message substitution. evidence on a Story rejection is readonly: completed checkpoints;
        end only if captured (otherwise absent); failing command index (zero-based), or the named
        bootstrap/end-capture/cleanup boundary; primary diagnostic; ordered cleanup diagnostics;
        cancelled boolean; retained trace and truncatedBeforeSequence; last accepted and drained
        evidence sequence numbers. These fields reuse @plan.Testing.O8 and @plan.Inspection.O4,
        not a CLI evidence model. Failed capture never invents end; later failure never deletes
        completed checkpoints. Evidence wire projections exclude cause.

        Flow's owned Effects map understood expected failures to FlowError in E while preserving
        success A and requirements R. Die and Interrupt remain Effect defects/interruption, not
        ordinary typed failures. A synchronous Schema decode boundary translates only SchemaError
        into SchemaValidation with actual issue paths and safe scalar details; it does not label
        arbitrary thrown defects as Schema errors. More specific owner codes in @O2 take precedence
        at event, codec, restore and hydration boundaries. Raw parser exceptions never escape.
        Consumers branch on _tag, code, classification, path and details; summary/help may evolve.
        Reference: references/dispatch-desk/tools/diagnostics.ts and app/host.ts.
    O2  The code vocabulary
        This is the complete active Diagnostic code list. It is frozen before S2; adding a code
        requires changing this outcome, its remediation and its exhaustive schema/owner tests.
        Each entry gives meaning, corrective action and owning Plan outcome. Unless stated
        otherwise classification is Failure. Reporting severity (error, warning or informational
        issue) is separate from classification: an issue need not reject a call. Construction
        defects and operational typed failures stay distinguishable under @O3.

        Collection sources: every file in references/design/ and all seven
        references/split-work/inventories/inv-*.md; references/split-work/decisions.md through
        ruling 38; Machines.plan, Operations.plan and ServerRendering.plan. Concurrent capability
        drafts are included where they name codes. Adopted sources are minimal-library sections
        1, 4, 7 to 11; entity-domain sections 4 to 9; server-rendering section 5; lazy-features
        sections 3.3 and 11. multi-tab section 13 is deferred by ruling 38, not silently adopted.
        External research exception names (such as InvalidWhereExpressionError) are not Flow codes.

        Every code carries a real owning path and safe scalar details naming the violated field,
        identity or bound. For example path ["actorRef"], details { machine: "Editor" } for
        MismatchedActorRef; path ["mailbox"], details { limit: 64 } for pre-attach overload;
        path ["states", "OPEN", "default"] for InvalidStateDefault. These illustrate data,
        not additional code/reason variants. Help must prescribe the corrective action below.

    O3  Cause
        Retain complete Exit and Cause through finalizers, cancellation, evidence acceptance and
        cleanup aggregation. Fail, Die and Interrupt remain distinct. Classification is Defect if
        any defect exists, otherwise Failure if a typed failure exists, otherwise Interruption.
        InvariantViolation and Defect classify as Defect; Interruption as Interruption.
        EntryMismatch, ServerOnlyImport, HydrateOutsideProvider and HydrationCrossRequest classify
        as Defect as specified above; a construction
        failure discovered during lazy adoption follows that boundary's Defect classification.
        Classification never rewrites the primary failure order: execution/cancellation stays
        primary; otherwise the first cleanup failure is primary. Remaining cleanup diagnostics
        preserve phase order and multiplicity, even if end was already captured.

        Do not squash Cause until the intentionally lossy synchronous/Promise host boundary.
        runPromise(Effect.exit(effect)) is the supported Exit form. Promise adapter rejection and
        forwarded AbortSignal cancellation preserve the same complete Cause through that boundary;
        operation failures, defects, interruption and remote unknown remain distinct outcomes.
        No thrown exception/Promise rejection becomes a reusable service failure channel.

        Raw Cause, stacks and fiber ids never enter snapshots, checkpoints, persistence, SSR
        payloads, traces, inspector events or CLI output. Only the in-process FlowError may hold
        cause; diagnostics carry safe ordered projections, never a Cause tree. Sensitive application
        values remain raw in in-process checkpoints; outbound values follow Schema redaction with
        keyed per-Runtime/per-run HMAC digests. SSR instead omits sensitive fields and dependent
        items under @plan.ServerRendering.O3, superseding ruling 4's original SSR exception.
        Reference: references/dispatch-desk/tools/diagnostics.ts and app/host.ts illustrate hosts;
        complete mixed-Cause examples have Reference: none yet (stage S10 adds it).
    O4  Rendering
        Shared printers accept Diagnostic only; schema and formatting stay separate. Escape all
        control text in paths/details and summary/help so hostile ids cannot inject terminal/log
        control sequences. Exclude raw input, ANSI, stacks and raw Cause from renderer input.
        Never fabricate file, line or column; source locations appear only when actually known.
        Preserve stable code/path/details and actionable help; human prose/whitespace may change.
        A renderer adds no service, Layer, Logger, route or public renderer/error hierarchy.
        Reference: references/dispatch-desk/tools/diagnostics.ts and app/host.ts.
decisions
    D1  One carrier and one diagnostic schema
        Was FlowState D10, from SurfaceSimplification D14. FlowError replaces FlowUsageError,
        FlowPersistenceError, FlowDisposeError and FlowStoryExecutionError. Diagnostic remains the
        canonical data/codec, not a competing terminal envelope.
    D2  Host execution uses Effect.exit
        Was FlowState D26. runPromiseExit stays deleted; runPromise(Effect.exit(...)) preserves the
        full Exit until the host intentionally projects it.
    D3  Closed vocabulary precedes implementation
        Binding ruling 24: @O2 is the closed list before S2; no undocumented code or reason can be
        added by a printer. Capture conflicts use ConcurrentCapture, never ConcurrentDehydrate.
    D4  Complete aggregation and boundary ownership
        Binding ruling 25: preserve complete Cause until cleanup ends and use defect/failure/
        interruption precedence. Capability owners choose occurrence/failure policy, this owner
        chooses shape/vocabulary; no public diagnostic service or second execution framework.

    V3  Production owner and remediation coverage
        Planned: trigger each active code through its named owner and match its corrective action.
        Include blocked provider disposal with named consumers, incompatible ref claims, distinct
        stream slots opening separate sessions, cancel-idle no-op, whole-batch queue overload with
        accepted FIFO preserved, failed readiness and failed disposal quarantine. No message 
        parsing.

        Planned: prove Cause stays in-process on FlowError and is absent from every snapshot,
        checkpoint, artifact, storage record, SSR payload, inspector event and CLI document.
        Verify partial Story failure before/after end capture and direct/CLI evidence parity.
    V5  Safe rendering and package gates
        Planned: hostile control text, every classification, no invented location, no input/stack/
        Cause leakage, actionable remediation for each code. Run focused diagnostic tests and
        pinned type checks, then fresh root exports/packed-consumer checks at the owning stage;
        these planned proofs have no executable receipt in this proposal.
