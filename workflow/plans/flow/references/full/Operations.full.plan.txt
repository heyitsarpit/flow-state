plan Operations
title   Operations: resources, transactions, streams, writes and activity lanes
status  proposed
goal
    Operations are plain requests. A resource reads keyed data into one canonical store per
    Runtime; a transaction commits a change and reports what happened, including when the outcome
    is unknown; a stream reports continuing values to the actor that owns its session. Machines use
    them only through static declarations with computed parameters (FlowState D1): subscriptions
    in activities, and lookup, refetch, commit, retry, cancel, setData, invalidate and clear in
    actions. Views read what an actor subscribes to as activity lanes.

    This Plan owns the full operation contract: descriptors and keys, the resource store and its
    freshness, transactions and their concurrency, attempts and uncertainty, streams, writes and
    optimistic layers, lanes, and cancellation. Operations registered in an entity domain keep
    every rule here except where @plan.EntityDomains.O1 replaces a call-site write with the
    domain's declaration. Where a rule names a diagnostic code, @plan.Diagnostics.O2 owns the
    vocabulary and its remediation; the names here are the required meanings.

    The archived Resources, Transactions and Streams Plans are provenance only (FlowState C1);
    references/ledger/Operations.md maps each of their commitments to its place here or the reason
    it was dropped. minimal-library.md sections 6, 8 and 8a are the design rationale.
outcomes
    O1  Descriptors and keys
        Three constructors return inert descriptors. Construction runs no adapter, opens nothing
        and registers nothing; a descriptor becomes live only when an App that reaches it is
        constructed into a Runtime (@plan.Runtime.O1).

        - **resource({ id, key?, lookup, result?, staleTime, gcTime, persist? })**: lookup is
        (params, { signal }) => Effect<A, E, R>
        - **transaction({ id, key?, input?, commit, concurrency })**: commit is (params, { signal,
        attempt, basedOn }) => Effect<A, E, R>
        - **stream({ id, key?, subscribe, result?, persist? })**: subscribe is (params, { signal
        }) => Stream<V, E, R> (was FlowState D35); a service is reached with
        Stream.unwrap(Service.useSync(...))

        Fields:

        - **id**: the authored durable name, under the identity rules of @plan.Machines.O1
        (nonempty, at most 256 UTF-8 bytes, no C0 controls, DEL, NUL or lone surrogates, exact
        spelling). Two distinct descriptor objects with one id reachable from one App are a
        construction error naming both.
        - **key**: a synchronous projector (params) => record. Omitted, every call has the empty
        record key {}. The projector must be pure; Flow calls it at admission and in passive reads.
        - **lookup, commit, subscribe**: the adapter. P, A, E and R are preserved exactly through
        the descriptor, the machine's operations record, the App, the Runtime, fixtures and
        Stories. R is satisfied by the Runtime's services Layer (@plan.Runtime.O2).
        - **staleTime, gcTime**: required Duration.Input values with no library default (was
        FlowState D34). Zero is legal: staleTime 0 means data is stale as soon as it lands, gcTime
        0 means an unheld entry is collected at the next turn boundary. Duration.infinity is
        legal: never stale by time (invalidate still applies), never collected while the Runtime
        lives (clear and disposal still apply). A negative, NaN or unparsable value is a
        construction error (InvalidDuration).
        - **concurrency**: required, one of "reject", "cancel", "allow", "serialize" (@O3).
        - **result** (resource, stream) and **input** (transaction): Effect Schemas for values
        that cross a boundary. A resource or stream value is encoded with result whenever it is
        persisted, put into a server-rendering payload or mirrored to another tab; a transaction's
        parameters are encoded with input inside its Attempt (@O3). result is required when
        persist is true (a type error, and a construction error for untyped callers:
        OperationSchemaMissing) and when the resource is registered as a domain read
        (@plan.EntityDomains.O1 infers record shapes from it). Elsewhere it is optional; without
        it the value is omitted from payloads and mirrors with reason NotEncodable
        (@plan.ServerRendering.O3, @plan.MultiTab.O2). There is no error Schema: typed errors never
        cross a boundary (they are not persisted, transferred or mirrored; traces carry the tag).
        - **persist**: resources and streams only, default false (@plan.Persistence.O2).
        Transactions take no persist field; their attempts follow their actor (decisions ruling
        15, @D9).

        Keys (was FlowState D30). The key is a named record. Its canonical form follows the
        archived byte grammar, kept exactly:

        - Allowed values: null, booleans, finite numbers, strings, dense arrays and plain records
        (Object.prototype or null prototype, enumerable own data properties only). The top level
        must be a record.
        - A property whose value is undefined is absent, at any depth; an undefined array element
        is rejected.
        - Canonical bytes: whitespace-free JSON-like text, record members sorted by raw UTF-16
        code-unit order of their names, numbers printed as finite JSON.stringify with negative zero
        as 0, strings with no Unicode normalisation (composed and decomposed spellings stay
        distinct), encoded as UTF-8 by the shared portable encoder (never Node Buffer).
        - Rejected: non-finite numbers, bigint, symbols, functions, accessors and getters, class
        instances and other non-plain objects, cycles, sparse arrays or arrays with extra
        properties, lone surrogates, and reflection that is hostile or inconsistent (a proxy
        whose answers change). Flow reads own data descriptors only and never runs a getter,
        toJSON, coercion or user iteration.
        - Bounds: at most 16 nested levels, 256 value nodes (scalars and containers) and 8,192
        UTF-8 bytes of canonical text.
        - A failure is FlowError KeyInvalid (grammar) or KeyTooLarge (a bound), with details
        naming the exact record path (for example key.filters[2].name) and the rule broken.

        Projection, validation, deep copy and freezing happen before any ownership, admission,
        mutation, publication or adapter call. An invalid key changes nothing: no store entry, no
        ordinal, no attempt, no publication, no adapter start. In an action it fails the action
        batch under @plan.Machines.O3; in an activity it publishes one issue and leaves the lane
        undefined; in a passive read it throws (@O6). Mutating the source parameters afterwards
        cannot change a canonical key.

        Identity. A descriptor plus canonical key bytes identifies one entry (resource) or one
        concurrency lane (transaction) or one session slot (stream) within one Runtime. There is
        no custom hash, custom equality or second key. Runtimes never share entries.

        Authoring rules for keys, stated in the documentation and enforced where a tool can see
        them:

        - Every parameter that can change the result belongs in the key: tenant, account,
        permission level, session, locale. Runtime partitioning is not a substitute; a different
        principal is a new Runtime (@plan.Runtime.O7), and within one Runtime two permission
        levels with one key would share an entry. flow check warns when a lookup's parameter
        record has a field the key projector never reads (@plan.CommandLine.O5).
        - A key never reconstructs parameters and never authorises work: an entry restored or
        hydrated with only its key stays passive until a live binding supplies parameters (@O2).
        - Keys are not redacted: they have no Schema, and they appear in persisted records, payloads
        and traces. A secret must be hashed or replaced before projection.

        Partial matching. invalidate and clear take a family (the descriptor) and a partial key
        record. An entry matches when, for every property of the partial record, the entry's key
        has that property with equal canonical bytes; nested values compare whole. The empty
        partial record matches every entry of the family. Tags are deleted (was FlowState D30).
        Reference (references/dispatch-desk): features/Tickets/ticket.operations.ts.
    O2  Resources
        One Runtime owns one canonical resource store. An entry holds the confirmed data (the base),
        the landed position and time of that data on the Runtime Clock, the generation counter, an
        invalidated flag, the last failure classification, and the live optimistic layers of @O5.
        Equal descriptor and key share one entry, so actors that subscribe to the same entry share
        its data and its in-flight lookup.

        Freshness. An entry is fresh when it has confirmed data, is not invalidated, and less than
        staleTime has passed since that data landed. Otherwise it is stale (or missing, with no
        data).

        Lookups. A generation is one adapter invocation for an entry. Concurrent requests for an
        entry with a generation in flight join it: equal-key lookups share one request.

        - **O.x.lookup(select, options)** (finite, an action): fresh entry: settles success at once
        with the current data, without invoking the adapter; generation in flight: joins it;
        otherwise starts a generation with the caller's parameters.
        - **O.x.refetch(select, options)** (finite, an action): always starts a new generation with
        the caller's parameters. A generation already in flight is fenced: its result is not
        installed, and every occurrence that had joined it joins the new one.
        - **O.x.subscribe(select, options)** (continuing, an activity): binds the entry while the
        activity's identity holds (@plan.Machines.O6). On binding, a missing or stale entry with
        no generation in flight starts one using the binding's parameters; a fresh one starts
        nothing. The passing of staleTime alone never starts a lookup; the triggers below do.

        Automatic generations (subscription start, invalidation, focus, reconnect, reacquisition
        after clear) use the parameters of the oldest live binding of the entry. An explicit
        refetch uses the caller's. A running generation keeps the complete parameters it started
        with, even when the binding that supplied them is released.

        Focus and reconnect. The Runtime receives "focus regained" and "connection restored" facts
        from a host-signal service (@plan.Runtime.O2 installs it: the browser Layer listens to
        visibilitychange and online; server and solo Layers emit nothing; Stories drive it through
        @plan.Testing.O3). On either fact, every subscribed entry that is stale or missing and has
        no generation in flight refetches once, in canonical order (descriptor id, then key bytes).
        Domain answers follow @plan.EntityDomains.O1 instead (a reconnect lowers their frontier).
        Offline never gates explicit work: lookup, refetch, subscribe and commit are admitted
        whatever the connectivity, and going offline cancels nothing.

        Finite settlement. Every admitted lookup or refetch occurrence settles exactly once:
        success with the entry's data after the generation it joined is installed (or with the
        current data when that generation's result was rejected by the ordering rule of @O5),
        failure, defect, or interrupt when the adapter itself was interrupted. An equal value still
        settles its occurrence. A finite occurrence belongs to the actor, not to the state that
        issued it: leaving that state does not cancel it, and its outcome event is delivered as a
        later turn whatever state the actor is in (unhandled, it changes nothing,
        @plan.Machines.O3). Only disposal of the actor ends it early (@O7).

        Outcomes (was FlowState D31, D32). One outcomes container per declaration; every member is
        optional; each maps to a bare event or E.X.from(value):

        - **finite (lookup, refetch)**: success(A), failure, defect, interrupt
        - **continuing (subscribe)**: value(A), failure, defect, interrupt
        - **failure**: for a tagged error union, an exhaustive record from each tag to an event;
        for an untagged E, one mapping receiving the error. When E is never, failure is a type
        error.
        - Mappers receive the value only: never an Exit, Cause, state or lifecycle.
        - An unmapped failure or defect leaves the lane in its Failure or Defect tag and publishes
        an issue on the snapshot; nothing else happens.

        Value outcomes (decisions ruling 12). value fires once at binding when the entry already
        holds confirmed data, unless the binding was restored or hydrated and that data's version
        is the one it last mapped (@plan.Persistence.O4, @plan.ServerRendering.O4). Afterwards it
        fires only when the confirmed data changes by Equal.equals. It never fires for an
        optimistic layer or a domain prediction, and an equal confirmed value is silent. A
        machine's memory baseline (the editor's saved title) therefore only ever holds confirmed
        data. Memory holds keys and drafts, never copies of cache data; flow check warns on a
        memory field written only from a value outcome and never used by the machine (was
        FlowState D29).

        Holding and collection. An entry is held while it has a live subscription, an in-flight
        generation or a live optimistic layer. Passive reads (descriptor.get, checkpoints,
        inspection) never hold, insert, refresh or collect. gcTime after the last hold ends, on
        the Runtime Clock, an unheld entry is collected: data, metadata and generation counter go,
        and a later binding starts from missing. Releasing a binding never deletes data by itself.
        There is no idle retention beyond gcTime.

        Shared work ends only at its final owner: a generation is interrupted when its last
        joined occurrence and its last binding are gone (and only then, @O7). Releasing the first
        or a middle owner leaves the generation and the data intact.

        Fencing. Before any result is installed, Flow checks the entry's current generation, its
        lifetime (a collected or cleared entry is a new lifetime) and the ordering rule of @O5. A
        late result from a fenced generation settles its own evidence and changes no data, no
        replacement binding and no other actor. Requested interruption alone is not a fence.

        No automatic retry. A failed lookup is not retried by Flow: polling and backoff are
        schedules (@plan.Machines.O5), and a retry is an explicit action.

        Persisted resources (persist true) store confirmed data, the landed time and the key, never
        optimistic layers, failures or in-flight generations (@plan.Persistence.O2). A restored
        entry has data and a key but no parameters: it serves passive reads and lanes, and starts
        work only when a live binding supplies parameters. Its landed position is the lowest, so
        any live source replaces it.
        Reference (references/dispatch-desk): features/Tickets/queue/queue.machine.ts (list,
        openCount), features/Tickets/ticket.operations.ts (ticketById persist).
    O3  Transactions and commits
        A commit is finite work admitted only by an accepted action (@plan.Machines.O3). Activation,
        reads, restore, hydration, context waves, schedules and re-entry never admit or re-admit a
        commit; a retry is always an explicit action.

        O.x.commit(select, { optimistic?, writes?, outcomes? }) (was FlowState D36):

        - **select** computes the parameters from the turn's pre-turn snapshot and event.
        - **optimistic**: setData writes applied when the occurrence starts (@O5).
        - **writes**: setData, invalidate and clear applied when the occurrence settles with
        success, whatever state the actor is in by then (@O5). They receive { value }. Failure,
        defect, interrupt and unknown apply none.
        - **outcomes**: success(A), failure (as in @O2), defect, interrupt, unknown(Attempt).

        Attempts (was FlowState D33; decisions rulings 6 and 36). Each admitted occurrence gets one
        Attempt, a value of the exported Attempt Schema: { id, operation, key, input }, where id is
        a string minted by Flow, operation the descriptor id, key the canonical key record and input
        the parameters encoded with the transaction's input Schema (or, without one, with the shared
        structural codec of @plan.Inspection.O2; parameters the codec rejects fail admission with
        AttemptInputUnencodable before anything starts). In production the id is 128 bits from a
        cryptographic random source, unique across tabs and Runtimes; in Stories it is derived from
        the Story seed (and tab, @plan.Testing.O7). The adapter receives it as { attempt } and
        should send attempt.id as its idempotency key. A machine may keep an Attempt in memory
        (Schema.NullOr(Attempt)).

        basedOn. For a write registered in a domain with predictions, the adapter also receives
        basedOn: the version each predicted record was computed over (an API may send it as
        If-Match). For any other commit basedOn is an empty record.

        Concurrency per actor, per descriptor and canonical key (was FlowState D34). Lanes of other
        actors and other keys are independent; a domain write with predictions adds the
        cross-actor per-record queue of @plan.EntityDomains.O1 underneath.

        - **reject**: while an occurrence on the lane is unsettled, a new commit is declined: no
        occurrence, ordinal, attempt, optimistic write or adapter call, and no outcome; a
        commit.declined evidence record names it. The action batch otherwise proceeds.
        - **cancel**: the unsettled occurrence is cancelled (@O7 says what it reports), then the new
        one is admitted with a fresh ordinal and attempt.
        - **allow**: every commit starts at once as an independent occurrence with its own attempt
        and optimistic layers. Every occurrence delivers its own outcome, in settlement order.
        - **serialize**: occurrences queue first in, first out, at most 64 per lane. A queued
        occurrence starts (applies its optimistic writes, joins any record queue, invokes the
        adapter) when the previous one settles. A commit that would exceed 64 rejects the whole
        action batch before any work starts (CommitQueueFull, @plan.Machines.O3).

        Cancellation and fencing are registered before the adapter can run. Ordinals are
        one-based, monotonic per actor incarnation and never reused; admission reserves
        safe-integer headroom for settlement and cleanup, and exhaustion fails before admission
        (CapacityExhausted). Completion requires the actor incarnation, descriptor, key and ordinal
        to match; results of an older incarnation never reach a new one (@plan.Runtime.O3).

        Settlement. Every admitted occurrence settles exactly once, as success, failure, defect,
        interrupt or unknown. Its consequences publish in one store cut, before its outcome event:
        (1) its optimistic layers end as @O5 says for that ending, (2) on success its writes,
        validated as one batch, apply, (3) the cut publishes, (4) the outcome event enters the
        actor's mailbox as an internal event. A handler for Saved therefore always sees the cache
        already updated. An invalid writes batch applies nothing and publishes an issue; the
        occurrence still settles success. When the actor is disposing, consequences (1) to (3)
        still apply and the event is dropped with evidence.

        Honest remote uncertainty. Flow calls an occurrence invoked once it has called the adapter
        function; from then on the commit may have reached the server. unknown fires for an
        occurrence that was invoked and whose result Flow will never observe: cancelled after
        invocation (by the cancel policy or the cancel action), restored mid-flight, or abandoned
        by a bounded Runtime disposal. Flow never claims a remote rollback, never retries
        automatically and offers no compensation, outbox or saga API: compensation is another
        explicit commit. An unknown outcome is a normal internal event; authors should give it a
        state that offers the user a way out (retry, discard, refresh). flow check warns when a
        commit maps no unknown and the state waiting on it has no other exit (@plan.CommandLine.O5).

        Retry (decisions ruling 36). O.x.retry(select, { optimistic?, writes?, outcomes? }) is the
        commit action's sibling. select returns an Attempt. It re-issues exactly that attempt: the
        same decoded input and the same attempt.id, under the same concurrency and outcome rules.
        Flow never mints a new id for it. When this Runtime has already observed that attempt's
        final result (its adapter ran to completion after the occurrence was fenced, or a
        settlement was recorded durably before a restart), the retry settles at once with that
        outcome, applying its consequences, without invoking the adapter. An Attempt whose
        operation is not this descriptor, or whose input fails to decode, rejects the action batch
        (AttemptMismatch). A successful or failed retry ends the uncertainty of a domain record
        the attempt predicted (@plan.EntityDomains.O1).

        Attempt durability (decisions ruling 6). For an actor with persist true, Flow writes the
        Attempt (with the record keys a domain write predicts) to the KeyValueStore and waits for
        the store's acknowledgment before invoking the adapter; this write is never coalesced. A
        failed write settles the occurrence as defect with an AttemptNotRecorded issue, without
        invoking the adapter. A non-persisted actor has no durability: a crash loses its workflow
        and its attempts together. @plan.Persistence.O6 owns the record format.

        Restore (@plan.Persistence.O4). Hydration and restore never replay a commit. An occurrence
        whose attempt was recorded restores as unknown with its Attempt, delivered as the actor's
        first turn after activation, unless durable evidence shows it settled. A captured
        occurrence that was queued and never recorded settles interrupt at that first turn (the
        actor is still waiting for it), without invoking anything. Parameters are never rebuilt
        from a key.
        Reference (references/dispatch-desk): features/Tickets/editor/editor.machine.ts
        (commitDraft, SaveUncertain), features/Tickets/ticket.operations.ts (saveTitle reject,
        assignTicket serialize).
    O4  Streams
        A stream is an actor-owned session, not a store entry (was FlowState O5). Its identity is
        the activity's declaration slot, operation kind, descriptor and canonical key. Equal
        identity keeps the session and its original parameters; a changed identity releases the old
        session exactly once before the new one opens. Two actors subscribing with equal
        descriptor and key have independent sessions; there is no cross-actor deduplication.

        Within one actor, a second live activity whose session would have the same descriptor and
        key is rejected: it publishes a DuplicateStreamSession issue, its lane stays undefined, and
        the existing session is untouched. flow check reports the case as an error when the keys
        are statically equal.

        Emissions. Each emission becomes the lane's data (the latest value) and keeps the lane
        Running. Emissions create no finite occurrences and never write to the resource store; a
        stream changes cache data only through a domain listen entry (@plan.EntityDomains.O1).

        Flow pulls from the stream. When the declaration maps value, Flow pulls the next element
        only after the previous value event's turn has run, so at most one value event per session
        is waiting in the mailbox and a fast source is held back by the stream's own buffering
        (dropping or sliding is written in the stream program, for example Stream.buffer with a
        sliding strategy; Flow supplies no pressure option). When nothing maps value, emissions
        only update the lane: adjacent lane-only updates may coalesce into one publication, and a
        lane-only publication evaluates no transition, guard or action (@plan.Machines.O6). Slow
        readers may skip intermediate values; there is no history and no replay. value is silent
        for an emission equal by Equal.equals to the previous one (decisions ruling 12).

        Terminal facts. complete, failure, defect and adapter-side interrupt settle the session
        once, set the lane's tag and keep its data. A terminal session never restarts by itself; a
        new session opens only when the activity's identity changes or its state is entered again.
        Mapped outcomes: value(V), complete, failure (as in @O2), defect, interrupt.

        Planned release (state exit, key change, when false, actor disposal) is cleanup: it maps no
        outcome, never fires interrupt, aborts the signal, interrupts the stream fiber and runs its
        finalizers once. A cleanup defect publishes an issue and never rolls back a published
        transition. Before any emission or terminal fact is published Flow checks actor
        incarnation, slot, descriptor, key and session generation; facts of a released session
        are dropped.

        persist (opt-in, decisions ruling 15) keeps the latest value, encoded with result, for a
        persisted actor; it never persists a fiber, transport, buffer or history, and never makes
        an actor durable. On restore the lane shows the restored value; once the actor's pending
        outcomes have drained, an active declaration opens a new session from live parameters in a
        new generation (no replay). A restored terminal session does not reopen. Missing
        parameters fail closed with a diagnostic and invent nothing.
        Reference (references/dispatch-desk): features/Tickets/ticket.operations.ts
        (technicianUpdates, ticketEvents), features/Tickets/editor/editor.machine.ts (progress
        lane).
    O5  Writes and optimistic layers
        Write actions, all validated before anything publishes (@plan.Machines.O3):

        - **O.x.setData(select)**: select returns { key, data }, where data is a value or an
        updater (current) => A | undefined. The updater reads the confirmed base, never optimistic
        layers. Returning undefined declines: no write.
        - **O.x.invalidate(select)** and **O.x.clear(select)**: select returns a partial key record
        (@O1).

        Ordering rule for plain writes (decisions ruling 13, entity-domain.md section 5.5). A
        source replaces an entry's data when its request started at or after the position at which
        the stored data landed. A lookup starts when its adapter is invoked; a setData, whether
        from an action or a commit's writes, starts and lands when it is applied. So setData fences
        every lookup that started before it: such a lookup landing later is rejected for the data,
        though its occurrence still settles. An accepted write also clears the invalidated flag and
        the last failure and refreshes the landed time; an equal value refreshes freshness and
        fires no value outcome.

        Invalidate and clear batches. Every target in one action (or one writes list) is validated
        and expanded against one pre-mutation index of the store, in descriptor then key insertion
        order, deduplicated first-seen. More than 256 expanded identities, or any invalid target,
        rejects the whole batch before mutation (TargetBatchTooLarge, KeyInvalid). A target
        matching nothing is a successful no-op. There is no whole-Runtime target; disposal owns
        complete removal.

        - **invalidate** keeps data and optimistic layers and marks each entry stale. A matched
        entry with a live subscription and no generation in flight refetches once with its oldest
        binding's parameters, in canonical order; an unsubscribed entry is only marked stale and
        refetches when next bound or looked up. A generation in flight is not interrupted, but its
        result no longer makes the entry fresh unless it started after the invalidation.
        - **clear** removes data, metadata and optimistic layers and fences every generation in
        flight (interrupting it at once, since the cleared lifetime has no owner). Commits whose
        layers were removed still settle normally. Surviving subscriptions see the entry missing
        (lane Pending without data) and reacquire with a new generation.

        Each nonempty batch publishes one atomic store revision; no prefix of a batch is ever
        visible. On a domain operation, call-site optimistic, setData and clear are type errors
        and writes may contain only invalidate (@plan.EntityDomains.O1; was FlowState D37).

        Optimistic layers (was FlowState D36). Each optimistic setData of an occurrence becomes a
        layer on one entry, created when the occurrence starts (admission, or dequeue under
        serialize). The visible value of an entry is its confirmed base with its live layers
        replayed in start order, recomputed whenever the base changes, so two stacked updates stay
        stacked over any base and ending one leaves the other. Every reader of the entry (every
        actor's lanes, descriptor.get, checkpoints) sees the visible value; the lane's pending is
        true while any layer is live. Layers are never persisted, transferred or mirrored, and
        never feed a value outcome.

        How a layer ends, by its occurrence's ending:

        - **success**: the layer stays, still pending, until a confirming source lands on that
        entry: a setData (from these writes or later) or a lookup that started after settlement.
        Then it ends in the same publication. flow check warns on an optimistic write whose writes
        neither set nor invalidate that entry, since nothing would confirm it.
        - **failure or defect**: removed at settlement; the remaining layers replay over the base.
        - **interrupt, or cancelled before invocation**: removed.
        - **unknown**: the layer stays pending, and the entry is invalidated, so a subscribed entry
        refetches; the layer ends when that confirming lookup lands.
        - **clear or collection** of the entry: removed with it.

        A revert never overwrites newer data, because a layer never writes the base.
        Reference (references/dispatch-desk): features/Tickets/queue/queue.machine.ts (domain
        writes); minimal-library.md section 6 shows the plain form.
    O6  Activity lanes
        s.activities.<name> is the lane of the actor's own subscription (was FlowState D39). It is
        stored in the snapshot when the snapshot is published, never computed at read time, so a
        checkpoint shows its own moment, and it keeps its object identity until its entry or
        session changes. A lane is undefined while its activity is not running, while its when
        predicate is false, or while its parameters are null, undefined or false. Lanes are
        matched with Match.valueTags.

        Resource lane tags (decisions ruling 14):

        - **Pending**: no confirmed data yet and a generation in flight or about to start; data is
        the visible value if a layer or placeholder supplies one, else undefined
        - **Ready**: confirmed data, no generation in flight
        - **Refreshing**: confirmed data and a generation in flight; data is always present
        - **Failure**: the last generation failed with a typed error; carries error: E; keeps
        previous data if there was any
        - **Defect**: the last generation died; keeps previous data; the diagnostic is in issues
        (no defect value or Cause is stored, @plan.Diagnostics.O3)
        - **Interrupted**: the adapter was interrupted by something other than Flow's planned
        cleanup; keeps previous data

        Every resource lane carries data (A | undefined) and pending (true while an optimistic
        layer or a domain prediction on that entry is live, and while an unknown commit's layer
        awaits confirmation). A lane showing a placeholder also has placeholder: true. A domain
        read's lane adds stale (@plan.EntityDomains.O1).

        Stream lane tags: Running, Complete, Failure (with error), Defect, Interrupted. data is
        the latest value or undefined before the first emission; a stream lane has no pending. A V
        that admits undefined cannot be told apart from "no value yet"; authors wrap such values.

        placeholder: ({ previous, input }) => data | undefined, an activity option. When the key
        changes and the new entry has no data, it receives previous ({ input, data } from the last
        lane of this activity that had data) and the new input. While it shows, the lane is
        Pending with that data and placeholder: true. previous is kept per actor and activity name
        across exit and re-entry; it is never written to the store, persisted, transferred or
        mirrored.

        Paged lanes (was FlowState D54; decisions ruling 14). A domain read declared with .pagedBy
        has a paged lane: data is the loaded pages in order (each a result value) and hasMore says
        whether a next page exists. The machine loads the next page with the O.D.read.more(select)
        action. Paging semantics, including repair of the page chain, belong to
        @plan.EntityDomains.O1; plain resources have no paged mode.

        Passive reads. descriptor.get(s, keyInput) returns the entry's lane-shaped view (tag, data,
        pending, error) at the store revision the snapshot s was published with, or undefined when
        that revision holds no entry. For a stream descriptor, get reads the session that the
        actor whose snapshot s is owns for that key, or undefined; it never reads another actor's
        session. get inserts, holds, refreshes and starts nothing; an invalid key throws FlowError
        KeyInvalid. Domain.entry.get and Entity.get are owned by @plan.EntityDomains.O1.
        Transactions have no lanes and no readers: their outcomes become events.
        Reference (references/dispatch-desk): features/Tickets/queue/QueueList.tsx (lane tags,
        hasMore), features/Tickets/editor/TicketPanel.tsx (progress lane).
    O7  Cancellation and cleanup
        Flow distinguishes planned cleanup, which Flow performs because the owner no longer wants
        the work, from interruption the adapter reports itself. Planned cleanup never fires an
        interrupt outcome; adapter-side interruption fires interrupt.

        Planned cleanup aborts the adapter's signal, interrupts its fiber, runs its finalizers once
        (Effect Scope order), and records evidence. What each point reports:

        - **subscription released** (state exit, identity change, when false, actor disposal): no
        outcome; the binding is gone; the shared generation is interrupted only if this was its
        final owner (@O2)
        - **finite lookup, actor disposed**: no outcome; the generation continues while other
        owners remain
        - **stream session released**: no outcome (@O4)
        - **commit cancelled before invocation** (cancel policy, cancel action, queued under
        serialize, actor disposal): settles silently; its layers are removed; no adapter call
        - **commit cancelled after invocation** (cancel policy, cancel action): settles unknown
        with its Attempt; late results are fenced
        - **commit invoked when its actor is disposed**: disposal waits for it to settle; a
        bounded runtime.dispose() that gives up records it unknown (@plan.Runtime.O6)

        O.x.cancel(select) is a transaction-only action: it cancels this actor's unsettled
        occurrences on that key, queued and running. Resources have no cancel (decisions ruling 15;
        leaving the owning state or a newer request ends the work). On a predicting domain write,
        cancel is a flow check error (@plan.EntityDomains.O1).

        Cleanup failures. A finalizer or release that fails publishes an issue and never rolls
        back a published transition; during disposal it follows @plan.Runtime.O6 (dispose
        rejects and the ref is quarantined). Full Cause is kept until cleanup ends, with
        precedence defect, then failure, then interruption, and is never serialised
        (@plan.Diagnostics.O3).

        After cleanup, late results, emissions and finalizer facts may settle their own bounded
        evidence but can change no data, lane, outcome, replacement binding or later incarnation.
        Reference (references/dispatch-desk): features/Tickets/editor/editor.machine.ts (leaving
        OPEN releases the ticket and progress subscriptions).
decisions
    D1  Keys are named records with partial-record matching
        Was FlowState D30, kept from SurfaceSimplification D25 to D27. The archived tuple keys and
        tags go; the canonical byte grammar and its bounds stay exactly. undefined properties are
        absent rather than rejected, so optional filters need no special form.
    D2  One outcomes container; failures map by tag; members are optional
        Was FlowState D31 and D32. unknown is a member for commits; complete for streams. The 
        failure
        member is unavailable when E is never.
    D3  Flow mints attempt.id; unknown carries an Attempt; retry re-issues it
        Was FlowState D33, extended by decisions ruling 36. Reverses the archived Transactions O1
        "no public identity". Reconciliation reuses the id; Flow never mints a new one for it.
    D4  concurrency, staleTime and gcTime are required Duration and policy inputs
        Was FlowState D34. Zero and Duration.infinity are legal with the meanings of @O1.
    D5  Stream adapters return a Stream
        Was FlowState D35.
    D6  Commits own their consequences: writes and optimistic
        Was FlowState D36, from minimal-library decision 6. writes apply on success whatever state
        the actor is in, before the outcome event; optimistic layers are shared by every reader.
        Reverses the archived "no completion-side invalidate or clear" and actor-local previews.
    D7  Memory holds keys and drafts, never copies of cache data
        Was FlowState D29, with the flow check lint of @O2.
    D8  Activity lanes replace operation readers; tags are enumerated
        Was FlowState D39, with decisions ruling 14. Replaces key, getData, getState, cancel on
        readers, the Missing tag and transaction readers. The paged field is hasMore, so it does not
        clash with the .more action.
    D9  Transactions take no persist; streams keep opt-in persist
        Decisions ruling 15. A transaction's attempts follow its actor; a stream's latest value is
        persisted only when asked, because live data is usually meaningless after a reload.
    D10  A paged lane holds its pages
        Was FlowState D54. descriptor.get and Domain.entry.get return the same shape.
    D11  Invalidate refetches what is subscribed
        Decided here. The archived Resources O4 rule (invalidate starts no lookup) left an active
        list showing stale data until an unrelated trigger; minimal-library section 6 and entity
        domains (entity-domain.md section 5.3) both assume subscribed answers refetch. Unsubscribed
        entries are only marked stale, as before.
    D12  Plain writes follow the request-start ordering rule
        Decisions ruling 13. Replaces the archived compare-and-set with its conflict issue: a write
        lands at its application, so any lookup that started earlier cannot overwrite it, and a
        lookup that started later is newer server truth.
    D13  A successful optimistic layer waits for a confirming source
        Decided here, mirroring the entity confirmation rule (entity-domain.md section 5.5).
        Removing the layer at success would flicker back to the old value until a refetch; promoting
        it into the base would put unconfirmed data where value outcomes and persistence read.
    D14  Under allow every occurrence reports
        Decided here. The archived rule that only the newest generation drives outcomes would drop
        unknown and failure for earlier attempts, breaking "every wait has an exit".
    D15  A stream with mapped values is pulled one turn at a time
        Decided here, closing the archived silence on pressure. It keeps the mailbox bounded
        without dropping events Flow cannot judge; dropping belongs to the stream program.
    D16  Attempts of persisted actors are durable before invocation
        Decisions ruling 6. Replaces the archived adapter-owned journal (Transactions O4, D3) for
        persisted actors; adapters of non-persisted actors need none.
    D17  List metadata beyond records and cursor has no repair guarantee
        Decisions ruling 36. Domain repair guarantees cover declared records and their paging
        cursor, not arbitrary response metadata such as total or a server aggregate. flow check
        warns on extra list result metadata; authors declare totals as derived reads when they
        must repair with entity changes (@plan.EntityDomains.O1).
constraints
    C1  No readers, registries or escape hatches
        No resources.get, operation registry, enumeration, public occurrence handle, second cache,
        read-triggered subscription, retry, poll, seed or reset helper, whole-Runtime invalidate,
        custom key hash or equality, or cross-Runtime sharing. Nothing listed as deleted in
        FlowState D39 survives as an alias.
    C2  Honest remote uncertainty binds every implementation
        An invoked adapter counts as possibly dispatched. Nothing claims a rollback, retries
        automatically or invents a result (FlowState D7).
    C3  Executable work is never serialised
        Fibers, Scopes, adapters, queues, callbacks and stream transports are never persisted,
        transferred or mirrored, and no key is inverted into parameters.

questions
    Q1  Should writes also apply on failure?
        Today writes run only on success, so an invalidate after a failed save must be written in
        the failure handler, which runs only if the actor still handles that event. Recommended for
        version 1: keep success-only, and add an onFailure writes list only if the reference or an
        example needs it.
    Q2  Should a transaction without an input Schema be a type error when unknown is mapped?
        Today its Attempt encodes parameters with the structural codec and fails admission for
        non-plain parameters. Recommended: keep the codec fallback; parameters are plain data in
        practice, and the failure is loud and early.
    Q3  Is 64 the right serialize bound?
        It matches the before-attach send buffer of @plan.React.O2. Recommended: keep it fixed and
        private, measure in S4.
    Q4  Should focus and reconnect refetching be configurable per resource?
        TanStack Query offers refetchOnWindowFocus. Recommended: no option in version 1 (FlowState
        D4); a resource that must not refetch sets a long staleTime.
