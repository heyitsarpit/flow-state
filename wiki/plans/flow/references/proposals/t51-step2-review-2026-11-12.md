**Verdict: PASS with fixes.** The table is one total function and the rework meets most acceptance items, but two
fixes block close: a twice-refused unknown on a Held lane now throws and loses the call's ending (a regression,
reproduced), and `dispose()` waits on the store with no bound (Actors R23). Range `e25bb637..de68a161`; read-only
review, no gates re-run; one scratch probe run (below).

## Blocking findings

1. **Keep on a Held head throws, and the step's revert loses the ending.** `src/core/cells.ts:298`
   (`Keep.Held: impossible`), raised at `src/core/lane-moves.ts:46-49`. Path: an unknown is admitted
   (`Ended.OnWire` → Hold, lane Held), its mapper throws (`serve.ts:157-160`, `203-216`), the redelivery throws
   again, `keepEnding` (`lanes.ts:257-268`) meets Held. Probe (scratchpad `probe/keep.test.ts`, the lanes.test
   harness plus a machine whose unknown mapper throws): `Defect: the lane's table rules out Keep on Head`; the world
   reverts, so the lane stays `OnWire` with its call already settled, no `Ended` is reported, and the key is
   blocked for good (the next commit declines Rejected). This breaks WriteLanes R10 and I27 and Actors R15 ("a sent
   write's twice-refused ending stays parked on its lane"). Production at `e25bb637` kept it (`persist.ts` `keep`
   had no lane check). A8 assumed the cell unreachable; it needs only reject and an author mapper that throws.
   Fix: `Held: keepBeside`, with the probe as the failing case first; T18 still rules the cancel-policy side of Q5.
2. **`dispose()` waits for the edge flush with no bound.** `src/host/driver.ts:192`
   (`Deferred.await(disposed).pipe(Effect.andThen(edge.flush))`), `src/host/edge.ts:156-165`. Actors R23: disposal
   "waits for the final persistence write within the same 5 s; a write still pending reports StorageFailure". At
   T51's start dispose never waited, so a silent store now hangs `dispose()` forever. Fix: bound the flush by what
   is left of the disposal's 5 s with `Effect.timeout` and report StorageFailure past it, with a failing case (the
   Q2 tests boot with `captureMs: 0`, `lanes.test.ts:203`, so the flush is never exercised); or the user accepts it
   as a stated limit in revisit.md.
