# The turn walk, boundary channels and fragments: the core algorithm (2026-11-21)

**Bottom line:** every change to an actor is one value, `Change`, applied by one function, `apply`, in one fixed
row order. A turn's walk returns one `Turn`; creation, a refusal, a context or props update, a firing that did not
commit, a use returning and the actor's end are the other eight `Change`s, so none of them is a second applier. A
fragment instance has no writer of its own: one pure function, `reconcile`, compares the stored instances with the
ones the committed facts want and returns every start, end, freeze and thaw as data. It runs inside the turn until
nothing more ends, so no state is ever committed unsettled and no follow-up flag exists. The root is the instance at
the empty address, so one holder table and one stale check serve the actor, its fragments and every `.each` copy.
Of eight problem families, four are removed by a type and four are handled at one point each (section 3).

Everything here is **proposed**. It runs skill:to-design steps 1 to 4 and 6 for cluster 2 of
@proposal.algorithm-round and writes no Spec. It builds on @proposal.algo-schedules, whose nine questions the user
answered as recommended. Thirteen questions for the user are in section 15: every departure from
@proposal.spec-turn-parts, @proposal.spec-boundary-channels, @proposal.spec-fragments, @proposal.algo-schedules, a
Plan or an accepted answer is one of them, or is listed after them as an implementation call. An executable model
of the tables was run on the first draft only; what is unfinished is listed as open holes in section 18.

Conventions: code paths are under `packages/flow-state-v3/` (`src/core/` unless they start with `src/`, `tests/` or
`fixtures/`). TP, BC and FR are the three concept proposals above; AS is @proposal.algo-schedules; AR is
@review.algorithm-review; R2 is @review.spec-cohesion-r2; CS is @review.case-studies; CX is
@review.complexity-sweep; CA is @review.code-audit. Every keyword in a code block is marked existing, CHANGED,
RENAMED, NEW or user-defined. Pseudo-code is conceptual.

## 1. Walkthrough: uploads, a frozen outline, and an emit

An editor holds a list of attachments. Each attachment is one copy of an `Upload` trait. An `Outline` trait lives
while the editor is in `EDITING` and is frozen, not dropped, in `PREVIEW`.

```ts
// existing in the Plan, unbuilt: trait, .each, .resumable, Flow.state, Flow.Callback, raise, notify, emit,
//   whenAbandoned, onEmit            existing: definition, machine, Flow.input, Flow.initial, O.x.commit, O.x.cancel
// user-defined: Upload, Outline, Editor, Attach, CancelAll, Preview, Back, Cancel, Done, onGone, send, autosave,
//   attachments, gone, uploads, outline, EDITING, PREVIEW
const Upload = trait(
  { id: "Upload", events: { Cancel: {} }, emits: { Done: { ref: Schema.String } },
    callbacks: { onGone: Flow.Callback({ ref: Schema.String }) },
    memory: { ref: Flow.input(Schema.String) }, operations: { send: SendFile } },
  ({ callbacks, emits, O }) => ({
    on: { Cancel: { emit: [emits.Done.from(({ memory }) => ({ ref: memory.ref }))],
                    notify: [callbacks.onGone.from(({ memory }) => ({ ref: memory.ref }))] } },
    whenAbandoned: [O.send.cancel],                       // a release: no callback
  }),
);
const Editor = definition({
  id: "Desk/Editor",
  states: { EDITING: Flow.state({ traits: { outline: Outline.resumable() } }), PREVIEW: {} },
  events: { Attach: { ref: Schema.String }, CancelAll: {}, Preview: {}, Back: {} },
  memory: { attachments: Flow.initial(Schema.Array(Schema.Struct({ ref: Schema.String })), []),
            gone: Flow.initial(Schema.Array(Schema.String), []) },
  traits: { uploads: Upload.each({ of: "attachments", by: "ref", max: 10 }) },
});
export const EditorMachine = machine(Editor, ({ S, E }) => ({
  default: S.EDITING,
  on: { Attach: { updateMemory: ({ event, memory }) => ({ attachments: [...memory.attachments, event] }) },
        CancelAll: { raise: [E.uploads.Cancel] } },
  states: { EDITING: { on: { Preview: S.PREVIEW } }, PREVIEW: { on: { Back: S.EDITING } } },
  traits: { uploads: { onGone: { updateMemory: ({ event, memory }) => ({
    attachments: memory.attachments.filter((a) => a.ref !== event.ref), gone: [...memory.gone, event.ref] }) } } },
}));
editor.onEmit({ uploads: { Done: ({ ref }, { key }) => rows.get(key)?.blur() } });
```

What the core does, with copies `r2`, `r1` in list order:

1. **`Attach r3`.** One turn with one part. Its patch changes `attachments`, so `reconcile` runs right after it:
   stored has no `uploads[r3]`, the list wants it, the step is `Start`. The applier mints its id, seeds its memory
   from the item, starts its schedules as a creation and publishes once.
2. **`CancelAll`.** The source raises `Cancel` into `uploads`: one part per live copy, in list order. Each copy's
   part emits `Done` and notifies `onGone`; the host's filling runs once per notify. It is the same alternative at
   the same address each time, so its patches fold: the second run reads the list the first one left. After the
   walk `reconcile` finds no key left in `attachments`: three `End(KeyGone)` steps, inside this turn. `whenAbandoned`
   lists only a release, so each copy's `send` lane is cancelled and no further part runs. The `Turn` holds seven
   parts, three emits and three ends, and publishes once: the published instances are exactly the ones the published
   list wants.
3. **The emits.** They are fields of the `Turn`, so nothing else records them. When the step ends, the host calls
   the `uploads.Done` handler three times with each copy's key, after its world is set; a handler that throws is
   reported and stays.
4. **`Preview`.** The move leaves `EDITING`. `outline` is resumable, so the step is `Freeze`, not `End`: its memory
   and timers stay as they are, its alarms are cleared, and its slice stays in the snapshot. No `whenAbandoned` runs.
5. **An autosave write of the outline ends while it is frozen.** The owed row's audience is the subject `outline`,
   whose instance is not live: the row waits. Nothing is dropped and nothing is heard.
6. **`Back`.** `EDITING` has a new activation; a resumable trait's anchor ignores it, so the step is `Thaw`: the
   same instance, the same id. Its schedules hear `Wake` and then `Context`, an overdue `autosave` fires once, and
   the parked row is queued behind the turn.

Every step is a row of the tables in section 6, and the incarnation is written only by `apply`.

Stated before any table, from @plan.Machines.O1 to O3, O7 and O8, @plan.React.O2 and O3, TP, BC, FR and CS. Each
invariant of section 8 traces to one.

| Id  | Property                                                                                                                                                                                                                                                                   |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1  | One event, one result: an accepted event with everything it raises, notifies, exits, starts and ends shows as exactly one publication; a refused, denied or unhandled one changes no state, memory, instance or emit, and a refusal shows as one issue                     |

### 4.2 Callback inputs

Every input of every user callback, and how a change in it reaches the callback. One function builds them all:
`readsOf(incarnation, scope, view)`; `check(s, event)` builds the same record from a snapshot. Today six sites build
their own literal (`turn.ts:431-436, 460, 480-481, 591-596`, `context.ts:289`, `schedules.ts:84-92`), which is how
a reader comes to miss an input. `memory` is the memory of the callback's own scope; `key` and `item` exist only
under `.each`; fragments read no context (@plan.Machines.O1).

| Callback                                            | Inputs                                                   | View                    | A change reaches it by                                    |
| --------------------------------------------------- | -------------------------------------------------------- | ----------------------- | --------------------------------------------------------- |
| a guard, and a key select inside a guard            | state, memory, props, context, event, lanes; no time     | before, folded (6.2)    | read on each turn it is tried in                          |
| `updateMemory`                                      | memory, props, context, event, now, lanes                | before, folded          | read on its turn                                          |
| payload mappers: raise, notify, exit, emit          | memory, props, context, event                            | before, folded          | read on their turn                                        |
| action selects, member keys, a send's ref and event | memory, props, context, event, now                       | after                   | read once, at row 7 of the turn                           |
| `resetOn`, an `.each` list, an input filler         | memory of the host scope; `key` and `item` under `.each` | the memory so far (6.4) | every `reconcile` of a turn whose host memory changed     |
| a schedule's delay; `keys`; reasons; `restartOn`    | AS 4.2, with the scope's memory, props, `key`, `item`    | committed               | AS 4.2; row C5 passes a scope whose inputs changed (6.12) |
| a context slot's select                             | its provider's reads                                     | committed               | a wave, then the consumer's context update                |
| `C.slot.change` and `P.prop.change`: `when`, mapper | the value now and before; memory, props                  | committed               | the `Inputs` change that carries the new value            |
| an ending's mapper; a schedule's send mapper        | the ending's value with `{ input, key }`; firing data    | none                    | not applicable                                            |
| an emit's handler (host)                            | the payload, `{ key, keys }`                             | the world at step end   | once per emit, per listener, after its turn               |

- Lanes in a before view are the pre-turn lanes with the turn's own ending admitted; in a committed view they
  carry the turn's members (@plan.Machines.O3, unchanged).
- `resetOn` reads memory only, never props or context (question 9). So the instances are a function of the state
  and the scopes' memories, and only a `Begin`, a `Turn` or an `End` can change them.

### 4.3 Representation types

Target: TypeScript with Effect data types (`Data.TaggedEnum`, `Brand`, `Option`, `Result`). Each lifecycle is a
tagged union; no `Option` or flag stands for a status.

```ts
// existing: ActorId, ActivationId, IncarnationId, Values, Move, Part, Resolved, Trigger, Owed, Failure, IssueSource
// NEW: SlotName, KeyText (AS), AddressKey, SubjectKey, Segment, Address, Anchor, Status, Instance, Instances,
//      Applied, Site, PartCause, Emit, PartRun, EndCause, InstanceStep, ScopeWork, Turn, Change, Why, Where

  readonly emits: ReadonlyArray<Emit>; readonly actions: ReadonlyArray<Resolved>;

  Start: { address: Address; reset: Option.Option<KeyText> };   // its place is its slot's node, resolved by apply

type OwnedBy = Data.TaggedEnum<{ Root: {}; Scope: { id: ActivationId } }>;          // RENAMED: State -> Scope
type Audience = Data.TaggedEnum<{ Subject: { subject: SubjectKey };                 // RENAMED from Identity
                                  Life: { incarnation: IncarnationId; scope: ActivationId } }>;   // CHANGED
type Where = Data.TaggedEnum<{ State: { depth: number }; Instance: { instance: Instance }; Gone: {} }>;
```

- **Unwritable:** an incarnation built outside `apply.ts`; an instance added, removed or re-statused outside it; an
  emit in any record but the turn's; an `unsettled` or pending-reset flag; a `why` that disagrees with its change;
  an id inside a `Turn`; a frozen instance with parked mail of its own (parked endings are owed rows); a grace timer
  id inside an incarnation.
- **Still writable, guarded by one writer and an invariant:** an instance whose host is absent (I2); two context
  updates in one mailbox (I7).
- **Two ids became one.** R2 section 4 gave an instance a seeded `InstanceId`. An instance's scope already needs an
  activation id for AS's `Schedules`, and a lane owner already names an activation. One id serves both. Activation,
  arming and instance ids are counters that restart at a boot; none is saved, and the host names an instance's work
  by `(IncarnationId, ActivationId)`, whose first half carries the boot seed (question 6).
- **A frozen instance has no place.** Only a resumable node trait freezes of itself; its descendants are traits and
  copies, which sit on no node (a trait has no states; a subroutine's states are in the one tree). So `place` is
  `some` only while a node trait or a slice is `Live`, and nothing saved needs it.

## 5. Operations


- `runTurn` and `reconcile` are pure and mint nothing. `apply` is the only function that mints activations and
  instance ids, as `serve.ts:271` is the only one today.
- `reconcile` fails only when `resetOn`, an input filler or a list read throws: the slot that threw. In a turn
  that is row W7; under `Begin` the throw reads as the slot's last value (the saved reset value, or absent), and
  the failure is that slot's outcome until its `resetOn` next reads clean.
- No other operation fails: a callback that throws is a `Refused` turn, a `Failed` check (AS) or a failure inside
  `Inputs`. A defect leaves the world as it was, because `apply` writes the incarnation in one `put`.
- `apply` takes `before: none` exactly for `Begin`. No other function takes or returns an `Incarnation` it built.

## 6. Rules: the tables

### 6.1 The walk

**Owner: `walk`, called by `runTurn`.** It keeps one accumulator: the parts, the changer's site, the keys written
per scope with the site that wrote each, and the instances the turn has ended. Every row starts from `Walking`;
"refused" means `Refused(InvalidTurn, slot)` unless a code is given.

| Row | A part arrives that                                                                     | Next                                                                |
| --- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| W1  | has no target                                                                           | `Walking`                                                           |
| W2  | has a target, and no changer is set or its own site is the changer                      | `Walking`, its site is the changer                                  |
| W3  | has a target, and another site is the changer                                           | refused: one state changer                                          |
| W4  | writes a key of its scope that another site wrote                                       | refused: one site per key                                           |
| W5  | writes a key its own site wrote earlier in this turn                                    | `Walking`: the write folds (6.2)                                    |
| W6  | is at a site already on its own path from the part that began its walk                  | refused: a walk must end                                            |
| W7  | has a guard, mapper, patch, `resetOn`, input filler or list read that throws            | `Refused(GuardDefect or Defect, slot)`                              |
| W8  | has a payload its codec refuses, or a patch naming a field it may not write             | refused                                                             |
| W9  | raises into a plain slot with no `Live` instance, with no handler or with only declines | refused                                                             |
| W10 | raises into an `.each` slot                                                             | one part per `Live` copy, in list order, by the three rows below    |
|     | a copy with a handler that accepts                                                      | its part joins                                                      |
|     | a copy with no handler on its path                                                      | skipped; its address goes to `Turn.skipped` (`Unhandled` evidence)  |
|     | a copy whose alternatives all decline                                                   | refused                                                             |
| W11 | notifies a callback                                                                     | the host's filling joins; an optional, unfilled callback is ignored |
| W12 | takes an exit                                                                           | the host's exit filling joins and is the changer (W2, W3)           |
| W13 | anything, once `Refused`                                                                | `Refused`, unchanged: the first refusal stands                      |

- Within one part: its patch, its emits, its raises in written order (each child part and everything it reaches,
  depth first), its notifies, its exit (TP PD2, adopted). Parts are recorded in that order.
- An `.each` raise with no `Live` copy is recorded and does nothing, and a `Frozen` copy is not reached. A plain
  slot that is frozen or absent is row W9.
- A raised event selects in the child's scope as the source does, the implicit "self" included. `armOn` and
  `disarmOn` match each part's own event in that part's scope (TP PD4, adopted; AS assumed it): that is
  `Turn.work`.
- The source is selected in the scope the trigger is for, `TurnInput.at`. A trait's scope has one level; the root's
  scope has today's route from the leaf up, subroutine states included.
- W6 is the bound: a path holds each site once, so it is no longer than the sites that exist, and a part's
  children are its written raises, notifies and exit over the copies that are live. Siblings may share a site:
  that is a fan-in, and it folds.

### 6.2 Two memory views, and the fold

Every guard, patch and payload mapper of a part reads the **before** view of its own scope: the pre-turn memory, or
a started instance's initial memory. Row 7 and everything after commit read the **after** view.

**The write rule.** A site is one alternative at one address. For each key of a scope:

| The key was written this turn by | A site writes it                                              |
| -------------------------------- | ------------------------------------------------------------- |
| no one                           | accepted; the site owns the key                               |
| the same site                    | accepted, in walk order; its before view shows its own writes |
| another site                     | the turn is refused (W4)                                      |

So a site reached again, by a second copy's notify or by a raise written twice, reads the memory its earlier runs
left, in the keys it owns, and the pre-turn memory in every other key. The after memory is the before memory with
every patch applied in walk order; since one site owns each key, that order is the site's own. The changer follows
the same rule (W2, W3): a target is fixed per alternative, so one site reached twice names one move. This replaces
TP's row W4 and the Plan's "disjoint memory keys" (question 2): under those, a list cleared with two copies in it
is refused whenever each copy's leaving patches one host field (9.4).

Two different sites still may not write one key. A source that patches a list, with a filling that patches the
same list, is refused every time it runs: a shape, not a matter of counts, and a `flow check` finding.

### 6.3 Instances: wanted against stored

**Owner: `reconcile`.** It is pure. `apply` turns its steps into the next `Instances`; nothing else adds, removes
or re-statuses an instance.

Wanted is derived top-down, hosts before their children, from `Facts`:

| Slot kind                | Wanted `Live` while                                      | Wanted `Frozen` while                    | Anchor compared               |
| ------------------------ | -------------------------------------------------------- | ---------------------------------------- | ----------------------------- |
| root trait               | its reset value is present                               | never                                    | reset                         |
| node trait               | its node is on the chain and its reset value is present  | never                                    | the node's activation, reset  |
| resumable node trait     | its node is on the chain and its reset value is present  | its node is off the chain, reset present | reset                         |
| subroutine slice         | its state is on the chain and its reset value is present | never                                    | the state's activation, reset |
| a fragment's child trait | its host is `Live` and its reset value is present        | never of itself                          | reset                         |
| `.each` copy             | its slot's row holds and its key is in the repaired list | as its slot's row                        | its slot's row                |

- A slot with no `resetOn` always has a present reset value. A reset value is a key: a string or a number, compared
  by its canonical text; null or undefined is absent (question 4).
- The repaired list: the host field's entries by `by`, a repeated key keeping its first position, keys past `max`
  dropped. Each drop is a `Repair` (`listRepair` evidence, written by `apply`); a repair never refuses (question
  12). A key dropped past `max` becomes a copy when an earlier key leaves.
- List order is the host list's order (FR PD2, adopted). **Address order** is hosts before children, slots in
  declaration order, copies in list order; a copy whose key left the list keeps the position it had. Starts and
  thaws are emitted in address order; ends children first, siblings forward.
- `reconcile` does not look below a `Frozen` instance: its descendants were frozen with it and stay as they are.

The one table. `a` and `b` are anchors; they are equal when every compared component is.

| Stored \ wanted | Absent       | `Live(b)`                                   | `Frozen(b)`                                        |
| --------------- | ------------ | ------------------------------------------- | -------------------------------------------------- |
| absent          | nothing      | `Start`                                     | nothing: a frozen instance is only ever a kept one |
| `Live(a)`       | `End(cause)` | `a = b`: keep; else `End(cause)`, `Start`   | `a = b`: `Freeze`; else `End(Reset)`               |
| `Frozen(a)`     | `End(cause)` | `a = b`: `Thaw`; else `End(Reset)`, `Start` | `a = b`: keep; else `End(Reset)`                   |

- `End`'s cause is the first that applies: `ActorEnded` (the actor ends), `Dropped` (the definition no longer
  declares the slot), `HostEnded` (its host ends in this reconcile), `Exit` (it is `Facts.exited`), `Left` (its
  node or state left the chain, or was entered again), `KeyGone`, `Reset` (the reset value changed or went absent).
- `End` and `Freeze` take the whole subtree: a host's `End` gives each descendant `End(HostEnded)` first; a
  `Freeze` freezes each descendant. A `Thaw` thaws the instance and then its descendants, in address order, in the
  same reconcile; their anchors have no place, so they compare equal.
- A `Thaw` keeps the instance's id and memory. A `Start` after an `End` is another instance: a new id, fresh
  memory. A resumable trait reset while frozen ends there; a new one starts when its node is next entered.
- A "keep" under `Begin` from a record is the same cell: the saved instance stays, with a new id; a saved node
  trait or slice takes the restored activation of its node as its place, so it compares equal (P5).

What an `End` runs, by cause:

| Cause                      | `whenAbandoned` callbacks, as parts             | `whenAbandoned` releases                |
| -------------------------- | ----------------------------------------------- | --------------------------------------- |
| `Exit`                     | no                                              | no                                      |
| `Left`, `KeyGone`, `Reset` | yes, inside a turn                              | yes                                     |
| `HostEnded`                | no: its host, where the filling lives, ends too | yes                                     |
| `ActorEnded`               | no: no turn runs                                | yes                                     |
| `Dropped`                  | no                                              | no: its lanes are cluster 3's `Retired` |

**Callbacks run only inside a turn, and only into a host that stays.** A reconcile under `Begin` or `End` appends
no part, whatever the cause. An instance that is frozen when it is abandoned is told like a live one: the callback's
mapper reads its memory, and the filling runs in its host. This is FR PD3 for every case outside a turn, it
settles FR-1, and it narrows the Plan's "ends other than by its own exit or a freeze" by the host's own end
(question 5).

### 6.4 Reconcile inside the turn

`reconcile` runs at two points of a turn, with the same table and the facts as they stand:

| Point                        | Facts                                                                  | Steps applied                                     |
| ---------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------- |
| R0, after the source's patch | the pre-turn chain; the memory with the source's patch                 | every `End` and every `Start`                     |
| rounds, after the walk       | the chain after the changer's move; the memory with every patch so far | every `End`, each round; then, once stable, every |
|                              |                                                                        | `Start`, `Freeze` and `Thaw`                      |

- **R0** decides which instances the source's raises reach: a copy its patch added is reached, a copy its patch
  removed is not, and a trait its patch reset is the new one (question 3). A started instance's before view is its
  initial memory. Only R0 and the rounds change who is live: a copy whose key a notify removed in mid-walk is still
  reached by a raise already under way.
- **After the walk,** the `Abandoned` parts owed by R0's ends are visited first, in step order, each with
  everything it notifies. Then a round: `reconcile`; for each new `End` whose cause runs callbacks, its `Abandoned`
  parts. If their patches or the changer's move changed the facts, another round follows.
- **An ended instance's memory stays readable** to its own `whenAbandoned` mappers until the turn returns.
- **It ends.** After the walk every `reconcile` but the last ends at least one instance, and none starts one, so
  there are at most as many as the instances live after R0, plus one. A key that returns to a list after its copy
  ended is a `Start` of a new instance in the stable round.
- **Nothing is left for later.** `Turn.steps` holds every step in the order applied: R0's, each round's ends, then
  the stable ones. So the published instances equal the wanted ones in every publication; `Incarnation` has no
  pending flag; the Plan's follow-up turn for a pending reset does not exist; and TP's row 12 is gone (question 1).

the root alone.

### 6.7 Occasions that do not compare

Four kinds of comparison exist in this cluster: a props patch against the props (6.9), a context slot against a
reaction's baseline, a reset value or a list against the stored instances (6.3), and AS's `restartOn`. Three
occasions compare nothing themselves: a restore, a thaw, and a use returning.

**One rule:** such an occasion leaves every saved baseline and anchor as it is, and the comparing step for each
kind it could have skipped runs right after it, in the same `apply`, without a condition:

| Kind              | After a restore                              | After a thaw                                  | After a use returning       |
| ----------------- | -------------------------------------------- | --------------------------------------------- | --------------------------- |
| instances         | `reconcile` against the record, no callbacks | the thaw is itself a step of a `reconcile`    | none: a use changes no fact |
| schedules         | AS's `Wake`, then `Context`, per scope       | `Wake`, then `Context`, for the thawed scopes | `Wake`, then `Context`      |
| context reactions | the owed context update (`owes`), by row C7  | none: a fragment reads no context             | none: slots kept reading    |
| props reactions   | none: props are never saved                  | none: a fragment declares no `onProps`        | none                        |

Each step changes nothing when nothing changed, so it needs no "differs from what the scope last heard" test and
no stored copy of what was heard. AS 6.7 raises `Context` after a `Wake` only when context or props differ; this
drops the test and keeps the result (question 13).

### 6.10 Emits

- An emit is a field of a `PartRun` and nothing else. The turn's record is `{ actor, from, to, turn, members }`,
  as an act and as evidence; the public `Emit` evidence is projected from it in `evidence-of.ts`, one record per
  emit in walk order, after the turn's `Published` (M1, TP PD1).
- An emit's payload is checked by its codec in the walk; a refusal refuses the turn (W8). A refused turn has no
  `Turn`, so nothing of it is delivered.
- Entry, exit, a `Begin`, an `Inputs` change and an `End` have no part, so they emit nothing. An instance that
  ends in the turn still emits: the emit holds its address by value.
- `src/host/emits.ts` owns the listener sets and is called once per step, after the driver set its world, with
  `turnsOf(batch)` (M4). Each call is to sit in its own `Result.try`: a throw is one host report, the listener
  stays and the next one runs (BC PD6, BC-3). The inspector sink at `driver.ts:358` is unguarded today and is to
  get the same guard.
- Emits are in the `Turn` before the turn's sends are served, and listeners run at the step's end: both halves of
  M3.

### 6.11 The actor's end, and the order of ends

An end is the `End` change of a live incarnation. It drops the incarnation; what it does to the saved actor record
and to mail differs by `how`. A later `ensure` of the identity is a `Begin`, from the record when one was kept.

| `how`             | Precondition                              | The actor record | Subject-held rows              | Mail                  | `Finished`             |
| ----------------- | ----------------------------------------- | ---------------- | ------------------------------ | --------------------- | ---------------------- |
| `Grace`           | free: unused, no lane in flight, no mail; | kept             | wait                           | none: it was free     | now                    |
|                   | the record encodes                        |                  |                                |                       |                        |
| `Disposed`        | none                                      | removed          | wait, for an adopting `ensure` | dropped               | now                    |
| `Forgotten`       | none                                      | removed          | closed, as evidence or let go  | dropped               | now                    |
| `RuntimeDisposed` | the Runtime is `Open`                     | saved            | wait                           | every mailbox cleared | when the disposal ends |

The order of ends is one function, `endOrder(world)`:

| Level              | Order                                                                                     |
| ------------------ | ----------------------------------------------------------------------------------------- |
| identities         | each after every live consumer bound to it; the oldest ready one first (`consumersFirst`) |
| inside an identity | instances children first, siblings in address order; the root last                        |
| after them         | entries and sessions (cluster 4), then the tab lock (cluster 5)                           |

`EndWork.owners` is that list, so a runtime disposal ends instances (FR-6) by the same rows as an actor's end.

### 6.12 What each scope's schedules hear

A scope is a state's activation or an instance. AS's `Schedules` map is keyed by the scope's id, and `decide` sees
no scope. Row C5 is the one caller of AS's `pass`, once per scope; the order of a restart and the arming it feeds
is inside `decide` (AS's table order), so the owner adds none.

| Scope event, in a change                                 | The owner does                                         | Occasion                        |
| -------------------------------------------------------- | ------------------------------------------------------ | ------------------------------- |
| a state entered; `Begin` from input                      | `before` is none; a turn's own arm is `Given`          | `Turn`                          |
| an instance's `Start`                                    | `before` is none; nothing is `Given`                   | `Turn`                          |
| a state exited; an instance's `End`; the actor's `End`   | drops the scope's entry, releases its armings          | none                            |
| a `Turn` that touched the scope's inputs, or named it in | passes `disarmed`, `started` and `fired`               | `Turn`                          |
| `Turn.work`                                              |                                                        |                                 |
| `Inputs`: props changed                                  | every awake scope                                      | `Context`                       |
| `Inputs`: context changed                                | every awake state scope of the root                    | `Context`                       |
| `Lanes`                                                  | the subject's scope, and its state scopes              | `Lanes`                         |
| `Settled`                                                | the firing's scope                                     | `Settled`; `Lanes` for the rest |
| `Freeze`; the last use released                          | clears the alarms of each scope that fell asleep; no   | none                            |
|                                                          | timer changes                                          |                                 |
| `Thaw`; `Begin` from a record; the first use returning   | for each scope that woke: sets alarms, then fires each | `Wake`, then `Context`          |
|                                                          | overdue timer once                                     |                                 |

- **An instance's start is a creation.** Its entry arms are decided after commit; a bad delay is AS's `Refused`
  with an issue and never refuses the host's turn. A state's entry and `armOn` keep the rule of AS question 5
  (question 8 here).
- **A scope's inputs** are its memory record, its `item`, the props, the context values (root scopes) and its
  lanes. Row C5 passes a scope only when one of them changed by identity, the change names it, it began or woke,
  or it holds a `Refused` timer (which AS retries on every occasion). `keys`, the reasons and `restartOn` are
  functions of those inputs and not of the clock, so a skipped pass would have changed nothing. This is AS's input
  gate, taken per scope: with a thousand copies, a root turn that changes one of them passes one scope.
- **The scope order** AS asked for: state scopes outermost first, then instance scopes in address order.
- **Schedule names** are scoped: the map is by scope id, then name, so a name need only be unique in its
  fragment. Evidence and issues name a timer by address and name.
- **Asleep** is not a status: a scope is awake when its actor is used and every instance on its address is `Live`.
  A hidden page and a hydration reach the core as a use change and a `Begin` from a record (cluster 5).
- **A trait that pauses its host's schedules** (the catalog's `RateLimit`) needs no new channel: its handler
  notifies a callback, the host's filling patches a host field in the same turn, and the host's reason reads that
  field in row C5.
- **A zero delay cannot wedge a step:** `tick` takes the alarms due at its start, once. A timer armed during the
  step waits for the next tick, which the host sends after a yield. The loop guard does not count firings, so an
  endless zero-delay series is not bounded: it yields to the host at every tick, as a zero interval does anywhere.

## 7. Algorithm

Conceptual pseudo-code. Three things the tables do not say: the source's guards run before any part; `apply` reads
the incarnation again after C3, because flushing lanes may move them; a `Refused` found in C1 restarts `apply` with
the `Refused` change and nothing of the turn written.

```ts
serve(mail):                                       // serve.ts; one item, then its actor's front mail
  Event(actor, at, tag)   -> the instance at `at` is Live ? turn(Trigger.Event, at) : Unhandled
  Firing(scope, arming)   -> locate(scope) is Live and the arming is live and due
                               ? turn(Trigger.Firing { fired }, scope's address) : drop      // AS's fire
  Ending(row)             -> its audience is Live ? tryOne(row, hear) : it waits             // 6.5
  Context | Props         -> change = inputsOf(incarnation, ...); if some: apply(change)
turn(trigger, at):
  result = runTurn({ ...readsOf(incarnation, at, "before"), instances, at, trigger })
  Accepted(turn) -> apply(Change.Turn { turn, trigger })
  Refused(f)     -> trigger is a firing ? apply(Change.Settled { fired, refusal: f })
                                        : apply(Change.Refused { source, failure: f, ending })
  Denied | Unhandled -> evidence; an ending: apply(Change.Unturned { row }); a firing: apply(Change.Settled)

runTurn(input):                                    // pure; tables 6.1, 6.2, 6.4
  source = select(input.at, input.tag)             // today's route and guards; none -> Denied or Unhandled
  acc = { parts: [], changer: none, written: Map<scope, Map<key, Site>>, memory: before, live: input.instances,
          steps: [], owed: [] }                    // owed: ends whose Abandoned parts are still to run
  visit(acc, source, Source, input.event, path = [])
  settle(acc, facts(the pre-turn chain, acc.memory), starts = true)                          // R0
  walkOut(acc, parts[0], path = [source's site])   // its raises, notifies and exit, depth first
  loop:                                            // after the walk
    for end in acc.owed, in step order: for callback in its whenAbandoned:
        part = visit(acc, the host's filling, Abandoned { of: end.address }, payload, path = [])
        walkOut(acc, part, path = [its site])
    acc.owed = []
    settle(acc, facts(the chain after acc.changer, acc.memory), starts = false)              // a round
    if it ended nothing: break
  append the Start, Freeze and Thaw of that last, stable reconcile to acc.steps
  refuse if acc is Refused                         // W13
  after = acc.memory; resolve each part's actions, sends and its scope's arms and disarms on `after`   // row 7
  return Accepted({ parts, move: moveOf(acc.changer), steps: acc.steps, memory, memories, work, repairs, skipped })
settle(acc, facts, starts):                        // one reconcile, applied to the working view
  r = reconcile(acc.live, facts)                   // a throw is W7
  for each End in r.steps: remove it from acc.live, keeping its memory readable; append it to acc.steps;
                           if its cause is Left, KeyGone or Reset: append it to acc.owed
  if starts: for each Start in r.steps: add it to acc.live with its initial memory; append it to acc.steps
visit(acc, site, cause, event, path):              // one part
  W6: site is in path -> refuse
  view = readsOf(before) overlaid with the keys acc.written says `site` owns
  patch = site.update(view); W4, W5, W8; acc.memory[scope] = merge
  if site.target: W2, W3
  emits = site.emits.map(payload(view)); W8
  push PartRun
walkOut(acc, part, path):                          // W9 to W12; children get path + [their site]
  for raise in part.raises: for target in liveTargets(acc.live, raise.slot):
      child = select(target, raise.event); visit(acc, child, Raise { from }, ...); walkOut(acc, child, ...)
  for notify in part.notifies: filling = the host's filling; visit(acc, filling, Notify { from }, ...); walkOut(...)
  if part.exit: filling = the host's exit filling; visit(acc, filling, Exit { from }, ...); walkOut(...)

apply(tx, before, change):                         // apply.ts; rows C1 to C7 of 6.6
  C1 if change is Turn and its sends would pass the loop guard: return apply(tx, before, Refused(...))
  C2 next = the Applied incarnation: mint an activation per entered state and an id per Start; give each Live
            node trait and slice its node's activation as its place; tx.putIncarnation(next)   // one put
  C3 for part in turn.parts: for member in part.actions: lanes.apply(member, owner = scope of part)
     insert the turn's record before the members' reports; flush lanes
  C4 for step in the change's steps, in order: the holder table (6.5)
  C5 for each scope by 6.12: schedules.pass(scope, occasion); drop ended scopes; sync alarms
  C6 if whyOf(change) is some and (the change publishes always or next differs from before): act(Published)
  C7 the change's mail, by its column

tick(tx):                                          // step.ts; replaces `fired`
  due = alarms.takeDue(env.now)                    // O(log W) each; sorted once by AS's due order
  for alarm in due: Schedule -> enqueue Mail.Firing; Grace -> apply(End Grace); Bound; Silent   // as today
  command(Wake { at: alarms.next() })              // one host wake
```

`reconcile` is the wanted table, then the status table, per address in address order; it visits only the slots
section 11 names. `runTurn` writes nothing, and `apply` installs the incarnation in one put, so a defect leaves
the actor as it was.

## 11. Cost and the index layer

By reading, not measured; the bench decides. No bench covers fragments or a fan-out; the build adds
`turn.fragments.none`, `.copies-100`, `.fanout-100`, a wave to 100 consumers and a mailbox of 1,000. Sizes: `A`
live actors; `M` one mailbox; `k` follow-ups of one drain; `C` consumers of a provider; `L` lanes of an actor; `d`
depth of the leaf; `W` alarms in the world; `D` alarms due together; `p` parts of a turn; `n` copies of a slot; `s`
slots a turn's change touches.

**CX's first F1 row is narrower than stated.** `draft` (`tx.ts:165-171`) copies a map on its first write in a
step only when the step does not own it. A step owns every map the step before it wrote or owned (`tx.ts:142-150,

only the test tooling and one unit test call (`src/host/testing/run.ts:466`, `tx.test.ts:28`): that half belongs to
cluster 5's F5. What does recur per step in production is the mailbox array (`tx.ts:151, 378-384`), below.

## 15. Questions for the user

Each has two traces where behaviour differs. Recommendation first.

1. **Instances settle inside the turn, in rounds** [open: 2026-11-21; recommend A]
   - A: as 6.4. No follow-up turn, no pending flag; `resetOn` is read again after the walk. This departs from
     @plan.Machines.O3 ("a pending reset ... runs first as its own follow-up turn"), TP row 12 and FR PD4.
   - B: FR PD4: a membership change caused by `whenAbandoned` or `resetOn` commits `unsettled` and settles in a
     follow-up turn.
   - Trace B: `onGone` for `r1` removes `r2` from the list. The turn publishes a list without `r2` and a live copy

2. **A site reached again folds its own writes** [open: 2026-11-21; recommend A]
   - A: as 6.2. One site per key and as the changer; the same site reached again reads what its earlier runs wrote.
