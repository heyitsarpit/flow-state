## Blocking (fix in the list before step 2)

- **B1 Pay and Cells share one machine id in the app mix.** `mixOf(parts, …)`
  (code:packages/flow-state-v3/conformance/parts/generate.ts#mixOf) places every part in one runtime. It is
  called from `parts/records.ts:179`, `parts/model-mutation.ts:207` and `parts/play.test.ts:66, 77, 91`. Both
  machines are `Checkout/Pay` (`conformance/machines/pay.ts:47, 451`), and Compile I14 requires machine ids to
  be injective in an App. `handlersFor` and `referenceFor` (`conformance/fixtures/fixture.ts:145-160`) key by
  machine id, so in a mix Cells' table silently judges Pay's actor: a wrong ending. The list names the shared id
  as a settled fact, but no Q resolves it. The new red check `parts/reference.test.ts:96` requires both parts to
  carry Pay's id, and the existing green `:113-117` requires part ids to be distinct and different from Pay's,
  so no build can satisfy both. Add a requirement and red check: no App, mix or case holds two fixtures with one
  machine id. Either Cells takes its own id, or the mix leaves one of the two out, and `handlersFor` refuses a
  duplicate id.
- **B2 Q27 lets retired `cancelAll` cases be relabelled.** LANE-03, 04, 05 and 10 are frozen
  (`parts/frozen.ts:71-74`). They send `All` and expect I21's order ("the queue in mint order, then the head",
  `write-lanes/lane-policies.scenarios.ts:143-147`; "the queued commit ends first", `:167`). WriteLanes R15
  says "Nothing builds or tests it". Removing their R15 citations, which is all Q27's check asks for, would
  leave four cases testing a retired rule under made-up cites. The guard also misses citations built at runtime
  by `wl(21)`: `dsl/lifecycle-rules.ts:199, 310`, `lifecycle-members.traces.ts:164`,
  `lifecycle-ends.traces.ts:234` and `lifecycle-obligations.traces.ts:224`, plus the CancelAll column at
  `lifecycle-rules.ts:320-346`. It scans no `.tsv` file. Split Q27:
  - **Q27a:** the text contradictions (Q13, Q14, the I8 message) and the R10/R4 re-check (M2).
  - **Q27b:** retiring `cancelAll` from the suite: the four frozen cases, the CancelAll column, the I21 branch
    of `lane-queue.ts`, and mutants `lane-queue.mutants.ts:151, 159, 189`. This deletes frozen cases and their
    catches, which conflicts with Q12 (V1, no lost catch). So it is a **scope stop** for the user's read, not
    T52 build work (see Scope).
- **B3 Q24 is stale.** Fable widened Q24 to "any owed row of the head's Attempt", and the lead accepted
  ("changed" in the Fable table). But Q24's text, the red test (`dsl/lifecycle.test.ts:186`) and the pending
  trace (`dsl/lifecycle-actor-lives.traces.ts:21-35`) still say "Kept row". Restate Q24 and add a trace for a
  non-Kept owed row (a restore owed twice is a doubled ending).
- **B4 Nothing holds the golden's content fixed (Q6).** Acceptance 1 requires one frozen golden, and the Task's
  false pass relies on it. Q6 checks only who imports the golden (`parts/golden.test.ts:247-260`). A golden
  rebuilt as `partFixture(pay)` passes every check, and so does a hand edit that copies a compiler bug.
  `parts/frozen.test.ts` checks ids and the count only. Add a pin: the golden equals the hand rows at 73227314
  (a hash, or a deep compare with a copy that changes only through a logged ruling), and the golden imports no
  `src/` and no `parts/reference.ts`.

## What the builder's checks missed, and why

change does to code that already holds the old shape: the mix over all parts, the frozen cases behind a
citation, and the golden's content. The list's Fable read and adversary sidecar looked at expected values and
weak gates, and no angle traced each new part through every existing reader of `parts`.
