# UI host and test tooling: one publication, one page death, one verdict (2026-11-21)

**Bottom line:** the host publishes once per slice that leaves no mail owed, compares each touched actor's new
snapshot against the last published one before it writes, and delivers emits after that write; a slice that ends
with mail owed publishes nothing, so a reader never sees half a chain. A tab's death is one occasion with one
fate word for every batch it left unanswered (`abort`, the Safari measurement, or `land`), and a Story addresses
tabs by name. The verdict is one pure function of the finished run, and no route returns an unjudged run, because
`Story.app` takes the project config that names the rules. The edge, the sweep and the generator lose their flag
lifecycles: the edge gets a tagged phase with a total table, the sweep a run phase, and the generator's private
timers become world words. Two of the user's answers need a change, both in section 14: what "a publication" is
(Q14's premise) and where the run rules reach `run()` (Q10's placement).

Everything here is **proposed**. Cluster 5b of @proposal.algorithm-round, the last of six; this was the lead's only
run. It designs past @proposal.spec-ui-host (UH) and @proposal.spec-test-tooling (TT); each departure is a question
in section 14. AS, AT, AR, AO and AY are @proposal.algo-schedules, @proposal.algo-turn, @proposal.algo-records,
@proposal.algo-operations and @proposal.algo-types; AV is @review.algorithm-review; R2 is
@review.spec-cohesion-r2; CS is @review.case-studies; CX is @review.complexity-sweep. Paths are under
`packages/flow-state-v3/` unless rooted. The Safari facts are `prototypes/safari/RESULTS.md` (cited, allowed).

## 1. Walkthrough: a checkout stepper, two quick clicks, a closed tab, a second tab

The shop's `CheckoutFlow` (`fixtures/shop/machines/checkout-flow.ts`, `persist: true`) is a stepper: ADDRESS,
SHIPPING.METHOD, SHIPPING.SLOT, PAY, with `Back`. The page binds it through UH's hooks (not built yet).

```tsx
// existing: CheckoutFlow, actorRef        NEW (UH, T111): FlowProvider, useActorByRef, useView
// user-defined: Stepper, setup, FlowRef
function Stepper() {
  const flow = useActorByRef(FlowRef, {})                       // a stable handle; render sends nothing
  const step = useView(flow, (s) => s.state)                    // useSyncExternalStore over the memo (6.1)
  return <button onClick={() => flow.send(CheckoutFlow.E.Back())}>{step}</button>
}
```

**Two quick clicks.** The user is on PAY and clicks Back twice, about 40 ms apart, so in two browser tasks.

1. Click 1 calls `send(Back)`. The driver is idle, so `run()` drains at once: one step, one `Turn`, the flow's
   incarnation changes and the step reports `touched = {flow}` (6.1). The step's `Persist` command marks the
   record; the edge goes `Quiet -> Marked{at: now + 5 s}` (6.4).
2. The inbox is empty and no mail is owed, so the slice publishes: the flow's new snapshot is built and compared
   with the memo's (`PAY` against `SHIPPING.SLOT`), it differs, the version goes from 7 to 8, the memo is written,
   and only then is the flow's one listener told. The cart's listeners are not told: the cart was not touched.
3. React re-reads `getSnapshot` (the memo, the same object until the next publication) and renders SLOT.
4. Click 2 is a new task: one more slice, version 9, one notify, a render of METHOD. Two clicks, two publications,
   two notifies; neither shows anything but a finished turn. The edge stays `Marked` at the first click's time.

Had a click fanned out to 150 mail items (a cart change heard by 150 consumers), the drain would yield after 100
(`drainYield`, `core/defaults.ts:39`) and serve the rest in a later task (`host/driver.ts:374-379`). Today's text
(UH S1, "a drained slice") would publish after 100 and again after 150: two renders, the first showing 100
consumers updated and 50 stale. Under 6.1 the first slice owes mail and publishes nothing; one publication shows
all 150 (Q1).

**Closing the tab while the write is held.** Two seconds later the user closes the tab. `pagehide` fires; the edge's
hidden row issues the batch at once (`Marked -> Out`); the IndexedDB transaction starts; the page dies. Chrome
lands it; Safari, entering the bfcache or closing, never answers it and lands nothing (RESULTS item 2: 0 of 12 and 0
of 6). The edge cannot know which: the batch's fate is unknown, and the app must be right under both.

**Reopening in a second tab.** The user opens the shop in a new tab. Its Runtime asks the lock (T27, UH 3.6); the
first page is gone, so it is `Owner` and reads the store. If the batch landed it restores METHOD; if not, the last
batch that landed, PAY. Both are endings a user can accept, because the stepper never sent anything on Back. Had
the first tab still been open, the second would boot `Second`, read nothing and save nothing until it reloads
(PD3, R2 Q14).

**The Story that tests it** (steps marked as in AGENTS.md; `closeTab` and `openTab` are new):

```ts
// existing: storeStory, ensure, send, advance, checkpoint, world, Fake.storage   NEW: closeTab, openTab, tab
// user-defined: backTwiceThenClose, mainFlow, mainShopper, mainCart
export const backTwiceThenClose = storeStory("shop/back-twice-close")
  .ensure(mainShopper).ensure(mainCart).ensure(mainFlow)
  // ... Begin, address, method, slot as in checkoutSteps ...
  .advance("5 seconds")                                 // the PAY batch lands
  .checkpoint("pay")
  .send(mainFlow, CheckoutFlow.E.Back())
  .send(mainFlow, CheckoutFlow.E.Back())
  .closeTab("main")                                     // NEW: pagehide flush, then death; inflight: "abort"
  .openTab("second", (t) => t.ensure(mainFlow).checkpoint("reopened"))   // NEW: a fresh page, same store
```

- `closeTab` runs the hide listeners, then kills the page; every batch the page left unanswered takes the fate
  word, here the default `abort` (Safari). The reload sweep runs the same Story with `inflight: "land"` (Chrome),
  so both endings are judged by every rule (6.5).
- The verdict runs inside `run()`: the flow's turns rule, I1/I2's round trip (AR), the publication drift rule and
  `CleanupLeft` all judge the finished run; a breach rejects `StoryFailed` with the step and evidence (6.6).
- `run.checkpoints.reopened.read(mainFlow).state` is `"PAY"` under abort and `"SHIPPING.METHOD"` under land.

## 6. Rules: the tables

### 6.1 Publication: one table over the driver's slice

A **slice** is one `run()` of the driver: it drains the inbox, including every input queued while it runs (a call
that settles synchronously, a listener's send). `Serve`, timers, answers and clicks arrive in later tasks and start
new slices. The pending record S3 accumulates every step's `touched` and `Turn`s; `lifeChanged` sets `all`.

| Slice end                                          | Publication life | Result                                                                                           |
| -------------------------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------ |
| mail owed (`owesServe`), life Open                 | Open             | nothing published; S3 kept; `Serve` scheduled once (one named task)                              |
| no mail owed, S3 empty                             | Open             | nothing                                                                                          |
| no mail owed, S3 not empty                         | Open             | `publish`: compare, write, notify changed actors' listeners, then `emits.deliver`; S3 emptied    |
| world life `Disposed` (the disposing slice ends)   | Open             | `final`: every memo entry compared (`all`), notify, deliver, then `Final`; listeners cleared     |
| a step, the admit hook or `publish` threw (`stop`) | Open             | `final` over the **memo**: each published snapshot with `lifecycle` set to stopped; then `Final` |
| any                                                | Final            | nothing; the inbox is cleared, later inputs are dropped by the life table, no `Serve` is armed   |

- A snapshot carries `lifecycle`, derived from `world.life` (`snapshot.ts:182`), so a life change changes every
  actor's snapshot and `final` always tells every reader once (H4).
- At stop the last committed world may owe mail, so it is never shown: readers get the last publication marked
  stopped (H1). Mail owed at disposal is cleared by the core (`core/disposal.ts:64`), so the disposing world is
  quiescent. Before its close, a disposing Runtime's last save is the core's `disposal.write`, a ticketed write
  (6.4's accept Now), so disposal drops no mark; after a stop, an edge issue reaches `input(Capture)`, which the life
  table drops, until the close interrupts the edge's tasks.
- `publish` runs its compare inside `Result.try`; a throw there (a defect in a snapshot) is `stop`, and the memo is
  unchanged because the write comes after the compare. `stop` does nothing when life is already `Final`.

`publish(q, p)`, in this order and nothing between:

1. For each actor in `p.touched` (every memo key when `p.all`): `next = reuse(memo[a], snapshotIn(q.world, a))`.
   `reuse` returns the old object when every field is equal (state and memory by reference, derived fields
   structurally) and otherwise `next` with each equal field's old reference.
2. `changed` = the actors whose `next !== memo[a]`; an actor whose `snapshotIn` is `none` is removed from the memo
   and counts as changed.
3. If `changed` is not empty: `version + 1`, and every `memo[a] = next`. This is the only write of S1 and S2.
4. Each listener of each changed actor, once, each in its own `Result.try`; a throw is one host report. The
   listener set is copied before the loop, so a listener that unsubscribes and subscribes again is not re-called.
5. `emits.deliver(version, p.turns)`: in turn order, after every snapshot listener. A turn's emit is delivered
   even when no snapshot changed (UH R-E1); its version is then the current one.
6. A listener's send is queued (the driver is still running) and served by the next slice of the same task.

The compare reads only the memo and the new snapshot, so it happens before the write by construction (UH-1).
The release alarm (AO 6.4) and `stepEnds` (AO 7) need nothing here: the alarm is a core alarm whose firing step
records `Published` for the holders (touched), and `stepEnds` is the last row of the core's `step`, not a host call.

### 6.2 Occasions that do not compare: one rule

**Every comparison is against the last published memo, never against the previous slice or step.** An occasion
that does not publish changes nothing any reader sees, and keeps its pending record; the next publishing occasion
compares everything since. The members:

| Occasion                                         | Skips                                                                                 | Compared by                                                             |
| ------------------------------------------------ | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| a slice ending with mail owed                    | the whole publication                                                                 | the slice that empties the mail                                         |
| a hidden page                                    | nothing (it still publishes)                                                          | -                                                                       |
| a boot, restore or wake (AT `Begin`)             | nothing: `Begin` touches its actor                                                    | the boot slice's publication                                            |
| a tab's death (Story) or a page freeze (browser) | everything after the last publication                                                 | the next open's boot: a new Runtime, an empty memo, the store's records |
| stop                                             | owed mail                                                                             | `final` compares every memo entry once                                  |
| the judge                                        | never skips: it compares per `Turn`, against the actor's last `Published` incarnation | -                                                                       |

### 6.3 Emits

`host/emits.ts` owns the listener sets (M4). The driver calls `deliver` from `publish`'s step 5, so once per
publishing slice, not once per step (departs from AT 6.10, Q3). A turn in a slice that owes mail waits in S3 with
its publication. React's `useOnEmit` keeps UH 3.5's queue in the binding: the queue is its own external store
whose value is its own sequence number, so a queued emit re-renders its listener even when no snapshot changed and
even when React skipped a publication's version; delivery is in the passive effect of the commit that read that
sequence. `deliver`'s `version` serves ordering and inspection only. No version is stored on an emit. Two turns in
one publication deliver in turn order, both after the memo holds the later one (H3 says "at or after").

### 6.4 The edge: one phase, one table

Each accept first adds to `pending`: a `Later` accept sets `marked` and `due = min(due, now + C)`; a `Now` accept
adds its ticket. Then the phase moves. `issue` takes all of `pending` into one batch, `carried = { tickets, marks }`
(`marks` are the keys the capture wrote, `again` included), empties `pending`, cancels `wake` and goes
`Out{now, carried}`. One keyed task `wake` holds the only timer, armed on entering `Marked{at}` or
`Backoff{until}` and replaced by the next arm (Effect's keyed fork), so a stale timer cannot fire. `hidden` is
the host's `hidden()`, read when a row asks, not edge state.

| Occasion \ phase      | Quiet                      | Marked{at}          | Out{carried}                                                                                                           | Backoff{until}                | Closed                |
| --------------------- | -------------------------- | ------------------- | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------- | --------------------- |
| accept Later          | Marked{due}; hidden: issue | Marked{min(at,due)} | Out (waits in pending)                                                                                                 | Backoff                       | ignored               |
| accept Now (ticket)   | issue                      | issue               | Out (waits in pending)                                                                                                 | issue                         | ticket answered false |
| `wake` fires          | -                          | issue               | -                                                                                                                      | issue                         | -                     |
| hidden                | Quiet                      | issue               | Out; the answer's row issues at once                                                                                   | issue                         | -                     |
| shown                 | -                          | -                   | -                                                                                                                      | -                             | -                     |
| landed (or no writes) | -                          | -                   | `carried.tickets` answered true; pending empty: Quiet; a pending ticket, hidden or due passed: issue; else Marked{due} | -                             | ignored               |
| refused               | -                          | -                   | `carried.tickets` answered false; `pending.again += carried.marks`; a pending ticket: issue; else Backoff{now+C}       | -                             | ignored               |
| close (services end)  | Closed                     | Closed              | Closed; carried and pending tickets answered false; its answer ignored                                                 | Closed; pending tickets false | -                     |

- "-" is unreachable or no change: `landed` and `refused` come only from the batch out, so they reach only `Out`
  and, after a close, `Closed` (ignored). C is the capture interval (`defaults.ts:38`).
- A `Second` Runtime (T27's `Ownership`) starts its edge `Closed`: the core records no `Persist` for it (UH R-L3),
  and a ticket that reaches it anyway is answered false. An `Owner` starts `Quiet`.
- A ticket is answered only by the batch that carried it, never by an earlier batch's answer.
- A refusal while the page is hidden still waits in `Backoff`: a refusing store is not retried at once, hidden or
  not. `shown` changes no edge state, since `hidden` is the host's.
- `Interrupted` (`edge.ts:200`) happens only at the Runtime's close, which is the `close` row: no phase stays out.
- `settled()` is `Quiet` with `pending` empty. A batch out past `storageSilent` shows as a derived inspection row,
  not a state (no new limit).
- Departure from today: a `Later` mark during `Backoff` waits for the retry instead of cancelling it
  (`edge.ts:75-76`); a ticket still issues at once, since a turn waits on it.

### 6.5 Tabs, page death and the fate of unanswered writes

The Story's world (store, fake servers, clock, locks) is one value; each tab is a page with its own Runtime over
it. Every actor step names its tab (default `"main"`); `openTab(name, build)` returns the builder for that tab, as
Playwright's `context.newPage()` does.

| Occasion \ tab life         | Shown                                             | Hidden                        | Gone                     | (no such tab) |
| --------------------------- | ------------------------------------------------- | ----------------------------- | ------------------------ | ------------- |
| `hide`                      | Hidden; hide listeners run                        | script fault `AlreadyHidden`  | script fault `TabClosed` | script fault  |
| `show`                      | script fault                                      | Shown                         | script fault `TabClosed` | script fault  |
| `closeTab(t, { inflight })` | Dying; hide listeners run; then death             | Dying (no second hide); death | script fault             | script fault  |
| `reload(t, { inflight })`   | `closeTab` then the same name's next open, Shown  | same                          | script fault             | script fault  |
| `openTab(t)`                | script fault `TabOpen`                            | script fault                  | the next open, Shown     | open 1, Shown |
| `advance(d)`                | the one clock moves; every live tab's timers fire | same                          | its clock never moves    | -             |

**Death**, the one point of handling for family C: while Dying, a batch that arrives at the store is held for the
death; after the hide listeners the tab's clock settles at the current instant (no time passes), so every batch
the flush issued has arrived; then every batch of that open that is `Held` (by a word or by Dying) takes the fate
word:

| Fate              | Records                    | Answer to the dead page  | Matches                                   |
| ----------------- | -------------------------- | ------------------------ | ----------------------------------------- |
| `abort` (default) | unchanged                  | none (`Aborted`)         | Safari: a `pagehide` batch never lands    |
| `land`            | the batch applied in order | none (`Landed`, unheard) | Chrome: it lands; the page never hears it |

Then the open's calls and writes become `Unheard`, its listeners are cleared, its lock is released, and its Owners
are ended; a task still alive once its Owner's end has finished goes to `left` (an interrupted timer does not).
The reload sweep runs every Story at every position in both fates; today's
`heldWrites` is this word renamed, and today's crash semantics (no hide listener) is gone: a reload runs `pagehide`
first, as a browser does. A crash with no `pagehide` is `closeTab(t, { inflight, hide: false })`.

**Locks** (T27, UH 3.6): a fake `Locks` in the world. `openTab` while another live open holds the app's lock boots
`Second`: no store call (UH R-L3); the death of the holder frees it; a `Second` stays `Second` until its own reload
(PD3). The browser's bfcache return is a host rule (`pageshow` with `persisted` reloads, UH R-L5), proved in the
browser tier, so the Story has no `freeze` word.

### 6.6 The verdict

```
verdictOf(run, index, rules, sw):
  judged  = rules minus sw.off                       -- an off rule's check is never called, here or in the judge
  broken  = RuleBroken records of run.evidence, rule not in sw.off, as Breach   -- the judge got sw.off too (6.7)
  threw   = those with threw: true, as Breach of rule "RuleThrew"                -- a crash is never the expected break
  found   = judged.flatMap(r => r.breaches(run, index)) ++ broken.filter(not threw) ++ threw
  checked = found.filter(b => b.rule not in sw.expectBroken).sortBy(step, then rule)
  broke   = set of rules in found
  return {
    breaches:     checked,
    neverBroke:   run.end is Finished and horizon is Quiet ? sw.expectBroken.filter(r => r not in broke) : [],
    unfinished:   run.end is Limit(reason) ? some(reason) : none,
    inconclusive: run.horizon is Quiet ? none : some(run.horizon),
  }
```

| Rule source       | Where named                                                                         | Judged by                                       |
| ----------------- | ----------------------------------------------------------------------------------- | ----------------------------------------------- |
| tooling rules     | `testing/verdict.ts` (`UnusedWord`, `CleanupLeft`, `PublicationDrift`, `RuleThrew`) | `verdictOf`, over the run                       |
| project run rules | `defineConfig({ rules })` (Flow's: `tests/rules/rules.ts`)                          | `verdictOf`, over the run and `RunIndex`        |
| machine rules     | the body (`Compiled.rules`, AY)                                                     | the Runtime's judge, live; read as `RuleBroken` |

| Switch \ rule's breaches | none                                         | at least one                                     |
| ------------------------ | -------------------------------------------- | ------------------------------------------------ |
| checked (default)        | passes                                       | fails; every breach listed, the earliest primary |
| `expectBroken`           | fails `neverBroke`, on a finished, quiet run | passes; later breaches are not failures          |
| `off`                    | not judged                                   | not judged (its check never runs)                |
| in both lists            | refused when the Story is built              | -                                                |

- A written Story's run has `horizon: Quiet` by definition; only generated runs have another horizon.
- `run()` resolves only on `passed`; otherwise it rejects `StoryFailed { verdict }`. A script fault (a release with
  nothing held, a step on a gone tab) rejects `StoryScriptFault` before any verdict: the Story is wrong, not the app.
- `CleanupLeft` reads `left`, built in `finish`, which disposes every live tab's Runtime and then closes it: calls
  still waiting whose caller never aborted, batches and loads not answered, listeners attached, stores open, and
  each Owner's tasks still alive after that Owner's end finished (`owners.ts` holds a `FiberMap` per Owner, line
  183). Reading the Owners replaces counting `TestClock` sleepers (TT-4): every sleeper is a task.
- `PublicationDrift` (new, the guard for 6.1's `touched`): at every publishing slice, for every memo key not in
  `touched`, `reuse(memo, snapshotIn(world))` returns the memo object. A tx writer that forgets to mark `touched`
  fails it. The test run records the check's result as evidence, so it stays a function of the finished run.
- The handed run rules join Flow's list: snapshot issues equal `issuesOf` of inspection's state (AO R2), every saved
  record round-trips (AR I1, I2), and the turns rules read `Turn` (SC-2).

### 6.7 The judge (machine rules, SC 3.4, AY Q5)

One function, `host/judge.ts`, run by the driver between a step and its sink, over the step's evidence:

| Record in the batch          | Invariant rules placed at the actor's state | Turns rules on the turn's edge                                                    |
| ---------------------------- | ------------------------------------------- | --------------------------------------------------------------------------------- |
| `Published` with `why` Begin | checked with `project(incarnation)`         | none; `last[actor] = incarnation`                                                 |
| `Turn` then its `Published`  | checked                                     | checked with `{ event, before: project(last), after }`; then `last = incarnation` |
| `Published` with `why` Other | checked                                     | none; `last = incarnation`                                                        |
| `Finished`                   | none                                        | none; `last` entry removed                                                        |

A `check` that returns false is `RuleBroken { rule, actor, step }`; one that throws is the same record with
`threw: true` (a throw changes only its own check). The setup option is `rules: "judge" | "off"` (AY Q5);
Stories and the CLI always judge, and a Story's run passes its switch's `off` list to the judge, so those checks
are never called. `last` belongs to one Runtime: a reload starts empty, and the first record after it is a `Begin`.

### 6.10 The sweep and the generator

**Sweep** (`sweep.ts:176-265`): the five flags of one cell become one phase.

| Occasion \ phase   | Replay{prefix}             | Given{stood}                                 | AwaitRefusal{before}                                  | Fired          | Quiet{pending} |
| ------------------ | -------------------------- | -------------------------------------------- | ----------------------------------------------------- | -------------- | -------------- |
| prefix done        | Given (fault steps queued) | -                                            | -                                                     | -              | -              |
| fault steps empty  | -                          | Quiet; outcome NoWrite                       | -                                                     | -              | -              |
| not stood          | -                          | Quiet; outcome NotReplayed                   | -                                                     | -              | -              |
| fault given        | -                          | Fired, or AwaitRefusal for a storage refusal | -                                                     | -              | -              |
| refusal counted    | -                          | -                                            | Fired                                                 | -              | -              |
| nudge (held write) | -                          | -                                            | Fired if a write is held; the nudge is kept otherwise | -              | -              |
| quiet done         | -                          | -                                            | Quiet; outcome NotFired                               | Quiet; Reached | -              |
| script fails       | Quiet; outcome NotReplayed | same                                         | same                                                  | same           | -              |

The outcome is derived from the final phase, never from flag pairs. `PHASES` is derived from the lane phase type's
tags, so a new phase is swept. The prefix runs once per phase and each of the seven faults forks from its saved end
(`run.ts:618` `save`), not seven replays.

**Generator** (`generate.ts`): `timers`, `landOnReload`, `offline`, `offlineLeft`, `online`, `armed`, `drawOf`
and `rest` go. Late, reordered and offline become draws of TT 3.2's world words (`late(d)`, `never()`, `duplicate()`,
`network.offline` with its `advance`), whose timing the fake world runs on the tab's clock. What stays is S13:

```ts
type Wait = { readonly until: number; readonly then: "Think" | "Gap" }   // one waiting reason at a time
type Quieting = Data.TaggedEnum<{
  Draining: {}; Counting: { readonly rounds: 0 | 1 | 2 }; Done: { readonly why: "Quiet" | "Limit" }
}>
```

A failing generated run's printed Story then replays by its text alone (TT R10), since nothing it did lives in the
generator. `QUIET_LIMIT` stays as today's measured bound until the bench says otherwise.

## 7. Algorithm

```
-- host/driver.ts
input(i): inbox.push(i); if not running: run()
run():
  running = true
  try:
    loop:
      while (i = inbox.shift()):                           -- a ring index, not Array.shift (section 10)
        out = Result.try(step(world, i, env))              -- failure: stop(defect); return
        ev  = out.evidence ++ judge(out.evidence, last, off) ++ slowWork
        admit(ev)                                          -- a throw: stop(fault); rethrow after the loop
        world = out.world
        pending.touched ∪= out.touched; pending.turns ++= turnsOf(ev); pending.all ||= out.lifeChanged
        sink(ev)                                           -- each sink in its own Result.try
        perform(out.commands)                              -- releases first, then starts (AT row 16)
      if life is Final: break
      if isDisposed(world.life): final(world, pending); break
      if owesServe(world): work.fork("serve", yieldNow, () => input(Serve)); break
      if pending not empty: publish(Quiescent(world, env.now), pending); pending = empty
      if inbox empty: break                                -- a listener may have sent: serve it now
  finally:
    running = false

stop(defect):
  if life is Final: return
  world = stopped(world); inbox.clear()
  finalFromMemo(lifecycle: stopped); Deferred.done(disposed, die(defect))   -- the owed world is never shown

-- host/publication.ts
publish(q, p):
  keys = p.all ? memo.keys() : p.touched
  changed = Result.try(() => keys.flatMap(a => {          -- compare; a throw: stop(defect) and return at once
    next = Option.map(snapshotIn(q.world, a), s => reuse(memo.get(a), s))
    return same(next, memo.get(a)) ? [] : [[a, next]] }))  -- (inside final too: final then does nothing more)
  if changed nonempty:
    version += 1
    for [a, next] of changed: next is some ? memo.set(a, next) : memo.delete(a)
  for [a] of changed: for tell of [...listeners.get(a)]: Result.try(tell) else report
  emits.deliver(version, p.turns)
  return { version, at: q.at }

final(world, p): publish(Quiescent(world, now), { ...p, all: true }); life = Final; listeners.clear(); inbox.clear()
finalFromMemo(lifecycle): changed = every memo entry with lifecycle replaced; version += 1; write; notify;
                          life = Final; listeners.clear()      -- no emits: the owed turns were never published

-- host/testing/run.ts, death of a tab
close(tab, inflight, hide = true):
  if hide: tab.life = Dying; for l of tab.listeners: l()       -- the edge issues
  tab.clock.settleNow()                                        -- every issued batch arrives, held by Dying
  for b of store.batches(open of tab, status Held): inflight == "land" ? store.land(b) : store.abort(b)
  fakes.unheard(open); tab.listeners.clear(); locks.release(open)
  work.end(open's Owners); left.add(their leftovers); tab.life = Gone
```
