## Blocking

### B1. An owed end owes a store write, which the Spec does not say

`unheard` refuses every owed end in a step with no `Wrote` (`dsl/expect.ts:365-368`). Actors R8 says a persisted
actor's record is *encoded* in the end's step, and I12 says the record *equals* its last committed state.
WriteAhead R10 captures only dirty records. With `captureMs: 0` (`dsl/life.ts:25`) the record is already landed
after each turn, so at ACT-01's end nothing is dirty and a correct runtime may write nothing. Both runtimes write
today, so nothing is red yet; the check holds production to more than the Spec. It also counts writes for the
whole step, not per ended actor, so one actor's write discharges another's.

The orchestrator's 21:50 note reads R8 as "record written at the grace". That is a Spec revision, so it is the
user's read. **The user's call:** (a) amend Actors R8 (and I12's wording) to say the end writes the record, logged
in `spec-log.md`, and key the check per actor; or (b) drop the write check, so `life.never-ends` is caught only by
the report and turns liar-green again, which reopens the liar-cap question. Recommendation: (a), because
an end that writes is what makes it observable, and both runtimes already do it.

### B2. The data-flow boundary test cannot see a leak into obligations

`dsl/dataflow.test.ts:87` compares `modelView = { live, held }` only. The `Model` (`dsl/lifecycle-model.ts:260-282`)
keeps the obligations in `attempts`, `endings`, `obligations`, `ended`, `releasing`, `saved` and `pending`. An
ending's lied channel and reason (`dataflow.test.ts:56-61`) would land in `endings` and `attempts`, which the test
never compares, so a report-to-obligation path there passes. The second test (`:183-204`) asserts that `lied`
changes a mint key: it never plants a module that reads the key, so it cannot show the main assertion fails. By
reading alone, the test fails only for a leak into the anchor, the predicted turns, `live` or `held`.

**Fix:** compare the whole `Model`, leaving out by name only the fields R19's stated limits allow (the
`acknowledged` set, a runtime answer); plant one expect-side read of `Ended.channel` and see the test fail.
Acceptance item 5 is not met by the data-flow half until then.

## Should fix

- **Two stated limits' mutants never reach what they admit.** `limit.mint-key-lies` (`limits.ts:107-127`, an
  Unanchored actor's keys) and `limit.from-lies` (`:171-192`, a turn after an unknown leaf) run on PAY-01, which
  has no kill, no reload and no Unanchored actor. Their `Caught` outcome shows the ordinary check works, not how
  far the limit reaches. Run each on a case that enters the path (a kill with turns no capture holds, such as
  DISP-06 or a crash point), and expect `Survives` there.
- **A keyed retry may now re-own any call with no folded key** (`turn/credits.ts:153-157`, 8eba365d). This widens
  the Unanchored keys limit to retries, but the `limits.ts` row's `admits` does not say so and no mutant covers it.
  Add it to that row's text and give it a mutant (a retry that re-owns another key's call after a kill).
- **`usedWrite` rests on `captureMs: 0`.** Its premise (`dsl/expect.ts:301-303`: in a clock-only step only an end
  or the disposal writes) is false under WriteAhead R10, which lets a dirty record's capture wait up to 5 s, so a
  correct runtime booted with the production default (5000) is red with I10. Sound for the suite's boot today; say
  the premise in the doc and tie the check to the boot's `captureMs` fact.
- **The early-end refusal has no runtime mutant.** `endHeard`'s `upper < GRACE_MS` branch (`dsl/compare.ts:173-178`)
  has unit tests (`dsl/compare.test.ts:159-170`) but no mutant; `life.ends-while-used` takes the `holds` branch.
  A `graceMs: 50` edit of `world.ts` would show whether the liar gate sees it (it is likely green: a free actor's
  early end writes while not every actor is used).
- **The schedules oracle's arm time and memory are the step's, not the turn's** (`turn/schedules.ts:152`,
  `:290`). `due` is the step's start clock plus the delay, and the memory is the anchor at the step's end. A
  computed-delay schedule armed by a timer firing inside an `Advanced` step would get too early a due and be red
  by `overdue`; a later turn in the same step that changes memory would change the delay. Latent: Pay arms
  `retry` only on an answer step (`fixtures/pay.ts:339, 362`), which moves no clock. Note it in the oracle's
  Gotchas, or take the arm time from the firing's due when one exists.
